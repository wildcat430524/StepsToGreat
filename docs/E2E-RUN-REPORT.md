# 端到端跑测报告（E2E Run Report）

> **跑测方式**：AI 扮演导师，按 `AGENTS.md` + `协议/` 完整走一遍「首次使用 → 摸底 → 排路线 → 发第一课 → 三轮教学 → 整课闭环 → 落档」。
> **目的**：验证协议在真实使用中是否可执行、校验器是否判得对。**不是演示，是找问题。**
> **日期**：2026-09-22
> **测试环境**：`E:\s2g-e2e`（复制项目文件夹，模拟真实用户下载解压后使用），跑测后已删除。

## 3. 发现的问题（按严重度）

### 🔴 P0-1 · 模板相对链接深度错误（**会直接害到用户**）

**现象**：按 `模板/` 生成的学习文件，链接**全部是坏的**。

**根因**：模板里的相对链接是**按 `模板/` 目录自身**写的（如 `../协议/01_摸底剧本.md`），
但模板的**目标安装位置更深**：

| 模板 | 目标位置 | 深度 | 需要的相对前缀 |
|---|---|---|---|
| `摸底测试模板.md` | `我的学习/学科/<学科>/00-摸底测试.md` | 3 层 | `../../../` |
| `课程路线模板.md` | `我的学习/学科/<学科>/00-课程路线.md` | 3 层 | `../../../` |
| `学生回答模板.md` | `我的学习/学科/<学科>/NN-<课名>/01_学生回答.md` | 4 层 | `../../../../` |
| `学习档案模板.md` | `我的学习/00-学习档案.md` | 2 层 | `../`（**本来就对**） |

**后果**：学生/导师照模板创建文件 → 得到 5 条坏链接（跑测实测数字）。
**这个 bug 靠读代码永远发现不了** —— 链接在 `模板/` 目录里全是有效的。

**已修**：
- 3 个模板的链接改成按目标位置（`../../../` / `../../../../`）
- `check.mjs` 新增 `TEMPLATE_VIRTUAL_BASE`：**按「模板将被复制到哪」来解析链接**
- 验收：用修好的模板重新生成 4 个文件 → `check.mjs` 全过（修复前必报 5 条）

> **为什么会存在**：`check.mjs` 只校验「链接在当前位置是否有有效」。
> 模板是**生成源**，其链接必须按**目标位置**判定 —— 这是校验器的盲区，现已补上。

### 🟠 P1-1 · 协议空白：「课间」状态没规定 🚦 怎么写

**现象**：整课通过后，📊 已标 ✅，但下一课还没发布。
此时 🚦 里「教学文档/回答文档」该写什么？**协议没有规定。**

**后果**：跑测时我（导师）先写成 `—（#2 尚未发布）`，
校验器报 `[I3] 指向不存在的文件` —— 因为 `—（…）` 没被识别为占位。
更糟的是：**不同导师会写出不同东西**（留空 / 写 `—` / 保留旧课路径），
接手的人分不清「还没发布」和「路径忘了填」。

**已修**：`协议/03_落档事件表.md`（中英）新增「两种课间状态的写法」小节，明确：

| 情形 | 当前课次 | 教学/回答文档 |
|---|---|---|
| A. 上一课完成、下一课未发布 | `#NN+1 <课名>` | `—（#NN+1 尚未发布）` |
| B. 刚发布新课 | `#NN+1 <课名>` | `<真实路径>` |

并说明：情形 A 下 📚 索引还没有新课那行是**正常**的，校验器只给提示不判失败。

### 🟡 P2-1 · 校验器误报：备注列「路径 + 说明」被整串当路径

**现象**：📊 备注写

```
学科/英语语法/01-…/01_学生回答.md；首次 1 处概念错误（…），修正后复评通过
```

→ 校验器报 `[I6] 证据文件不存在 → 学科/…；首次 1 处概念错误…`（把整串当路径）。

**根因**：`linkTarget()` 只认 markdown 链接，裸路径时取整格内容。
但**备注列天然会混写「证据入口 + 一句结论」** —— 这是最自然的写法。

**已修**：按 `；;，,` 与空白切出第一段；并加「必须像路径（含 `/` 或以 `.md` 结尾）」的判据，
不像路径就不当路径。

---

### 🟡 P2-2 · 校验器误报：`—（说明）` 形式占位被当成路径

**现象**：🚦 写 `—（#2 尚未发布）` → 报「指向不存在的文件」。

**根因**：`PLACEHOLDER_VALUES` 只认精确等于 `—` 的值，不认「破折号 + 说明」。

**已修**：`isPlaceholder()` 增加 `/^[—–-]/` 规则 —— 破折号开头在语义上就是「不填/不适用」。

---

### 🟢 P3-1 · 出题表述不严谨（导师的错，非项目缺陷）

第三轮问题 4 我要求「改成 2 种正确英文」，但**没限定「必须是时态的两种」**，
学生用 `used to live` 作答也完全合规 —— 我出的题允许了非预期答案。
**记录在案**：教学文档出题时应写清约束边界。

### 🟢 P3-2 · 协议对「学生首次答错时」的引导粒度描述偏粗

跑测中我按「概念错误 → 只给提示不给答案」处理（协议第 5 节）。
但协议没说明：**给提示时能不能直接指出「去看教学文档第 X 节」**。
我这样做了（有效），但换一个导师可能给得更少或更多。
**建议**（未改）：协议可补一句「提示可以是定位到教学文档的具体小节」。

## 4. 校验器对抗注入验证

在**真实档案**上人为注入 4 类错误，验证检出能力：

| 注入 | 期望 | 实际 | 结果 |
|---|---|---|---|
| 1. 删掉含最终复评的回答文档 | I6 | I4 + I6 + I5（3 条） | ✅ 检出 |
| 2. `#1` 改回 `⏳ 待作答`（提前推进） | I9 | I9（+I6 联动） | ✅ 检出 |
| 3. 🚦 路径改成不存在的路径 | I3 | I3 | ✅ 检出 |
| 4. ⏳ 证据入口改成死路径 | I5 | I5 | ✅ 检出 |

**4/4 全部检出，退出码均为 1。漏报 0 条。**

> **测试脚手架的自省**：注入 1 删掉了回答文档，而我的备份只覆盖档案本身 →
> 真实跑测数据被误删。这**不是项目缺陷**，是我的测试脚本不严谨（已重建该文件）。
> 教训：**破坏性测试必须先对整个目录做快照，而不是只备份被直接编辑的文件。**

## 5. 跑测中确认「好用」的设计

以下设计在真实使用中确实起了作用，不是纸上谈兵：

| 设计 | 实际效果 |
|---|---|
| **一轮 1–3 题** | 学生第一次答错概念（问题 2）时，只损失 1 题；修正后再做第二轮，全部答对 |
| **「先重读文件再评估」硬规则** | 我确实每次都重读了（本文档可查）—— 这条规则防的是「凭印象批改」 |
| **区分小问题代改 / 大问题引导** | 问题 1（表述不清）我直接代改示范；问题 2（概念错）只给提示让学生自己推 |
| **「没改的题也要明说通过」** | 我两轮都写了「其他内容本次都已通过」—— 避免学生误以为没说就是有问题 |
| **整课通过才落档三处** | 中间轮次不动档案，跑测中确认没出现「档案与回答文档不一致」 |
| **学科包定义维度③** | 语言包把③定义为「表达规范」，且明确「地不地道是②不是③」—— 问题 4 判 ✅ 时直接引用了这条 |

## 8. 一句话总结

> **协议的流程是通的，校验器的判定是对的，但「模板 → 生成文件」这条链路上有一个会让每个用户都踩到的坏链接缺陷。**
> 这个缺陷只能靠端到端跑测发现 —— 它证明了「跑测」不是可选项，是本项目的必要环节。
