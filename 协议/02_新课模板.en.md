# 02_Lesson Template

> Purpose: when publishing a lesson, create `01_教学引导.md` as the teaching index, `第N轮_教学引导.md` for each issued round, and `01_学生回答.md` for cumulative answers and assessments.
> Chinese version: [`02_新课模板.md`](./02_新课模板.md)

---

## 1. How the teaching and answer documents relate (single source of truth)

After needs are understood, introduce every new block with a short situation/story and one question per [`05_对话导入.en.md`](./05_对话导入.en.md), then prepare its documents. Append later blocks to the owning lesson rather than creating a lesson or overall placement for each block. Preserve entry answers and hints as informal feedback; formal rounds still verify independently. Placement and routing precede formal lesson 1; the previous round/lesson must pass before introducing the next block.

```
学科/<学科>/NN-<课名>/
├── 01_教学引导.md      ← index: current status view + links to each round's guide
├── 第1轮_教学引导.md  ← complete explanation + examples + prompts for this round; create another file for the next round
└── 01_学生回答.md      ← mirrored prompts + answers and assessments appended by round + two final placeholders
```

- **The answer document = the only learning evidence.** Mastery is judged by its "Final Re-assessment".
- **No HTML copy is generated.** Generate one on demand only when interactive practice is needed, and the generated artifact is not truth (Markdown is).
- The answer document always ends with two placeholder H2s: `## Final Re-assessment`, `## Correct Answers & Analysis` — filled in by the tutor after assessment.
- **Keep every round's teaching document.** Save its full explanation, examples, and prompts when issuing it; add a link in the teaching index. Create `第2轮_教学引导.md` and so on for later rounds without overwriting or shortening issued guides. Append answers and assessments to the one answer document. Existing lessons need no mass renaming.
- **Keep numbering in the profile.** Use subject, topic, and round in teaching/answer document titles and body, without repeating formal `#NN` lesson numbers. Maintain those numbers in the profile's 🚦 handoff and 📚 lesson index. The `NN-<lesson>` directory prefix may still sort folders.

## 2. Teaching guide layout (necessary content first)

Both documents place the same two-level view after their title, per [`06_小目标进度.en.md`](./06_小目标进度.en.md): module name and module mastery bar first, then the current small goal and its concrete skills. Derive the bar from route-defined units and formal mastery evidence, never from current checklist ticks. Skills describe actual explanations, operations, or applications, not completing tasks or passing verification. Unknown module scope means scope pending, not an invented total. See the teaching and answer templates.

Organize each **round teaching document** as the problem, method and example, necessary pitfalls, and current-round practice. Integrate useful comparisons and links to prior knowledge into explanations. Do not require eight sections, five key points, or a fixed trap count. Concision must not remove key principles, boundary conditions, actionable steps, or verifiable sources.

For new lessons, `01_教学引导.md` is the clickable index and shares the current status view with the answer document. Keep only links to issued rounds and, if useful, one brief orientation sentence for the current round. Save the complete explanation and prompts in `第N轮_教学引导.md`; see [`模板/轮次教学引导模板.md`](../模板/轮次教学引导模板.md). Append links for later rounds without changing earlier ones. If an older index contains a combined guide, add navigation while preserving its original teaching content.

```markdown
# <subject> · <lesson> | Teaching Guide

<!-- s2g-goal-view:start -->
## <owning module name> · Module mastery

**<mastered units>/<total module units>** knowledge units mastered

![<module> mastery K/T](./assets/<module>-K-of-T.svg)

### Small goal | <this block's tangible result>

- [ ] <verb first: explain a specific concept or method>
- [ ] <verb first: perform a specific step or operation>
- [ ] <verb first: independently apply a specific skill>

> **Current step** | <the one immediate action>.

*Evidence: module - <formal mastery reference>; skills - <current assessment or initial observation/unverified>.*
<!-- s2g-goal-view:end -->

## Round teaching documents

- [Round 1: <current topic>](第1轮_教学引导.md)

<Optional: one sentence describing the current round, linking to its full document; do not duplicate the explanation or prompts here.>
```

> **Why lay the questions out by round**: if question 1 exposes a conceptual error, sending 5 at once makes the later ones **wrong all the way down**;
> round by round, question 2 is answered on a correct understanding. The total count is unchanged, but every question sits on the right track.

### How to schedule the Feynman round (inserted on demand)

**Not every lesson has a Feynman round.** The criteria are in §6.1 of [`00_导师协议.md`](./00_导师协议.md).

| Case | How to schedule |
|---|---|
| This lesson has an abstract / easily confused concept and the student is meeting it for the first time | Insert a Feynman round **after the concept round** (**1 question only**) |
| End of a major module (e.g. OOP finished, functional programming finished) | A Feynman round is **mandatory**, covering the whole module |
| Purely operational content (e.g. "how to import a module") | **No** Feynman round |
| The student has been strong at Feynman before and this lesson is concrete | **No** round, or close the lesson with one light line: "sum up this lesson in one sentence" |

**Question template for the Feynman round**:

```markdown
### Feynman round · Question N

**In words your mum could follow, explain: <concept name>.**

Rules:
- ❌ These words must not appear: <this lesson's term 1>, <this lesson's term 2>
- ✅ Analogies and everyday examples are welcome
- 3–5 sentences is enough

> This is not an exam. **It's normal not to explain it clearly** — failing to explain it is exactly what shows there's a hole here, ready to be filled.
```

> ⚠️ A Feynman question **counts as 1 question**, and **that round has only that 1 question** (it takes far longer than an ordinary one).

## 3. Question-writing discipline

| Item | Rule |
|---|---|
| **Questions per round** | **1–3** (default 2; use 1 when the topic is brand new or hard) |
| **Rounds per lesson** | Usually 2–3 (about 5 questions in total); adjustable to the student's goal, not fixed |
| **Feynman question** | **Counts as 1 question**, and that round has **only that 1 question**; whether to schedule it is in §2 "How to schedule the Feynman round" |
| **Prerequisite for the next round** | **This round is all ✅.** If this round has ⚠️/❌ → finish the explain → fix/re-derive → re-assess loop first |
| **Variation** | Hands-on and synthesis questions must **change the conditions** of the worked examples (new data, new constraint, new edge case) and **must not be same-shape copies** |
| **Language** | Write questions in the student's language |
| **Forbidden** | Sending more than 3 questions at once; listing a whole lesson's questions for the student to work through alone; memory-recall questions like "recite the content of section 3"; **abusing Feynman questions as ordinary questions** (see the hard floor and ceiling in §6.1) |

## 4. Answer document template (**append by round**, not listed all at once)

> ⚠️ **Key**: the answer document **starts with round 1's questions only**. Once the student has answered and the assessment has passed,
> the tutor **adds** the next round's questions if the same content block still needs practice. When the current small goal is complete, close it first; introduce and issue a new block only after the student continues or under an agreed continuous-study plan. Insert the new round before the two final placeholders, preserving earlier answers, assessments, and placeholders.
>
> The reason: if the document listed all 5 questions at once, the student would be seeing every question up front — which contradicts the "1–3 questions per round" design.

## 5. Output template for the student when publishing a new lesson

At block start show the module bar and current skills, then the situation and question. After a submission, give one specific achievement sentence first and show newly confirmed skills; disclose help rather than ticking from praise. Ordinary revisions need only the relevant skill reminder, not the whole view. Close with the acquired capability even if module progress is unchanged. Do not reissue goals/questions or repeat five key points, promises, reminders, or task sections. Use one line of document links; do not bury achievements under the next exercise.

```markdown
<One specific observation naming the student's actual action and its result, disclosing any help.>

<At skill changes or stops, the same module progress and current skills as both documents.>

<Close a completed small goal; otherwise give only the current small step, not another block.>

<clickable teaching-guide file link> · <clickable student-answer file link>
```
