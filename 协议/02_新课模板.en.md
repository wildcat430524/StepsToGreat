# 02_Lesson Template

> Purpose: every time you publish a new lesson, produce two files per this document: `01_教学引导.md` (written by the tutor) + `01_学生回答.md` (mirrors the same questions; the student answers, then the final re-assessment).
> Chinese version: [`02_新课模板.md`](./02_新课模板.md)

---

## 1. How the two files relate (single source of truth)

```
学科/<学科>/NN-<课名>/
├── 01_教学引导.md     ← tutor writes: explanation + worked examples + questions (laid out by round)
└── 01_学生回答.md     ← student writes: mirrored questions + blank answer slots + two placeholder sections at the end
```

- **The answer document = the only learning evidence.** Mastery is judged by its "Final Re-assessment".
- **No HTML copy is generated.** Generate one on demand only when interactive practice is needed, and the generated artifact is not truth (Markdown is).
- The answer document always ends with two placeholder H2s: `## Final Re-assessment`, `## Correct Answers & Analysis` — filled in by the tutor after assessment.

## 2. Teaching guide skeleton (8 sections, fixed order)

```markdown
# <subject> | NN_Teaching Guide

## 1. Why learn this?
<1–2 paragraphs, must be tied to the student's goal. Empty talk like "this is fundamental and important" is forbidden.>

## 2. Core concepts
<What this topic is, why, and how to use it. Only 1–2 concepts at a time.>

## 3. Syntax / method + examples
<A minimal runnable (or actionable) example, explained line by line / sentence by sentence.>

## 4. Old vs new
<Compare with what's already learned: how it was done before, how it's done now, where the difference lies.>

## 5. Common traps
<The 3–4 places students get wrong most, spelling out "why it's wrong" and "what happens when it's wrong".>

## 6. Links to prior knowledge
<Hook it onto the knowledge network already built.>

## 7. Key points of this lesson (5)
<5 items; when reviewing, the student only reads here.>

## 8. Questions (laid out by round)

> **Each round has only 1–3 questions.** The tutor **sends one round at a time**; the next round goes out only after the student has answered and the assessment has passed.
> Never send all the questions below at once, and never set the document up so that "everything is answered in one go".

### Round 1: conceptual understanding (1–2 questions)
### Round 2: hands-on practice (2 questions)
### Round 3: synthesis (1 question)
### Feynman round (on demand, see below)
```

> **Why lay the questions out by round**: if question 1 exposes a conceptual error, sending 5 at once makes the later ones **wrong all the way down**;
> round by round, question 2 is answered on a correct understanding. The total count is unchanged, but every question sits on the right track.

### How to schedule the Feynman round (inserted on demand)

**Not every lesson has a Feynman round.** The criteria are in §6.1 of [`00_导师协议.md`](./00_导师协议.md).

| Case | How to schedule |
|---|---|
| This lesson has an abstract / easily confused concept and the student is meeting it for the first time | Insert a Feynman round **after the concept round** (**1 question only**) |
| End of a major module (e.g. OOP finished, functional programming finished) | A Feynman round is **mandatory**, covering the whole module |
| Purely operational content (e.g. "how to import a module") | **No** Feynman round |
| The student has been strong at Feynman before and this lesson is concrete | **No** round, or close the lesson with one light line: "sum up this lesson in one sentence" |

**Question template for the Feynman round**:

```markdown
### Feynman round · Question N

**In words your mum could follow, explain: <concept name>.**

Rules:
- ❌ These words must not appear: <this lesson's term 1>, <this lesson's term 2>
- ✅ Analogies and everyday examples are welcome
- 3–5 sentences is enough

> This is not an exam. **It's normal not to explain it clearly** — failing to explain it is exactly what shows there's a hole here, ready to be filled.
```

> ⚠️ A Feynman question **counts as 1 question**, and **that round has only that 1 question** (it takes far longer than an ordinary one).

## 3. Question-writing discipline

| Item | Rule |
|---|---|
| **Questions per round** | **1–3** (default 2; use 1 when the topic is brand new or hard) |
| **Rounds per lesson** | Usually 2–3 (about 5 questions in total); adjustable to the student's goal, not fixed |
| **Feynman question** | **Counts as 1 question**, and that round has **only that 1 question**; whether to schedule it is in §2 "How to schedule the Feynman round" |
| **Prerequisite for the next round** | **This round is all ✅.** If this round has ⚠️/❌ → finish the explain → fix/re-derive → re-assess loop first |
| **Variation** | Hands-on and synthesis questions must **change the conditions** of the worked examples (new data, new constraint, new edge case) and **must not be same-shape copies** |
| **Language** | Write questions in the student's language |
| **Forbidden** | Sending more than 3 questions at once; listing a whole lesson's questions for the student to work through alone; memory-recall questions like "recite the content of section 3"; **abusing Feynman questions as ordinary questions** (see the hard floor and ceiling in §6.1) |

## 4. Answer document template (**append by round**, not listed all at once)

> ⚠️ **Key**: the answer document **starts with round 1's questions only**. Once the student has answered and the assessment has passed,
> the tutor **appends** the next round's questions (append-only; the part the student already wrote stays exactly as it is).
>
> The reason: if the document listed all 5 questions at once, the student would be seeing every question up front — which contradicts the "1–3 questions per round" design.

**Round 1 (written when the lesson is published)**:

```markdown
# <subject> | NN_Student Answer

## Topic: <this lesson's topic>

## Round 1 · Question 1: <question restated>
**Your answer:**
```
(answer here)
```

## Round 1 · Question 2: <question restated>
**Your answer:**
```
(answer here)
```
```

**Round 2 (appended after round 1 is all ✅)**:

```markdown
---

## Round 2 · Question 3: <question restated>
**Your code / your answer:**
```
(answer here)
```

## Round 2 · Question 4: <question restated>
**Your code / your answer:**
```
(answer here)
```
```

**Round 3 (appended after round 2 is all ✅)**:

```markdown
---

## Round 3 · Question 5: <question restated>
**Your code / your answer:**
```
(answer here)
```
```

**At the end (put in place from the start, filled in by the tutor after assessment)**:

```markdown
---

## Final Re-assessment
(filled in by the tutor after every round of the lesson has passed)

---

## Correct Answers & Analysis
(filled in by the tutor after every round of the lesson has passed)
```

## 5. Output template for the student when publishing a new lesson

```markdown
# #NN <previous lesson> closed ✅            ← if the previous lesson just passed
**Re-assessment**: concept, logic, form all passed.
First pass found N problems, fixed directly at your request: 1)… 2)… 3)…
The profile has been updated too.
---
**Next: #NN <new lesson>** (<one line on why it matters, tied to your goal>)
### 📁 Where the files are
- Teaching guide: <path>
- Answer document: <path>
### 📖 This lesson's key points (5)
### 📚 Further reading
- Required: <title> §<chapter number> <chapter name> (read before / check against after / self-test source)
- Optional: <title> §<chapter number> <chapter name> (when to come back to it)
- Self-test source for this lesson: <title> §<self-test chapter>
### ✅ Your task
Read the teaching guide, answer **this round's questions** (1–3), then just tell me "done".
> Review reminder (non-blocking)
```

## 6. Filing (at the moment a new lesson is published)

| To do | Where |
|---|---|
| Create `01_教学引导.md` (questions laid out by round, but **round 1 only is sent**) | `学科/<学科>/NN-<课名>/` |
| Create `01_学生回答.md` (**round 1's questions only** + the two placeholder sections at the end) | same as above |
| Append the later rounds' questions | **Append** in the answer document (append-only, never overwrite) |
| Update the current lesson and progress | `我的学习/00-学习档案.md` → 🚦 Handoff Status |
| Append the lesson mapping | same as above → 📚 Lesson index |
