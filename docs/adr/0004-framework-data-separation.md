# 0004 · 框架与学习数据分离

- **状态**：已接受
- **日期**：2026-09-21
- **决策者**：项目发起人

---

## 背景

项目开源，用户会 `git clone` 拿去用，然后**持续使用几个月甚至几年**。
期间框架会更新（协议改进、新增学科包、新增工具适配）。

三种仓库形态可选：

1. **单仓库单档案**：clone 一份就是一份学习档案
2. **单仓库多工作区**：`learners/<名字>/`
3. **框架仓库 + 个人数据隔离**：数据落在 gitignore 掉的目录里

约束：
- 用户是**非技术人**，不能要求他们处理 git 冲突
- 学习记录**不能丢**（丢了等于白学）
- 框架要能持续更新

---

## 决策

**采用方案 3。**

```
StepsToGreat/                    ← 框架（git 跟踪）
├── AGENTS.md / 协议/ / 学科包/ / 模板/ / 教程/ / _tools/ / docs/
├── 我的学习/                     ← 数据（.gitignore，除起始档案与 README）
└── 资料/                         ← 数据（.gitignore，除 README）
```

`.gitignore` 规则：

```gitignore
我的学习/**
!我的学习/00-学习档案.md
!我的学习/README.md

资料/**
!资料/README.md
```

即：**保留起始档案**（用户一打开就有东西可看），其余全部忽略。

---

## 理由

| 理由 | 说明 |
|---|---|
| **`git pull` 永不冲突** | 用户的数据不在版本控制里，框架更新不可能覆盖它 |
| **用户无感** | 用户不需要懂 git；就算他从不 pull，也能正常用 |
| **可选择性纳入版本控制** | 用户想备份自己的记录，可以自己改 `.gitignore` 或另建私有仓库 |
| **公开仓库干净** | 不会把别人的学习记录推到 GitHub 上 |

---

## 备选方案与为何否决

| 方案 | 否决理由 |
|---|---|
| 单仓库单档案 | 用户一旦 `git pull`，要么冲突要么覆盖自己的记录 —— 对非技术用户是灾难 |
| `learners/<名字>/` 多工作区 | 用户得先想一个目录名；且不解决 pull 冲突（还是要 gitignore） |
| 把数据放仓库外（如 `~/Documents`） | 用户会找不到；且「文件夹即项目」的直觉被破坏 |
| 用 git 分支隔离数据 | 非技术用户不可能理解分支 |

---

## 已知取舍

| 取舍 | 说明 |
|---|---|
| **用户的数据默认没有版本控制** | 误删无法恢复。已在 `我的学习/README.md` 里提示可自行纳入 git |
| **起始档案是个特例** | `00-学习档案.md` 被跟踪，用户改动它会产生本地修改 → 提示：用户改的是自己的记录，`git pull` 时可能冲突一次（罕见，且只此一个文件） |
| **`资料/` 不放内容进仓库** | 便于开源，但用户分享「我的学习包」时需手动打包 |

---

## 影响

- `_tools/check.mjs` 的 `SKIP_DIRS` 包含 `资料/`（用户资料不参与质检）
- 所有文档里的路径示例都用 `我的学习/` 前缀
- 教程明确写「换工具不丢记录，因为记录在 `我的学习/` 里」
- 若将来要做「导出学习包」功能，从 `我的学习/` 打包即可
