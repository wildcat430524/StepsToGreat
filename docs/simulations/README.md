# 仿真工作区（Simulation Workspace）

> 用途：用**仿真对话**测试各学科的「导师协议 + 学科包」是否好用，从问答中发现优化点。
> 产出：每个学科一份对话记录 + 该学科的优化发现，汇总到 [`00-优化汇总.md`](./00-优化汇总.md)。

---

## 一、仿真要求（每个学科必须做到）

### 1. 学生必须像真人

**禁止**学生一答就对、一学就会。必须包含这些真实行为：

| 行为 | 要求 |
|---|---|
| **错误回答** | 至少 2 处**实质错误**（不是笔误），且错误类型要符合该学科的真实高频错误 |
| **不懂就答不出** | 至少 1 处**完全答不出**或答偏（不是错，是真不会） |
| **反复提问** | 至少 2 次**追问同一个点**（「还是不懂」「为什么啊」「能不能再说一遍」），导师需要换角度讲 |
| **只报结论不报原理** | 至少 1 处学生只给答案不给理由（这是项目已知的高频问题） |
| **笔误** | 至少 1 处该学科典型的**可豁免笔误**（用于测学科包的豁免判据） |
| **答非所问** | 至少 1 处学生答偏了，导师需要拉回来 |
| **质疑或不服** | 至少 1 处学生对导师的判定表示疑问（「这个也算错？」），导师需要解释清楚 |
| **情绪** | 至少 1 处挫败感表达（「我是不是学不会」「好难」），导师需要鼓励但不降标准 |

### 2. 导师必须严格按协议

必须体现这些协议要求（**做不到就在报告里记为协议缺陷**）：

- 一轮只出 **1–3 题**，本轮全 ✅ 才发下一轮
- 学生说「完成了」后**重新读文件**再评估（对话里要体现）
- **一次性列全本轮全部题目**的评估，不挤牙膏
- 小问题**代改 + 三段式**（原答案 → 错在哪为什么 → 改成了什么）
- 大问题走 **Socratic**（只给提示，让学生自己推）
- 没改的题**明确说「你答得对」**
- 区分**结构性错误**与**可豁免笔误**（按该学科包判据）
- 整课通过才写「最终复评结果」+ 落档三处

### 3. 记录必须真实完整

对话要写成**逐轮实录**，含学生原话（可以口语、短句、有错别字）、导师原话。
**不要写成「导师完美、学生配合」的宣传稿** —— 要写真实摩擦。

## 二、产出格式（每个学科一份）

文件放在 `docs/simulations/`，命名 `<NN>-<学科>-<领域>.md`，结构：

```markdown

|---|---|
| 学科 / 领域 | |

| 学生画像 | 基础、目标、习惯、性格 |
| 仿真长度 | 摸底 N 轮 + 正课 M 轮 |
| 日期 | 2026-09-22 |

## 1. 摸底（如有）

（逐轮实录）

## 2. 正课对话

（逐轮实录，标注「第 N 轮」「学生」「导师」）

## 3. 三维评估汇总

| 轮次 | 题号 | ① | ② | ③ | 结论 |
|---|---|---|---|---|---|

## 4. 本学科发现的优化点

### 4.1 学科包缺陷（该学科包没覆盖到的情况）
```

## 三、纪律

1. **不许美化**：发现协议不好用就直说，附上「哪一轮、导师卡在哪」。
2. **不许编造学科事实**：题目与判据必须真实正确（你是该领域的可靠来源）。
3. **区分「我的偏好」与「真缺陷」**：只把「按协议做不出来 / 做了会出错」列为缺陷。
4. **建议必须落到具体文件与具体改法**，不要写「建议优化一下」。
