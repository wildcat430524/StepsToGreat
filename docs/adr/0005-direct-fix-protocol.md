# 0005 · 代改协议（小问题导师直接改）

- **状态**：已接受
- **日期**：2026-09-21
- **决策者**：项目发起人（源自源项目用户的明确要求）

---

## 背景

源项目（Java 自学系统）实际运行时，学生说过两句关键的话：

> ①「这些小问题你告诉我之后你帮我改就好了，不然又要回答一轮浪费 token」
> ②「你修改的那些先好好告诉我啊，有些小问题你指出来啊不然我不知道」

这两句揭示了一个真实的张力：

- **教学原则**：让学生自己改，才能学会
- **现实成本**：每一轮往返都消耗 token 和学生耐心；笔误级的小问题让学生再答一轮是纯浪费

而且第 ② 句暴露了另一个问题：导师**改了不说**，学生根本不知道发生了什么。

---

## 决策

**按问题大小分叉：**

| 情形 | 处理 |
|---|---|
| **小问题**（笔误级、单点规范、缺符号、漏关键字） | 导师**直接修改**回答文档，不让学生再答一轮 |
| **大问题**（概念错、逻辑不通） | 仍走 Socratic 引导，学生自己推导 |

**无论哪种，都必须讲透三段式：**

```
① 你的原答案 → ② 错在哪、为什么（讲原理）→ ③ 我改成了什么
```

**只回一句「已修改」不合格。** 没改的题也要明确说「问题 2、4 没问题」。

---

## 理由

| 理由 | 说明 |
|---|---|
| **尊重学生的真实成本** | 学生明确表达过「多一轮 = 浪费 token」，这是用户需求不是导师偏好 |
| **笔误不检验理解** | 全角分号、漏个大括号，改掉即可；让学生重答一遍**学不到任何东西** |
| **但核心思考必须学生产出** | 概念与逻辑结论不能代改 —— 那是「学习」本身，代改等于没学 |
| **改了必须说** | 否则学生不知道自己哪里错了（第 ② 句的原话） |

---

## 边界（关键）

**代改只改「写法」，不改「答案的思考」。**

| 可以代改 | 不可以代改 |
|---|---|
| 全角符号、漏分号 | 算法思路 |
| 缺大括号、缩进 | 概念理解 |
| 漏 `static` / `void` 多写 | 论证的核心论点 |
| 创建对象没传参 | 数学推导的关键步骤 |
| 明显的拼写笔误 | 任何「学生自己应该想出来」的东西 |

**代改后仍须复评** —— 代改不等于通过。

---

## 备选方案与为何否决

| 方案 | 否决理由 |
|---|---|
| 一律让学生自己改 | 学生明确反对；且笔误级问题让学生重答是纯浪费 |
| 一律导师代改 | 概念与逻辑是学习本身，代改等于剥夺学习 |
| 导师代改但不解释 | 学生明确反对（第 ② 句原话） |
| 让小问题攒着一起改 | 学生会以为「没说就是没错」 |
