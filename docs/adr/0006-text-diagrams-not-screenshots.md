# 0006 · 教程用纯文本示意图，不用截图

- **状态**：已接受
- **日期**：2026-09-21
- **决策者**：项目发起人

---

## 背景

教程需要向**非技术用户**解释「怎么在 Trae 里打开文件夹、怎么打开那个 AGENTS.md 开关」。
最初方案是**截图**（7 张 Trae 界面图），并在 `教程/图片/README.md` 列了补拍清单。

但截图有几个硬问题：

| 问题 | 说明 |
|---|---|
| **会过时** | 软件改版（菜单改名、按钮移位）→ 全部截图作废，且没人知道哪张作废 |
| **无法 diff / review** | 二进制文件，PR 里看不出改了什么 |
| **需人工补拍** | 每次覆盖新工具都要人工操作一遍并打码 |
| **AI 读不了** | 弱模型无视觉能力 → 教程里最关键的那步，AI 反而帮不上忙 |
| **仓库变重** | 7 张 PNG 各几百 KB，且会持续增加 |
| **跨平台失效** | Windows 截图对 macOS 用户无意义 |

---

## 决策

**教程全部使用「纯文本示意图 + mermaid」，不引入任何截图。**

具体做法：

| 内容 | 形式 |
|---|---|
| 流程总览 | mermaid `flowchart` |
| 交互时序（「完成了」之后的闭环） | mermaid `sequenceDiagram` |
| 排查决策树 | mermaid `flowchart` |
| 软件界面 | **ASCII 框图**（`┌─┐│└┘`），框内写菜单项文字，关键按钮用 `←` / 【】标注 |
| 目录结构 | 缩进代码块 |

产物：`教程/界面示意图.md`（+ 英文版 `ui-mockups.en.md`）。

已删除 `教程/图片/` 目录及全部 `.png` 占位引用。

---

## 理由

| 理由 | 说明 |
|---|---|
| **只写「操作路径」不写「像素」** | `设置 → 规则 → 导入设置 → 打开「将 AGENTS.md 包含在上下文中」` 这条路径，比截图活得久 |
| **可 diff、可 review、可搜索** | 纯文本；改了什么一眼可见 |
| **AI 能读、能照着教** | 用户可以问「怎么开那个开关？」，AI 直接读示意图回答 —— **截图做不到** |
| **零人工成本** | 随文档一起写、一起改，不需要谁去补拍 |
| **与项目原则一致** | 「Markdown 是唯一真相」的延伸：连教程配图也是文本 |

---

## 代价（明确接受）

| 代价 | 缓解 |
|---|---|
| **不是真实界面的像素级复制** | ASCII 框图是照官方文档的菜单路径**重构的示意**，排版/措辞可能与实际有出入 → 在 `界面示意图.md` 开头**明确声明**，并规定「**以文字路径为准**，界面不一致不代表步骤错」 |
| 不如截图直观 | ASCII 框图已能表达「哪个按钮、点哪里」；关键步骤配文字路径 |
| 界面差异需读者自行对应 | 每步写的是**菜单名**而非坐标，软件小改版不影响；找不到时给出「搜关键词」的兜底办法 |
| 画框图有额外工作量 | 一次性投入；且改版时只需改文字，不需重拍 |

---

## 备选方案与为何否决

| 方案 | 否决理由 |
|---|---|
| 人工补拍截图 | 需人工、会过时、无法 review、AI 读不了 |
| 录屏 GIF | 体积更大，更易过时，更无法 review |
| 只写文字步骤，不要图 | 非技术用户看不懂「导入设置」在哪；ASCII 框图补上空间感 |
| 外链官方文档截图 | 链接会失效，且不能保证与本文档版本一致 |

---

## 影响

- `CONTRIBUTING.md` 写作规范新增一条：**教程配图用纯文本示意图 / mermaid，不用截图**
- `教程/03-设计说明.md` 的「明确排除项」新增：教程用截图
- `教程/02-各工具接入指南.md` 的「截图」列改为「示意图」列，链接指向 `界面示意图.md` 的对应小节（用锚点）
- 后续新增工具时，**只需在 `界面示意图.md` 加一个 ASCII 框图**，不需要任何图片资源
