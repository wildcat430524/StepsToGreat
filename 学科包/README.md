# 学科包（Subject Packs）

> 一个学科包 = 一个 Markdown 文件，定义**这个学科的三维评估长什么样**。
> 导师在教学前必须先读本 README 选包；没有对口的，照 [`_自定义学科包模板.md`](./_自定义学科包模板.md) 现场生成一个。

---

## 1. 为什么需要学科包

`协议/00_导师协议.md` 定义了三维评估的**机制**（三独立维度、全 ✅ 才算掌握），
但「第三个维度叫什么、判什么、什么是可豁免笔误」**每个学科都不一样**：

| 学科 | 维度 ③ | 判什么 |
|---|---|---|
| 编程 | 语法可编译 | 代码结构性正确、能跑 |
| 英语 | 表达规范 | 语法、时态、搭配、拼写结构 |
| 文科 | 表述规范 | 论证结构、术语、引用 |
| 理科/数学 | 推导与计算 | 符号、步骤、单位、计算 |
| 考研/考公 | 答题规范 | 题型格式、得分点覆盖 |

学科包就是把这张表**展开成完整定义**的地方。

---

## 2. 内置学科包

| 文件 | 覆盖范围 |
|---|---|
| [`编程.md`](./编程.md) | 各类编程语言、算法、工程实践 |
| [`语言.md`](./语言.md) | 英语、日语等外语学习 |
| [`文科.md`](./文科.md) | 历史、政治、哲学、法学、文学 |
| [`理科.md`](./理科.md) | 数学、物理、化学、生物 |
| [`考试.md`](./考试.md) | 考研、考公、考证等应试类 |

> 一个学科可能跨多包（如「考研数学」= 理科 + 考试）→ **以主包为准，把另一包的判据附在主包后面**，并在学习档案里注明用了哪套。

---

## 3. 怎么选（导师决策树）

```
学生要学什么？
├─ 编程语言 / 算法 / 框架 / 工程          → 编程.md
├─ 外语（英语、日语…）                     → 语言.md
├─ 历史 / 政治 / 哲学 / 法学 / 文学        → 文科.md
├─ 数学 / 物理 / 化学 / 生物              → 理科.md
├─ 目标是某场考试（考研考公考证）          → 考试.md（+ 对应内容学科包）
└─ 以上都不像（乐器、健身、写作、软件操作…）→ 现场生成自定义包
```

**自问一句**：这个学科的答案，什么是「**结构性错误**」（必须扣分），什么是「**手滑**」（不扣分）？
答得出来 → 照模板写；答不出来 → 先问学生「你们老师/考试怎么扣分的」。

---

## 4. 生成自定义学科包的步骤

1. 复制 [`_自定义学科包模板.md`](./_自定义学科包模板.md) 为 `<学科名>.md`。
2. 填 5 件事：
   - 维度 ① / ② / ③ 各叫什么、各判什么（**必须三个独立**，不能合并）
   - 该学科**典型的可豁免笔误**（写下来，避免误扣）
   - 该学科**典型的致命错误**（写下来，避免漏判）
   - **出题形态**（这个学科怎么出题才有意义：写代码？翻译？论证？解题？）
   - **验证方式**（怎么确认学生真会了：跑代码？复述？换场景？）
3. 存进 `学科包/`，并在 `我的学习/00-学习档案.md` 的 📋 学生信息里注明用了哪套。
4. 若这个学科**很常见**（比如「乐器」「健身」），欢迎提 PR 到本仓库，让下一个人不用再写。

---

## 5. 纪律

- ❌ 不许把三个维度合并成「综合打分」——全 ✅ 才推进的机制就靠维度独立。
- ❌ 不许因为学科「不好量化」就跳过维度 ③——**换个名字**也要有（如「表达清晰度」「步骤完整性」）。
- ✅ 学科包只定义**评估口径**，不定义课程内容（内容由导师按学生资料现场生成）。
