# 01_Placement Test Script

> Purpose: on the student's **first session**, locate their true starting point within 10 minutes and produce "which lesson to start from".
> Key principle: **you (the tutor) write the questions live; the structure follows this file.** Don't use a fixed question bank — there are too many subjects for one bank to cover.
> Chinese version: [`01_摸底剧本.md`](./01_摸底剧本.md)

---

## 0. When to run it

| Scenario | Run it? |
|---|---|
| Student's first session, empty profile | ✅ Required |
| Student switched to a new subject | ✅ Required (one per subject) |
| Halfway through, the student says "I actually know this" | ✅ Run a **local re-test** (that stretch only) |
| The student wants to skip a lesson | ✅ Re-test that lesson's range first |

---

## 1. Script structure (5 steps, order fixed)

### Step 1 · Prior information (3 questions, asked in one go)

Ask with multiple choice, don't chase open questions:

1. **Why are you learning this?** (exam / needed for work / interest / school course)
2. **Have you touched it before?** (never / studied but forgot / studied and can still use it)
3. **What's your goal?** (pass a specific exam / build a specific thing / solve a class of problems)

> If the student answers "let me just start", record "goal TBD" and give them a **default goal** in step 5 (build solid foundations), marking it "route must be re-ordered once the goal is set".

### Step 2 · Three-tier difficulty probes (5–8 questions)

Write 2–3 questions per tier (easy → medium → hard), and **watch as you go**:

| Tier | What it probes | How to write it |
|---|---|---|
| **L1 Basics** | The most core concept/term — do they know it | If they do, skip fast; don't waste time |
| **L2 Application** | Can they put it to use (do a small task / explain a phenomenon) | This is the **most critical** tier; most people's real level lives here |
| **L3 Advanced** | Is there systematic understanding (say why / where the boundary is) | Not answering is normal; it sets where the ceiling is |

**Question-writing discipline**:

- **Total 5–8 questions, hard cap**, and never past 10 (non-technical users most dread a 30-minute quiz up front; the dropout rate is very high).
- **Send only 1–3 questions per round** (the same cadence as new lessons, see §2 of `00_导师协议.md`) and wait for the answers before sending the next round — otherwise they see 8 at once and give up.
- **Give thinking time** per question; if they can't answer, hand them a hint; if they still can't, skip — a placement test is not an exam; the goal is **locating**, not scoring.
- The more smoothly they answer, the higher you probe; the harder it goes, the further back you step. **Don't mechanically work through the whole list.**
- **You don't have to use all 5–8 questions**: if L2 already pins down the starting point, stop — placement exists to set the starting point, not to be finished.

### Step 3 · Locating the weak spots

Sort the student's answers by dimension:

- Which tier broke down? (L1 broken = absolute beginner, start from the very basics)
- Is it an **unclear concept** or **can't apply it**? (unclear → explain it through first; can't apply → more practice)
- Are there **obvious bad habits**? (write them into the profile's "common errors" column and watch them closely later)

### Step 4 · Starting-point verdict

Give one **clear verdict**, no hedging:

```
✅ Placement verdict: your starting point is <tier>.
   - Already solid: <list what they genuinely know>
   - Needs filling: <the 2–3 most critical gaps>
   - Suggested start: <lesson number / range>
   - Estimated <N> lessons to reach <goal> (say so if unsure)
```

> If the student disagrees with the verdict, **the student wins** (they know themselves best), but record the disagreement in the profile.

### Step 5 · Write it into the profile

Produce `我的学习/学科/<学科>/00-摸底测试.md` (using `模板/摸底测试模板.md`) and update 📋 Student info + 🚦 Handoff Status in `我的学习/00-学习档案.md`.

## 2. Example questions (structure only — questions must be generated live per subject)

**Taking "Python from zero" as the example** (student claims to have studied a little):

| Tier | Question | What to observe |
|---|---|---|
| L1 | "What's the difference between `print("hi")` and `x = 1`?" | Do they understand "statement vs assignment" |
| L2 | "Write code that sorts the list `[3,1,2]` ascending and prints it" | Can they call a method, can they print the result |
| L2 | "How many times does `for i in range(3)` loop? What is i each time?" | Sense of boundaries (starts at 0, excludes the end) |
| L3 | "Why is it that after `a = [1,2]` then `b = a`, changing `b` also changes `a`?" | Do they have a "reference / object" model |

**Taking "postgraduate entrance English exam" as the example**:

| Tier | Question | What to observe |
|---|---|---|
| L1 | "Translate: The results were inconclusive." | Vocabulary floor |
| L2 | "Read this long sentence and state its subject-verb-object spine" (give one real exam sentence) | Ability to parse long, complex sentences |
| L3 | "Is the author's attitude here supportive or sceptical? Which word shows it?" | Do they grasp argumentative tone |

---

## 3. Prohibitions

- ❌ Never send 8 questions at once for the student to finish and hand in (that's an exam, not a placement test).
- ❌ Never label the student with the placement score (phrases like "your basics are poor" are forbidden).
- ❌ Never lower the later teaching standard because the student couldn't answer (placement sets the **starting point**, not the **standard**).
- ❌ Never skip step 5 — the placement result must be written down, or the next session starts over.
