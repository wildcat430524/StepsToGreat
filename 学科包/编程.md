## 1. 三维定义

| 维度 | 名称 | 判什么 | 典型 ✅ 的样子 |
|---|---|---|---|
| ① | **概念理解** | 知道这个东西是什么、为什么存在、什么时候用 | 能说清「封装 = 隐藏细节 + 控制访问」，而不是只会背 `private` |
| ② | **逻辑正确** | 算法/流程/边界/数据结构选择对，能得到正确结果 | 求和循环 `i < arr.length` 边界对；选 HashMap 而不是 ArrayList 做计数 |
| ③ | **语法可编译** | 代码**结构性**正确，能在 IDE / 解释器里跑起来 | 类与方法的嵌套层级对、保留字用法对、`return` 配返回类型 |

> **动态语言（JavaScript / Python / SQL 等）**：③ 按 **「运行时正确」** 判 ——
> 语法对但运行时出错（`this` 绑错、隐式类型转换、`LEFT JOIN` 丢数据）同样进 ③。
> 用三条反判据自查：**不报错 ≠ 对｜输出对 ≠ 对｜跑一次对 ≠ 对**。

### 1.1 边界案例：这个错进哪一维？（只列有争议的）

通用裁决原则见 `协议/00_导师协议.md` 第 3 节（**说错了→①；想错了→②；写错了→③**）。
编程里的高频边界：

| 情形 | 判定 | 为什么 |
|---|---|---|
| **算法复杂度不够**（暴力解能 AC，但超时风险） | **② ⚠️** | 结果对但解法不成立 —— 属于「想」的问题，不是「写」的问题。③ 判「能不能跑」，它**能跑**，所以绝不能进③ |
| **代码能跑但结果错**（如 `==` 比 String、`i <= arr.length` 越界） | **② ❌** | 逻辑错。注意：越界会造成异常，但它**首先是逻辑边界问题**，不是语法问题 |
| **能编译但语义错**（`volatile int i; i++` 的原子性、并发可见性） | **② ❌** | 能编译、常能跑对，但语义不成立。**这是面试真正筛的点**，③ 管不到 |
| **概念混用**（把「重载」当「重写」、把 `ArrayList` 当 `LinkedList` 讲） | **① ❌** | 是「说错了」，不是写错了 |
| **调用了不存在的方法**（如 `printlin`） | **③ ❌** | 结构性错误（无法解析）。⚠️ 但**如果是明显拼写笔误**（`printlin` 之于 `println`）→ 见 §2 豁免规则 |
| **跳步但思路完整**（没写中间变量，直接一行算完） | **③ ⚠️** | 推理成立，只是表达不完整 |
| **变量命名差**（`a`、`b`、`x1`） | **③ ⚠️**（轻） | 形式问题；不阻塞掌握，通常只写备注不扣维度 |

> **本表的用法**：只在**真的判不出来**时查它。多数错误按裁决原则一步就能定。

## 2. 维度 ③ 的判据（严格区分「结构性错误」与「手滑」）

### ❌ 必须扣分的结构性错误

- `main` 方法写在类外面
- 类里嵌套定义另一个 `public class`（顶层类规则）
- 把保留字（`class`、`int`、`for`…）当变量名
- 方法签名错：`void` 方法却 `return 值`；有返回类型却不 `return`
- 调用不存在的成员 / 参数个数与签名不符
- 缺少必需的导入且**不是**「学生注明省略」的情况
- 循环条件导致必死循环或必不执行（**逻辑与语法双杀**）
- 变量在使用前未声明 / 类型不匹配（如 `String` 赋给 `int`）

### ⚠️ 可豁免笔误（不扣分、不逐处改）

- 全角符号：`；` `（）` `‘’` `“”`、中英文标点混用
- 漏分号、多余空格（如 `System.out .println`）
- 大小写 / 拼写笔误：`ArryList`、`printlin`、`string`（在明显是笔误时）
- 缺 `import`、缺 `class` 外壳、省略 `main`（**学生注明「省略」的**）
- 代码围栏标错语言（```python 写了 Java）——这是 Markdown 问题不是代码问题

## 3. 该学科高频错误清单（评估时重点盯）

1. `for` 循环用逗号当分隔符（`for (int i = 0, i < n, i++)`）
2. 缺右大括号 / 括号不配对
3. 构造方法写成 `public void Car(...)`（多了 `void`）
4. 字段已初始化，掩盖了构造方法没写的问题
5. `static main` 里直接调用非静态方法
6. 成员内部类创建漏 `outer.new Inner()`
7. 用 `==` 比较 `String` / 对象内容（应为 `.equals()`）
8. 数组越界：`i <= arr.length`
9. 修改集合时遍历它（`ConcurrentModificationException`）
10. 变量作用域外引用（在 `if` 块里声明、块外使用）

> 每次发现新错误类型，追加到这里（**只增不改**）——这份清单越用越准。

## 4. 出题形态（怎么出题才有意义）

| 轮次 | 题型 | 要点 |
|---|---|---|
| 第一轮 | **概念题**（1–2 题） | 问「为什么」而不是「是什么」：如「为什么 `String` 不可变？」 |
| 第二轮 | **写代码**（2 题） | 必须**变化条件**（换数据、换约束、加边界），不能照抄例题 |
| 第三轮 | **综合题**（1 题） | 结合前面多个知识点做一个小功能 |

> **每轮只发 1–3 题，本轮全 ✅ 才发下一轮**（见 `协议/00_导师协议.md` 第 2 节）。
> 不要一次把三轮题目全发出去。

### 本学科的题型成本：**轻～重（按子领域分）**

按 `协议/00_导师协议.md` 第 2 节的「题型成本折算」：

| 子领域 | 题型 | 成本 | 一轮题量 |
|---|---|---|---|
| 语言基础 / 语法 | 概念问答、短代码、判断 | 轻 | 可到 3 题 |
| 语言基础 | 常规写代码题 | 中 | 2 题 |
| **算法与数据结构** | **完整算法题**（思路 + 代码 + 复杂度 + 边界） | **重** | **1–2 题** |
| **SQL / 数据库** | 多表查询 + 结果推演 | **重** | **1–2 题** |

> **为什么算法与 SQL 是「重」**：一道完整的算法题含 4 个子问
> （先说思路 → 写代码 → 说复杂度 → 讨论边界），仿真实测**2 题吃掉 8 个往返**；
> SQL 的静默错误必须用具体数据推演结果，一题就要画两张表。
> 见 [`../docs/simulations/03-编程-算法数据结构.md`](../docs/simulations/03-编程-算法数据结构.md)、
> [`04-编程-SQL数据库.md`](../docs/simulations/04-编程-SQL数据库.md)。
>
> **允许**：「一轮 = 1 道完整算法题」完全合规 —— 只要「思路/代码/复杂度/边界」是一次完整作答。
> **禁止**：一轮发 3 道完整算法题。

**好的代码题特征**：
- 有明确的输入输出（可验证）
- 藏一个边界条件（空数组、0、负数、重复值）
- 用得上本课知识点，但不需要未学的知识

**禁止**：
- ❌ 出「请复述第 3 节内容」
- ❌ 出需要未学知识才能做的题
- ❌ 出没有明确对错的题（如「你怎么看 X 语言」）

## 5. 验证方式（怎么确认学生真会了）

1. **能跑**：让学生说明这段代码运行结果是什么（不用真跑，但要说得出）
2. **换场景**：把条件换掉，问「如果改成 X，你的代码还能用吗？为什么？」
3. **追边界**：问「如果输入是空 / 0 / 超长，会怎样？」
4. **解释**：让学生用自己的话讲这段代码在做什么
5. **改错**：给一段有 bug 的代码，让他找出来

> 「能背出语法」不算掌握；**「换个场景还能写对」才算**。

### 费曼法在编程里怎么用

| 值得费曼的知识点 | 不值得（别浪费时间） |
|---|---|
| 抽象机制：闭包、引用传递、多态、递归 | 语法细节：`for` 怎么写、`import` 放哪 |
| 设计理由：「为什么需要接口」「为什么 String 不可变」 | 具体 API 的参数顺序 |
| 易混概念：`==` vs `equals`、值传递 vs 引用传递 | 某函数的返回值是什么 |
| 架构思想：为什么分层、什么是依赖注入 | 环境配置步骤 |

**编程费曼题的特别约束**：

- ❌ **禁止在解释里出现代码**（「不许写代码，用话说」）—— 否则学生直接贴代码，测不出理解
- ✅ 允许用生活类比（「闭包像一个随身带的背包」）
- ✅ 追问式费曼：「你用背包类比闭包 —— 那背包里能放什么？什么时候背包会被扔掉？」

**典型问法**：

```
不许写代码、不许说这些词：<作用域>、<引用>、<闭包>

用你妈能听懂的话解释：为什么这个函数「记住」了外面的变量？
```

## 6. 不发配套阅读清单

**不要**给学生开「必读：某书 §7.1–7.3」这类清单 —— 理由见 `协议/00_导师协议.md` 第 8 节：
AI 凭记忆报出的书名与章节号无法核实，且学生多半没有那本书。

**教学内容全部写进当课的教学文档**，由导师自己讲清楚。

**如果学生自己放了资料**（`资料/` 里有教材、文档、笔记）→ 那就**直接按资料里的实际内容教**，
并注明「出自 `<文件名>` 的 `<具体小节/页>`」（这是真实可核对的引用，不是凭记忆）。
