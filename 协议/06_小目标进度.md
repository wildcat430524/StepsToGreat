# 06_小目标进度

> 用途：先让学生及时感到「刚才这一步学会了、做成了」，再用模块掌握条和本次技能清单呈现成果。条与清单分属两个层级，不能互相换算。
> 英文版：[`06_小目标进度.en.md`](./06_小目标进度.en.md)

## 1. 两层进度：模块条与小目标清单分开

**模块**是本学科里一段有边界的知识范围（如「列表方法」「一元一次方程」「日常交流」），包含多个**知识单元**及更小的**小目标**。模块**不等于**当前任务、当前轮次或整个学科。

**模块条**表示模块掌握进度：`K` = 模块内已正式掌握的知识单元数，`T` = 课程路线界定的单元总数。十格条填充 `floor(10*K/T)` 格，配文 `K/T 个知识单元已掌握`。

**小目标清单**（第 2 节）是学生当前正在攻的具体技能。清单勾数**绝不换算成模块进度**，模块条也不随某次勾选变化。

单元记录与等权规则：

- 模块名称、边界、单元清单与「单元等权」规则记录在**已有的课程路线** `00-课程路线.md` 中，**不新增状态库、权威掌握表或进度数据库**。
- 默认单元 = 路线里**已命名**的课/知识单元，未掌握的也计入 T；只有正式掌握者计入 K。K 由导师独立核对 📊 掌握表与 `01_学生回答.md` 的「最终复评结果」得出，**不是正确率，也不是智能掌握概率**。
- 模块未定义（路线里没有该模块或单元清单）或证据不足时：模块条位置写 **「模块进度待确定」/「模块进度待核对」**，不造分母、不造百分比。缺规划就先教当前内容，**不强迫在导入前做长规划**。

## 2. 本次小目标：2–4 项具体技能

本次小目标写 2–4 项技能，**通常 3 项，极小目标可 1 项**，不凑数、不把同一能力拆成几条。每条都是具体、可观察的能力：能解释什么定义、完成什么操作、做出哪步推导或表达什么意思；一条只表达一件事，不写泛泛的「理解了」「学完了」。

技能清单**不写流程项**：不写「完成任务」「交作业」「通过验证」「做完练习」。**正式验证是后台判断条件，不混进技能清单，也不作为最后一条技能。**

勾选与完成：

- 每项技能必须有**学生原答**加**该学科适用维度的正式评估**才能勾；**导入原答只注明「初步观察」，不算已掌握**；**提示下完成不勾**独立能力项。
- 本块**正式轮次全部通过**，本次小目标才闭环；全钩给出明确的小目标完成感。某项独立验证或综合验证还没做时，用**一句短说明**如实标注，**不假装全掌握**。

模块条的推进与清单无关，条件更严：

- 只有该单元**所有条件满足、且对应整课最终复评通过**，模块 K 才加 1。
- 必要费曼/综合收尾在路线中提前归入某个单元的出口条件或验证单元；未通过时该单元不计入 K，所以条不满。如果旧路线漏掉必要收尾，标「模块范围待核对」并说明缺口，不能画与 K/T 矛盾的条，也不临时偷偷加分母。
- 所以「本次小目标全钩」时模块条可能**一动不动**；模块条满格只出现在模块真正完成时。

## 3. 顶部两层，对话与两份文档共用

固定三层信息，顺序不变：

1. **模块标题 + 模块条**：模块名，下一行等宽十格条与 `K/T 个知识单元已掌握`（模块未定义时写「模块进度待确定」）。
2. **小目标标题 + 技能复选**：本次小目标名，下面 2–4 条 `- [x]` / `- [ ]`。
3. **一句当前一步 + 简短依据**：`> 当前一步：……。依据：……`。

- 模块条在**小目标标题之前**，**不放在小目标标题下面**；小目标区**不再写局部 `k/N`，也不画第二条**。
- 依据用短注分别指向模块正式掌握证据和本次技能评估，例如「认识列表最终复评；本次第 1 轮评估」；导入注明初步观察，未验证注明未验证，不另开报告。
- 对话用**加粗标题行**，文档用 **H2**；三处内容必须一致，层级和字体可以不同。
- 条用等宽 `██████░░░░`；不支持方块时用 `#`/`-` 表示同样的十格，不支持复选框则用「已完成 / 待完成」。导师按证据更新，学生不必手动勾。
- 正文自然换行，窄屏可顺序阅读；不用宽表格、不画框、不靠空格对齐。

| 展示位置 | 放在哪里 | 展示什么 |
|---|---|---|
| 对话 | 块开始、小目标或模块计数改变、停下、接续 | 完整两层 + 当前一步，只在需要时重贴 |
| `01_教学引导.md` | 标题后、正文前 | 同样两层，下面接讲解 |
| `01_学生回答.md` | 标题后、题目与原答前 | 同样两层，下面接本轮作答与追加评估 |

两份文档把整块放进下面这两行注释之间，每份只保留一个当前区：

```
<!-- s2g-goal-view:start -->
（模块标题 + 模块条 + 小目标标题 + 技能复选 + 当前一步）
<!-- s2g-goal-view:end -->
```

**只替换这一区**（展示快照），学生原答、提示记录、历史评估和已追加的历史快照一律不动。旧文档没有这两行注释时，在标题后新建一区并保留历史；与教学/回答模板共用同一版式。

整块视图**紧凑必要**：不加成就墙、仪表盘、重复任务区，不强制八段或固定条数总结；关键原理、条件、来源、题面和正式复评不能为短而省。

## 4. 及时反馈与完成感

**每个实质进展先反馈成果，再给纠错或下一步。** 用一句话指出「你刚才独立做对了什么 → 产生了什么结果 → 这一步现在能做了」，必要时引用学生的一小段原答。不只回「正确」「很好」，不等模块条变化才反馈，不让长评估淹没成果。正式评估记录仍完整保存；对话先点出成果和待改处，细表留文档，需要解释的原理照样讲清。

技能已达标就及时勾对应项；只做成中间一步也具体肯定该步，但不把整项勾满。提示后完成要说明帮助条件。导入可说「这个判断你已经做对了」，仍记初步观察，不冒充正式掌握。

全技能且本块正式轮次通过时，明确说「这个小目标完成了，你现在能……」，让学生停在可指认的成果上。模块条是否变化另算，不用「还只完成一点点」冲淡成果，不附加新的必做任务。

- **块开始**：先给两层视图，再给短场景和当前一题；不提前展示未来题面或空轮次。
- **跨小目标**：模块条计数**保持**（不因换小目标清零），小目标标题和清单**换成新的**；旧小目标已学技能的证据留在回答文档里，**不抹掉、不搬进新清单**。
- **小目标完成**：全钩且本块正式轮次通过后展示成果并收尾，模块条照实显示（常常不变），不因清单满了就强制模块满条；若仍有已发布验证未通过，如实说明已确认技能及剩余验证，不宣告闭环。
- **停点**：小目标全钩且本块正式轮次全部通过 → 明确说这块结束、可以停；除学生已约定连续学习，不附下一块题目。模块条也满时要另说清模块完成的是什么。
- **收尾未完成**：模块还差预先约定的费曼/综合验证时，对应单元保持未掌握；旧路线漏项标范围待核对并解释，不临时加任务冲淡刚完成的小目标。
- **卡住**：缩小当前练习或换解释，不扩张目标、不新增技能来凑进度。
- **范围确需变化**：说明原因，另立新块或在已有路线里改单元清单并重算；不在临满格时增加必做项。原块成果与未验证部分如实保留。
- **证据不足/冲突**：模块未知或 📊 与最终复评冲突时标「模块进度待核对」，不放宽标准，不编造总课数或全课程进度。

## 5. 打钩依据

| 情况 | 怎样更新 |
|---|---|
| 学生完成一个动作，但还没达到该项技能条件 | 具体肯定这一小步；该项保持待完成，模块条不动 |
| 导入原答看起来证明某项技能 | 只在清单旁注明「初步观察」，**该技能保持未勾**；转入正式学习并按正式评估通过后才勾，不据此宣告掌握 |
| 在提示下答对 | 标明提示；独立技能项不勾选 |
| 学生说懂了、导师代答后复述、资料不可读 | 不作为完成证据 |
| 正式评估通过 | 从已重读的原答与本轮评估映射到技能项；一次回答可证明多项，一项也可需多次验证 |
| 修订后该项关键概念或逻辑仍有问题 | 该项保持待完成，不放宽标准 |
| 新证据推翻先前的初步判断 | 说明具体依据并撤销该钩，保留历史观察/评估，不偷偷改写 |
| 单元条件全满足且对应整课最终复评通过 | 模块 K 加 1，按 `floor(10*K/T)` 重画模块条；由路线 + 📊 + 最终复评独立核对，不由清单勾数推导 |
| 模块收尾（费曼/综合）未完成 | 对应单元尚未满足出口条件，不计入 K；旧路线遗漏时标范围待核对，不造假满条 |

**满格条件**：技能每项都有证据、独立项由学生完成、本块已发布正式轮次适用维度全通过，小目标才全钩；**模块条满格另需模块全部单元掌握且收尾验证通过**。完成小目标不等于整课掌握，📊 的「已掌握」仍要求整课最终复评。

## 6. 更新流程、恢复与核对

更新顺序：

1. 先读 `01_学生回答.md`，保存原答与提示；
2. 重读并做适用维度评估，追加本轮评估与技能判定；
3. 技能勾选由**评估结果**确定；模块 K/T 由**课程路线 + 📊 + 相关整课最终复评**独立推导；
4. 从最新证据生成同一份两层视图，更新学生文档顶部，再读并更新教学文档顶部；
5. **重读两处核对**一致后，在对话里展示同一视图。

- 在顶部末用一句依据分别指向模块正式掌握证据与本次技能评估；范围未知、未验证或初步观察如实标明。
- 一处写入失败时明确说该文档待同步，**不声称三处一致**；先读实际文件、按证据修复，不回滚学生答案、不伪造评估。
- **恢复不凭记忆**：先读 `我的学习/我的规则.md`、🚦 交接状态和证据文档，再比对两份文档顶部视图；不一致就从证据重新生成。
- 未知模块或证据冲突时，三处如实显示「模块进度待确定/待核对」；**不新增权威表**，🚦 只引用所属文档并写当前小目标及下一步，📊、⏳ 仍按 `03_落档事件表.md` 维护。
- 本节只定义展示与判定口径，**不改动实际学生档案**的既有结构与历史内容；教学和改偏好时也不改无关文件。

## 7. 一个有实感的示例

以下是虚构的版式与反馈示例，不是当前学生记录，不能写入真实档案。

**场景**：购物清单里已经有面包、鸡蛋，临出门又想起牛奶。学生需要往原清单末尾加一件商品，不重写或覆盖原清单。

**假设路线与证据**：模块「Python 列表」有四个等权单元：认识列表、添加、删除、查找。「认识列表」已有整课最终复评，其余尚未整单元掌握。当前「添加」单元包含单项追加和批量添加两个小目标；这次只学单项追加，不提前发下一目标的题。

学生独立写出 `items.append("牛奶")`，并从更新后的列表确认原有商品仍在、牛奶位于末尾；本次技能与正式轮次都通过。先给反馈：

> 原来的面包、鸡蛋都保留了，牛奶也加到了末尾。这个小目标完成了：你现在会给已有清单追加商品，不用重写整张清单。

再同步两层视图：

**模块：Python 列表**

`██░░░░░░░░` **1/4 个知识单元已掌握**

**本次小目标：给购物清单追加一件商品**

- [x] 说清 `append` 是把单个元素加到列表末尾
- [x] 区分追加与覆盖，知道原有元素会保留
- [x] 独立调用 `append` 新增商品并核对列表变化

> 当前一步：本次小目标已完成，可以停在这里。依据：认识列表最终复评、本次技能评估。

**清单全钩，模块条仍是 1/4。** 添加单元里的批量添加还没学，本次单项追加却已完整做成，不能把成果说成「还不算完成」。以后添加单元全部条件和整课最终复评通过，条才变为 `█████░░░░░` **2/4**。换下一个小目标时模块条保留，清单换成新技能，原成果留在回答记录中。


## 8. 验证口径

检查：模块条是否由路线 + 📊 + 最终复评推导（而非清单勾数换算）、未定义模块是否如实标「待确定/待核对」、技能是否 2–4 项实感能力且不含流程项、正式验证是否留在后台而非清单条目、勾选是否有原答与适用维度评估、提示是否如实标注、`floor(10*K/T)` 与格数是否一致、模块收尾未完成时是否避免 100%/满条、三处两层视图是否一致且只替换顶部展示区（历史答案未被覆盖）、停点是否明确、恢复时是否保留同一范围。清单不是新增题单，**分轮仍只出 1–3 题、不预发后续轮次**。本设计用于实现目标感与完成感，是否提高持续学习或学习效果仍需真实使用验证。
