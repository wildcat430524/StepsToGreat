# 03 · 设计说明（给作者与贡献者看）

> 这份文档回答：**为什么这么设计**。用户不需要读它。

---

## 1. 这个项目要解决什么问题

市面上的 AI 学习工具都在解决「**给你内容**」。
但真正让人学不会的不是缺内容，是**没人盯着你、没人评估你、没人告诉你哪里错了**。

本项目的假设：

> **AI 已经足够会教，缺的是一套「能长期运转的教学协议」。**

所以这个项目**不是软件**，是**一套 Markdown 协议**：
把它放进一个文件夹，任何能读文件的 AI 都变成一位一对一导师。

---

## 2. 三个核心设计决策

### 决策一：Markdown 为唯一真相，不做 App

| 方案 | 问题 |
|---|---|
| 做个网站/App | 要维护服务器、要账号、用户数据锁在你手里 |
| 做成 Prompt 集合 | 用户每次要手动粘贴，状态不落盘 |
| **Markdown 文件夹（本方案）** | ✅ 用户拥有数据；任何工具都能读；换工具不丢记录 |

**代价**：不能做炫酷交互。
**收益**：零运维、零锁定、十年后还能打开。

### 决策二：`AGENTS.md` 单一契约 + 自动生成跳板

问题：25+ 个 AI 工具，每个认不同的规则文件名。

| 方案 | 结果 |
|---|---|
| 每个工具复制一份完整规则 | ❌ 改一处要改 25 处，必然漂移 |
| 只写 `AGENTS.md`，不认的工具不管 | ❌ 大量用户用不了 |
| **单一契约 + 脚本生成跳板（本方案）** | ✅ 改规则只改一处；换工具零成本 |

跳板文件内容只有一句「去读 AGENTS.md」，由 `_tools/setup-agents.mjs` 生成。
**新增工具 = 改一个数组 + 重跑脚本。**

### 决策三：三维评估 + 全 ✅ 才推进

从旧项目（Java 自学系统，22 课实战验证）继承的核心机制：

```
概念理解 ／ 逻辑正确 ／ 规范表达
        ↓ 三项全 ✅
      才允许推进下一课
```

**为什么必须三维独立**：

- 只有「概念」→ 学生能说不会做
- 只有「逻辑」→ 学生做对了但说不清为什么
- 只有「规范」→ 学生写得漂亮但理解错

**为什么维度 ③ 随学科变**：编程判「能编译」，英语判「语法」，数学判「推导」。
所以有 `学科包/` —— 把这条从 Java 专属变成通用。

## 3. 从旧项目继承了什么，改了什么

### 继承（经过 22 课实战验证）

| 机制 | 出处 |
|---|---|
| 三维评估全 ✅ 才推进 | 旧项目主循环 |
| 回答文档 = 唯一学习证据 | 旧项目铁律 |
| 小问题直接代改 + 三段式讲透 | 旧项目「代改协议」（用户原话） |
| 落档事件表（事件 → 写哪个文件） | 旧项目第 7 节 |
| 状态只维护三处（🚦/📊/⏳） | 旧项目反例教训 |
| 「改了必须重新读文件」 | 旧项目硬规则 1 |
| 配套阅读精确到章节 | 旧项目路线文档末节 |

### 优化（本项目新增）

| 优化 | 为什么 |
|---|---|
| **学科包** | 旧项目硬编码 Java 口径，无法通用 |
| **多 agent 适配层** | 旧项目只在 DSH 里跑，别人用不了 |
| **摸底剧本** | 旧项目只有一次诊断，且无固定剧本 |
| **框架/数据分离** | 旧项目一份 clone 一份数据，框架更新会冲突 |
| **质检脚本** | 旧项目 22 课无自动检查，靠人肉 |
| **示例演示** | 旧项目新人看不懂结构 |
| **中英双版** | 开源需要 |
| **git 版本管理** | 旧项目**零版本管理**（22 课证据全靠人肉备份）——最大风险 |

## 4. 目录结构的设计理由

```
StepsToGreat/
├── AGENTS.md              ← 唯一契约（AI 入口）
├── 协议/                   ← 教学规则（AI 只读）
├── 学科包/                 ← 评估口径（AI 只读）
├── 模板/                   ← 骨架（AI 只读）
├── 示例/                   ← 演示（AI 只读）
├── 教程/                   ← 给人看（AI 只读）
├── _tools/                 ← 脚本（AI 只读）
├── docs/                   ← 兼容矩阵 + ADR
├── 我的学习/               ← 学生的全部数据（AI 可写）
└── 资料/                   ← 学生的资料（只增不改）
```

**关键划分**：**只读框架** vs **可写数据**。

- 框架：`git pull` 可更新，永不被学生数据污染
- 数据：进 `.gitignore`，学生永远不会因更新框架而丢记录

## 5. 为什么不做这些（明确排除）

| 排除项 | 原因 |
|---|---|
| 内置课程内容 | 学生带着自己的资料来，塞别人的课反而干扰 |
| 云端同步 | 数据主权归用户；同步用他自己的网盘/Git |
| 自动判题后端 | 判题逻辑由 AI 承担，不需要服务端 |
| 用户账号系统 | 没有服务器，就没有账号 |
| 交互式 HTML 课程 | Markdown 是唯一真相；HTML 按需生成，不落盘 |
| 固定题库 | 学科太多，固定题库覆盖不了；题由 AI 现场出 |

## 6. 怎么贡献

### 加一个学科包（最有价值）

1. 复制 `学科包/_自定义学科包模板.md`
2. 填 6 个部分（三维定义、判据、高频错误、出题形态、验证方式、阅读写法）
3. 存为 `学科包/<学科名>.md`
4. 提 PR

**判断标准**：这个学科里，什么是「结构性错误」（必须扣分），什么是「手滑」（不扣分）？
答得出来就是好学科包。

### 加一个 AI 工具

编辑 `_tools/setup-agents.mjs` 的 `TARGETS` 数组 + `MATRIX` 表，跑一次脚本，提 PR。

### 改协议

改 `协议/` 前请先开 issue 说明**你在什么场景下遇到了什么问题**。
协议是核心资产，改动会传播到所有使用者。

### 跑质检

```bash
node _tools/check.mjs        # 全量检查
node _tools/check.mjs --quiet
```

检查项：围栏奇偶、坏链接、占位词残留、UTF-8 无 BOM、CRLF、跳板一致性、档案路径存在性。

## 7. 已知限制

| 限制 | 说明 |
|---|---|
| 依赖 AI 的工具调用能力 | 不会读写文件的 AI（纯聊天）只能手动粘贴 |
| 免费额度有限 | 一次会话读 5–10 个 md 很吃积分 → 让 AI 按需 read |
| 隐私 | 多数工具会临时上传文件做索引；敏感资料需用本地模型 |
| 判题准确度取决于模型 | 弱模型可能误判 → 建议用中档以上模型 |
| 无自动化测试 | 只有 `check.mjs` 做格式检查；教学质量靠协议约束 |
| 中文长文档表现 | 无厂商公布量化数据；免费档多绑 Auto/弱模型，长指令遵循度更弱（推断） |
