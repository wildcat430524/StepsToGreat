## 1. 摸底（1 轮，3 题）

### 导师 · 开场

读完 `学科包/编程.md` 与学习档案。摸底不评档案，只定位起点。3 题，一次性发。

> **Q1（概念）**「Java 的 `HashMap` 查一个 key 平均是 O(1)」——这个 O(1) 指的是什么？为什么 `HashMap` 能做到，而 `ArrayList` 得一个个翻？
> **Q2（复杂度）**
> ```java
> for (int i = 0; i < n; i++)
>     for (int j = 0; j < n; j++)
>         count++;
> ```
> 这段的时间复杂度是多少？说理由。
> **Q3（代码）** 写一个 Java 方法 `int max(int[] arr)` 返回数组最大值。可以省略 class 外壳。

### 学生 · 阿豪

> Q1：O(1) 就是很快啊，一次就查到了。ArrayList 慢是因为它是数组。
> Q2：O(n) 吧，它就是循环 n 次。
>
> Q3：
> ```java
> int max(int[] arr){
>     int m = arr[0];
>     for (int i = 0; i <= arr.length; i++){   // 这句我写的应该对
>         if (arr[i] > m) m = arr[i]；
>     }
>     return m;
> }
> ```

### 导师 · 摸底评估

| 题 | ①概念 | ②逻辑 | ③语法 | 判定 |
|---|---|---|---|---|
| Q1 | ❌ | ✅ | — 不适用 | 未掌握 |
| Q2 | ✅ | ❌ | — 不适用 | 未掌握 |
| Q3 | ✅ | ❌ | ⚠️ | 未掌握 |

- **Q1**：你答的是「快」，不是「为什么快」。`O(1)` 在这里指**查表这一步只花固定代价**；`HashMap` 能做到是因为它把 key 换算成数组下标、直接跳过去取，**跳过了逐个比较**。你说的是结论的另一种说法，没有机制。
- **Q2**：O(n) 错。**外面循环 n 次，里面每次都跑 n 次 → 总操作数是 n × n，应该是 O(n²)。** 你把「循环层数」当成「循环次数」了。
- **Q3（两个问题）**：
  1. `i <= arr.length` —— `arr.length` 是**元素个数**，最后一个下标是 `length - 1`。你这个循环最后一次会访问 `arr[arr.length]`，**数组越界**。这是实质错误，不是笔误。
  2. `arr` 为空时 `arr[0]` 直接崩。
  3. `；` 是全角分号 —— **这个不扣分**，属于可豁免笔误（`编程.md` 第 2 节）。

**摸底结论**：概念停在「会用不会说」，复杂度基本没建立，边界习惯差。正课就从 **哈希表为什么快 + 两数之和 + 复杂度分析** 起。

| 题 | ①概念 | ②逻辑 | ③语法 | 判定 |
|---|---|---|---|---|

**本轮不通过，不发下一轮。** 逐条：

**1️⃣ 问题 1（题 1）：把结论当理由**
- **你的原答案**：「哈希快是因为它是 O(1) 的，数组是 O(n) 的」
- **问题在哪里**：这是**用结论解释结论**。`O(1)` 只是「快」的学名，不是「为什么快」的原因。真正的原因在**存储方式**：`HashMap` 用 key 自己的内容算出一个数组下标，**一步跳到那个位置**；数组/线性扫描没有这层「定位」，只能从第 0 个开始一个个比。
- **我改成**：「哈希表拿 key 算出应该放哪个桶，直接跳到那个桶取，不用逐个比较；数组没这个定位能力。」

**2️⃣ 问题 2（题 2）：复杂度算错** —— 这是本学科最要命的一类错
- **你的原答案**：「复杂度是 O(1)，因为哈希表查表是 O(1)」
- **问题在哪里**：**O(1) 是「查一次表」的代价，不是「整个算法」的代价。** 你的循环跑了 `n` 次，每次都做一次查表 + 一次存表，所以总代价是 `n × O(1)` = **O(n)**。你把「单步复杂度」当成了「整体复杂度」——这是背题解最典型的症状：记得住结论，串不成链。
- **我改成**：「时间 O(n)：遍历 n 个元素，每次查表/存表是 O(1)。空间 O(n)：`map` 最多存 n 个元素。」

**3️⃣ 问题 3（题 2）：`map.put` 在自己前面 —— 大问题，走 Socratic，我不代改**

先不解释。看这个输入：`nums = [3, 2, 4]`，`target = 6`。**你把循环抄下来逐步跑一遍**，告诉我你的代码返回什么、正确答案是什么。

**4️⃣ 豁免声明**：`contaisKey` 拼写笔误 —— **不扣分**，属于`编程.md` 第 2 节的可豁免笔误，我直接代改成 `containsKey`，你不必再答一轮。

**5️⃣ 没改的地方你说对了**：`return new int[0]` 的无解兜底 ✅；`for (int i = 0; i < nums.length; i++)` 边界写对了（摸底那个 `i <= arr.length` 的毛病这题没犯）✅。

#### 学生 · 阿豪

> 但我还是不服 —— **我这代码 LeetCode 上 AC 了，为什么不算过？**

#### 导师 · 「能过 ≠ 掌握」

你说的应该是 **LeetCode 原题**。原题 `n ≤ 10^4`，暴力两层循环是 10⁸ 次比较，Java 一秒内跑得完，**确实能 AC**。但我这题写的是 **10^5**，暴力和「先存后查」的漏判在 10¹⁰ 次这个量级上根本跑不完。

看清楚这三点：

| 「能过」证明了 | 「能过」**没有**证明 |
|---|---|
| 这一组测试数据没超时 | 你的算法在约束规模下对（大样例一压就崩） |
| 这一组数据没触发边界 | 你处理了 `[3,2,4]/6` 这种自身复用（原题刚好没这个用例） |
| — | 你能说清复杂度（面试官直接问「你这 O 是多少，为什么」） |

**AC 是判题机的结论，不是能力的结论。** 我们的口径是「换个场景还能写对才算掌握」——你换个约束就崩了，所以不算过。

#### 学生 · 阿豪

> 为什么是 O(n)？里面那个查表不是 O(1) 吗？我还是不懂。

#### 导师 · 换角度（第一换：数步数）

不讲定义了，你拿张纸跟我数：

> 假设 n = 5。把循环展开成 5 行，每行写「查一次表 + 存一次表」。
> `查表 + 存表` → 2 行。5 次就是 10 行。n 次就是 **2n 行**。
> **总行数跟着 n 一起长大 → O(n)。** `O(1)` 是「一行的长度」，不是「整张纸的行数」。

#### 学生

> 还是不太懂，那不还是每一步都是 1 吗？

#### 导师 · 换角度（第二换：极限对照）

换个问法：`n` 从 10 万变成 200 万，**你这个算法要多花几倍时间**？

> 多 20 倍。因为循环次数也变成 20 倍。
> 如果整体是 O(1)，那 n 涨 20 倍、时间应该**一点不变**——显然不是。
> 所以整体肯定不是 O(1)。**是 O(n)。**

#### 学生

> 哦……所以 O(1) 说的是"查一次"要多久，O(n) 说的是"这一整段"要多久。**那懂了。**

#### 学生 · 改好了

> ```java
> public int[] twoSum(int[] nums, int target) {
>     Map<Integer, Integer> map = new HashMap<>();
>     for (int i = 0; i < nums.length; i++) {
>         int need = target - nums[i];
>         if (map.containsKey(need)) {
>             return new int[]{map.get(need), i};
>         }
>         map.put(nums[i], i);
>     }
>     return new int[0];
> }
> ```
> 时间 O(n)：遍历 n 次，每次查表和存表各是 O(1)。空间 O(n)：map 最多放 n 个数。
>
> 题 1 重答：哈希表拿 key 通过一个函数算出它应该在第几个桶，直接跳过去取。数组没这个"定位"，只能从第 0 个一个个比。

## 4. 本学科发现的优化点

### 4.1 学科包缺陷（`学科包/编程.md`）

**⭐ 问题一：复杂度分析该归②还是③？——归②，但②现在的措辞覆盖不了它。**

现口径：② =「算法/流程/边界/数据结构选择对，**能得到正确结果**」；③ =「代码**结构性**正确，能跑起来」（判据全是 `main` 位置、保留字、方法签名）。

- **绝不能归③**：③ 的判据是「能不能跑起来」。O(n²) 的暴力解**能跑、能在 LeetCode 上 AC**——塞进③等于宣布「能跑 = 达标」，恰好放过了本学科最典型的不会。而且复杂度不是语法，`编程.md` 第 2 节列的结构性错误（`main` 在类外、保留字、方法签名）里没有一条沾得上复杂度。
- **归②是对的，但②现在的定义判不出来**：②说「能得到正确结果」。学生交 `O(n²)` 暴力，**结果确实正确**，按现措辞该判 ✅。而仿真里真正发生的是：阿豪的哈希解**结果也对**（`[3,2,4]/6` 返回 `[0,0]` 是特例才崩），复杂度却是错的。②用「结果对不对」这一个轴，测不出「在约束规模下可不可解」。
- **实测误判风险**：R1 题 2 首评时，如果严格按照文字判②，导师会判「算法正确、结果正确 → ②✅」，直接漏掉 O(1)/O(n) 的错和自身复用 bug。**我是自己补了「复杂度 + 边界」两个子项才判出 ❌ 的**——这不是协议给的，是导师临场发挥。

**⭐ 问题二：「多个正确解法」怎么评——现包完全没覆盖。**

阿豪的暴力解和哈希解**在 `n ≤ 100` 时都是正确解**。`编程.md` 没有任何一句话告诉你「哪个算过」。仿真里导师靠题面写死的 `n ≤ 10^5` 才判出暴力不达标——**这个判据是我发明的，不在包里**。

- 关键认识：**没有规模约束，复杂度的对错是不成立的**。`n ≤ 100` 时暴力 10⁴ 次操作，完全正确，硬判 ❌ 是惩罚正确解。
- 所以「多个正确解法」的正确判法是**两级判定**：题面给约束 → **达标线 = 能在约束内跑完**；达到基线解（正确但复杂度不够）判 ⚠️（部分掌握，走引导）；达到目标解判 ✅。
- 「复杂度更优」**不应**变成第三个维度或额外加分项——它只是备注（`✅ 且更优`）。理由见 `学科包/README.md` 第 5 节：三维独立是这个项目推进机制的根基，加维度会破坏它。

**⭐ 问题三：「代码能 AC 但说不清复杂度」按现有三维算不算掌握？——按现协议算，这就是缺陷。**

阿豪交了 O(n) 哈希解，代码对、边界对（改完后）、语法对 → **三维全 ✅ → 推进**。但他只是背了题解模板：他自己承认「刷了 50 题好像啥也没学会」，换个问法（三数之和）立刻废。而③「语法可编译」和②「能得到正确结果」**都测不出这一层**——代码是对的，结果是对的。

这正是本次仿真最有价值的一处现场证据：**导师不问「说说复杂度」，三维评估就抓不到他。** 一问，他说成 O(1)——② 才亮 ❌。

**⭐ 问题四：`编程.md` 说的「有明确输入输出」对算法题不够。**

现包第 4 节「好的代码题特征」只要求「有明确的输入输出（可验证）」。对算法题至少缺两样：

1. **数据规模上界**（必须）—— 没有它，复杂度无意义（见问题二）。仿真里我被迫自己补了 `2 ≤ nums.length ≤ 10^5`。
2. **返回值语义**（必须）—— 返回下标还是值？有多组答案返回哪组？无解返回什么？**阿豪正是用「题目没说清楚」找借口**，而题面确实有可挑剔的地方（`i != j` 写了，但「同一个元素不能用两次」这种自然语言说明没写）。**题面不严，就是给学生递借口。**

**问题五：其他没覆盖的**

| # | 缺口 | 现场证据 |
|---|---|---|
| a | **③ 在算法领域实际权重极低** | 3 道算法题只有 1 道能碰到③（还只是笔误）。算法答案常是**伪代码/自然语言思路**，根本到不了编译层。协议要求「不许跳过③」，导致评估里堆 `— 不适用`，形同虚设 |
| b | **缺「思路层」判据** | 算法是「先想后写」。学生写出正确答案可能纯属背的。`编程.md` 第 5 节「换场景」太弱——需要**「先说思路，再写代码」的强制产出要求** |
| c | **缺面试导向的掌握证据** | 阿豪目标是秋招。算法掌握的终点不是 AC，而是「**被追问不倒**」。现包没有「追问」型判据 |
| d | **第 3 节高频错误清单全是语言错误** | 10 条里 9 条是 Java 语言错（构造方法加 `void`、内部类 `outer.new`、`==` 比 String）。**没有一条是算法错误**。算法需要独立清单（见 4.5） |
| e | **费曼禁令不够** | 第 5 节说「禁止出现代码」——对算法不够。阿豪的回答全是术语（`O(1)`、哈希表），禁了代码他照样能糊过去。**必须同时禁 Big-O 记号与本知识点核心术语** |

### 4.2 协议缺陷（`协议/00_导师协议.md`）

| # | 缺陷 | 现场卡点 |
|---|---|---|
| 1 | **学生拿题面当借口时，协议没规定动作** | 阿豪说「题目没说清楚」两次。协议第 4 节只说「不得只记录未掌握」，第 10 节只说「语气耐心鼓励、标准不降低」，**没有「借口处理」流程**。导师需要三步：①核实题面是否真有歧义（有→认账并补题面）②无歧义→明确指正「这不是题面的问题」③把「审题习惯」本身记进 ⏳ 待办。**第③步协议完全没路径**——⏳ 待办只记知识点 |
| 2 | **算法需要「先说思路再写代码」两阶段，协议只有单阶段** | 第 2 节主循环全是「学生提交→评估」。算法题直接判代码对不对，**测不出背题解**。第 4 节的 Socratic 只用在「概念错」之后，没有「先交思路」的前置机制 |
| 3 | **「小问题代改」与「结构性错误」在算法里的分界线没定义** | 第 5 节：小问题=笔误级，直接代改。但 `i <= arr.length`（摸底 Q3）**是一个字符的笔误，还是结构性错误？** `编程.md` 第 2 节列了「循环条件导致必死循环或必不执行」为结构性错误，但 `i <= n` 造成的**越界**不在清单里。**判定悬挂**：导师不知道该代改还是走 Socratic。仿真里我按「结构性错误、走 Socratic」处理——**这是我补的规则，不是协议给的** |
| 4 | **「本轮全 ✅ 才发下一轮」在算法里会把一轮拉爆** | 第 2 节这张表本身推导出矛盾：下一节再展开（4.3） |
| 5 | **「每题标三维」在算法里产出大量 `— 不适用`** | 第 3 节允许「自然语言概念题标不适用」，但没解决「**某学科整体③低适用**」的情况。逐题写 `— 不适用` 是纯噪声 |
| 6 | **没有「学生跑题」的处理规则** | 阿豪在第 3 题追问复杂度时岔去问「HashMap vs Hashtable」。协议第 9 节有「挂起任务不阻塞」，但那是学生主动说「先进行新课」，**不是中途岔题** |

### 4.3 对话节奏问题（3 题一课对算法够不够？）

**实测数据**：

| 阶段 | 题量 | 往返数 | 备注 |
|---|---|---|---|
| 摸底 | 3 题 | 2 | 快，能一次定位 |
| 正课 R1 | 2 题 | **8** | 思路→代码→复杂度追问×2→边界→复评 |
| 正课 R2 | 1 题（费曼） | 3 | 费曼第一次❌→重讲→✅ |
| **合计** | **6 题** | **13** | 协议设想「一课 2–3 轮 ≈ 5 题」 |

**结论：一轮 1–3 题对算法偏多，一课 2–3 轮偏少。**

原因很清楚：**一道算法题 = 一道普通编程题的 3 倍工作量**，因为它内部有四个子问题：**思路 → 代码 → 复杂度 → 边界**。而协议第 2 节要求「本轮全 ✅ 才发下一轮」——R1 的两道题里，题 2 就吃掉 8 个往返。

实际执行时会退化成两种坏结果：
- **要么** 一轮只敢出 1 题——那「一课 2–3 轮 ≈ 5 题」的目标完不成（只能跑到 2–3 题）；
- **要么** 硬出 2–3 题——学生做 4 道半成品题，反馈拉得很长，正好违背协议第 2 节「不要让学生一路错到底」的设计初衷。

**另一个跑偏点**：R1 用了 8 个往返，其中 **2 个是学生跑题**（问 Hashtable）、**2 个是同一问题追问**（`为什么是 O(n)` 问了两次）。协议对这两类都没有节流规则。

### 4.4 该学科特有的教学法发现（值得固化）

| # | 做法 | 现场证据 | 建议 |
|---|---|---|---|
| 1 | ✅ **「先说思路，再写代码」两段式** | R1 题 2 用两段式：阿豪第一段就说「枚举两个数，两层循环」，**在写代码前就暴露了他只会暴力**。导师用一句提示（「走到第 i 个数时你手上需要知道什么」）把他引到哈希——**省掉了一整轮代码返工** | **固化进 `编程.md` 第 4 节，作为算法出题的默认形态** |
| 2 | ✅ **代码题固定附加问「说清时间/空间复杂度及理由」** | 不问他永远不会说。一问，O(1) 的错误立刻现形——这是抓「背题解」的唯一有效探针 | 固化为算法写代码题的**必附问**，计入② |
| 3 | ✅ **复杂度用「数步数」教，不用「讲定义」** | 第一次讲「哈希 O(1) 所以整体 O(1)」他没懂。改成「把循环抄在纸上，n=5 写 5 行，每行做 2 件事 → 2n 行」，30 秒懂。第二次换成「n 从 10 万变 200 万，时间涨几倍」再确认一遍 | 固化为算法讲解的**首选角度** |
| 4 | ✅ **边界/逻辑错用「具体反例」驱动，不用「讲道理」** | 说 100 遍「先 put 会复用自己」不如一句「`nums=[3,2,4]`, `target=6`，你返回啥？」——他自己跑出 `[0,0]`，立刻认账 | 固化：算法纠错默认**先给反例，再讲原理** |
| 5 | ✅ **费曼题在算法里的三禁令** | 禁代码（包里有）+ **禁 Big-O 记号** + **禁「哈希/哈希函数/HashMap」**。第一次他只挤出「算一下就知道」，**精确暴露了「只会用术语」**；三禁令一上，他被迫去抓机制，第二次用快递柜讲对了 | 补进 `编程.md` 第 5 节费曼约束 |
| 6 | ⚠️ **反面：导师第一次"讲定义"是无效动作** | 追问复杂度时导师讲渐进分析定义，学生第二次追问「还是不太懂」——**浪费一个往返**。算法教学里「讲定义」的优先级明显低于「给反例/数步数」 | 写进 `编程.md` 第 5 节作为反面提示 |
| 7 | ✅ **「能过 ≠ 掌握」要讲透两层** | 阿豪的暴力解在原题（`n ≤ 10^4`）**确实能 AC**——导师没有否定事实（否定事实会失去信任），而是讲清「AC 只证明这组数据没超时，没证明算法在约束规模下对，也没证明你能被追问」。阿豪当场接受 | 固化进 `编程.md` 第 5 节「验证方式」 |

### 4.5 学生画像补充（真实错误类型与困惑模式）

**建议在 `编程.md` 第 3 节后新增「3.1 算法与数据结构高频错误清单」**（现清单 10 条全是语言错，算法一条没有）：

1. **哈希表「先 put 后 check」** → 把自己当成配对的另一半（`nums=[3,2,4]`,`target=6` 返回 `[0,0]`）
2. **双层循环复杂度算成 O(n)** —— 把「循环层数」当成「总操作次数」
3. **边界写成 `i <= n`** —— 把「元素个数」当成「最后一个下标」
4. **能写出 O(n) 解，却把整体复杂度说成 O(1)** —— 把「单步复杂度」当「整体复杂度」，**背题解的最典型症状**
5. **忘处理空输入**（`arr[0]` 在空数组上崩；哈希解法在 `length == 0` 时直接崩）
6. **把「哈希平均 O(1)」当成「永远 O(1)」** —— 从不谈冲突退化和最坏情况
7. **只谈时间不谈空间** —— 从不主动提「哈希解法用了 O(n) 额外空间」
8. **递归无终止条件 / 终止条件写在递归调用之后**
9. **双指针忘排序前提 / 快慢指针相遇条件写错**
10. **「题目没说清楚」型归因** —— 答错后第一反应是怪题面，不先查自己的代码

**阿豪的困惑模式（画像补充）**：

- 他**不是不会用**，是**串不成因果链**。原话：「我刷了 50 题好像啥也没学会」——缺的是「为什么」，不是题量。
- 他**用术语当挡箭牌**：说 `O(1)`、说「哈希表快」，但一问机制就空。**术语密度高 ≠ 理解深**，这是判「背题解」的直接信号。
- 他**答错后先找外部归因**（题面、题目偏）。需要一条明确规矩，仿真里导师用的是「**先怀疑自己的代码，再怀疑题面**」——值得写进 `编程.md` 第 3 节。
- 他**有真实的羞耻感**（「是不是我太笨了」）——鼓励必须**给具体证据**（「你今天只错了两个点，都在同一小时内改对了」），空泛的「你可以的」无效。

> **（A）一轮 1–3 题对算法偏多** —— 一道算法题含「思路/代码/复杂度/边界」四个子问题，实测 R1 两题吃掉 8 个往返。建议算法改为一轮 1–2 题、一课 3–4 轮。
> **（B）复杂度必须算进②，但②的措辞要从「能得到正确结果」扩成「正确性 + 复杂度 + 边界」三子项。** 绝不能归③ —— ③ 判的是「能不能跑起来」，而 O(n²) 的暴力解**能跑、能 AC**，归③就等于宣布「能跑 = 达标」。
