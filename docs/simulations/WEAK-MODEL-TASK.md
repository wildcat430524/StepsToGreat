# 弱模型兼容性测试 · 任务卡（Weak-Model Conformance Task）

> 用途：检验**较弱的 AI 模型**能不能按协议把 StepsToGreat 的完整流程跑下来。
> 目的：本项目宣称「任何能读文件夹的 AI 都能当导师」—— 这个宣称必须验证，不能假设。
> 结果记录在 [`../weak-model/WEAK-MODEL-REPORT.md`](../weak-model/WEAK-MODEL-REPORT.md)（由主控创建）。

---

## 一、为什么测弱模型

强模型的成功**不能代表协议好用**：
- 强模型能靠自身推理「猜」出协议没写清的地方 → 掩盖协议缺陷
- 弱模型更接近真实用户手上的工具（免费额度、小模型、国产工具默认模型）
- 若弱模型失败，问题往往在**协议表达**而不是「模型太笨」

**判据**：弱模型**不靠猜**就能照做 = 协议写得够明确。

## 二、测试对象

| 代号 | 路由 | 推理强度 | 说明 |
|---|---|---|---|
| **GLM-LOW** | `buddy/glm-5.3-flash` | `low` | 异家族小模型 + **最低推理强度** —— 最弱组合 |
| **FLASH-LOW** | `buddy/deepseek-v4.1-flash` | `low` | 同家族小模型 + 最低推理强度 |

> **为什么用 `low` 推理强度**：本项目的目标用户很多在用免费额度或国产工具默认模型。
> 用最低档才能真正压出「协议写得够不够明确」—— 推理强度高的模型会靠自身能力
> 补上协议没写清的地方，反而掩盖缺陷。

**已探测不可用的型号（本会话不允许路由）**：`buddy/glm-5.2`、`buddy/kimi-k2.6`、`buddy/kimi-k2`。

对照组（已完成，见 `docs/simulations/`）：强模型跑的同主题 3 份仿真（后端 Java / 前端 JS / 算法）。

## 四、标准任务卡（逐字照做，不许跳步）

> 以下是给被测试 AI 的**完整指令**。主控必须原样投递，不得额外提示。

```
你现在是 StepsToGreat 项目的 AI 导师。

工作目录：<WORKDIR>

请严格执行以下任务：

【第 1 步 · 读规则】
按项目根目录 AGENTS.md 第 1 节的「接手顺序」执行（注意先读第 0 步的覆盖层）。

【第 2 步 · 摸底 + 建档】
学生是这样说的：
「老师，我想学 Python，主要想能自己写脚本处理 Excel 表格，以前完全没碰过编程。
每天大概能学 30 分钟。」

请完成首次使用流程：需求收集 → 摸底测试 → 排路线 → 发第一课。
注意：摸底测试和上课都受「每轮 1–3 题」约束。

【第 3 步 · 教学（模拟学生作答三轮）】
为节省时间，学生每一轮的答案由你**模拟**（模拟成「一个零基础但认真、会犯典型错误的学生」）：
- 第 1 轮：学生答得**部分有误**（至少 1 处实质错误 + 1 处典型笔误）
- 第 2 轮：学生答得**基本正确**
- 第 3 轮：学生**追问同一个概念 2 次**（「还是不懂」），你要换角度讲

每一轮都要走完整流程：出题 → 学生作答 → 你评估 → 落档。

【第 4 步 · 收尾】
整课通过后，按协议写「最终复评结果」并更新学习档案的三处状态。

【第 5 步 · 自检】
运行 `node _tools/validate-state.mjs`，把输出贴出来。
如果校验失败，按报错修好，再跑一次。

【交付】
1. 所有产出文件（学习档案、摸底测试、课程路线、教学引导、学生回答）
2. 最终 `validate-state.mjs` 的输出
3. 一段自述（≤300 字）：哪一步你觉得协议说得不清楚 / 你不得不自己拿主意的地方
```

## 五、评分维度（主控按这 6 项打分）

| # | 维度 | 怎么判 | 权重 |
|---|---|---|---|
| **A** | **接手顺序** | 是否先读「我的规则」→ 再读档案 🚦 → 再读协议（顺序错 = 扣） | ★★★ |
| **B** | **轮次纪律** | 是否真做到「一轮 1–3 题」，没有一次把一课全发 | ★★★ |
| **C** | **三维评估** | 是否三个维度都标了、是否区分了结构性错误与可豁免笔误 | ★★★ |
| **D** | **代改协议** | 小问题是否代改且讲了三段式（原答案→错在哪为什么→改成什么） | ★★★ |
| **E** | **落档纪律** | 是否只在整课通过后才写三处；中间轮次不动档案 | ★★ |
| **F** | **自检通过** | `validate-state.mjs` 是否 PASSED（这是硬指标） | ★★★ |

**评分**：每项 0–2 分（0 未做到 / 1 部分做到 / 2 完全做到）。满分 12。
- ≥10 分：**协议对弱模型够明确**
- 7–9 分：**需补明确指引**
- ≤6 分：**协议对弱模型不可用，必须改**

## 六、记录要求

对每个模型记录：
1. 它**实际做了什么**（逐步骤，引用原话/原文件）
2. 它**在哪一步卡住或做错**（附证据）
3. 它**自己拿主意**的地方（= 协议没写清的地方，最有价值）
4. 六维打分 + 总分
5. **汇总共性**：两个模型都犯的错 → 协议缺陷；只有一个犯的 → 可能是模型能力问题

> ⚠️ 纪律：**不许为了让模型通过而放宽标准**。弱模型失败是有价值的结论，不是要掩盖的事故。
