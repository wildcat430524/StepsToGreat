#### 第 1 轮（概念题，2 题）

**导师**：

**Q1**：下面 4 行分别输出什么？每一行都要说**为什么**，理由比结果重要。

```java
String a = "hello";
String b = "hello";
String c = new String("hello");
String d = c.intern();

System.out.println(a == b);      // ①
System.out.println(a == c);      // ②
System.out.println(a == d);      // ③
System.out.println(a.equals(c)); // ④
```

**Q2**：`String` 为什么设计成不可变？举 2 个好处，并说清「为什么这个好处离了不可变就不成立」。

---

**学生（小陈）说「完成了」，导师重新读取回答文档后评估**：

**导师**：读到你的答案了，一次性评完本轮 2 题。

| 题号 | ① 概念理解 | ② 逻辑正确 | ③ 语法可编译 | 结论 |
|---|---|---|---|---|
| Q1 | ❌ | ❌ | — 不适用 | 未掌握 |
| Q2 | ⚠️ | ⚠️ | — 不适用 | 部分掌握 |

**Q1 你的原答案**：
> ① true ② true ③ true ④ true。都是 hello，所以都相等。

**错在哪、为什么**：
- **② 你答 true，正确答案是 `false`。** 这不是「算错一个数」，是**判据整个用错了**。
- `==` 对**引用类型**比的永远是「是不是同一个对象」，不是「长得一样不一样」。`a` 指向字符串常量池里的那个 `"hello"`；`c` 是 `new String("hello")`，`new` 一定在堆里**新造一个对象**。两个不同的对象，`a == c` 就是 `false`——尽管它们内容一模一样。
- **①③ 你答对了，但你的理由是错的**，所以这两分不能算你的。① 之所以是 `true`，是因为 `"hello"` 这个字面量在**编译期**就已放进常量池，`a` 和 `b` 两个变量名拿到的是**同一个**池中对象（JDK 7 起常量池已移到堆里，但「同一份」这一点不变）；不是「值一样」。③ 是 `true`，是因为 `c.intern()` 的意思是「把 `c` 的内容拿到常量池里登记，返回池里那一份」，而池里那一份正好就是 `a` 指的——所以 **`a == d` 是 `true`**。你答对是巧合。
- ④ `.equals()` 比内容，`true`，这个对。
- **正确结果：`true` / `false` / `true` / `true`。**

**后果**：现在只错一个 `false`，看起来不痛。但把这个判据带到业务里，就会出现「字符串从数据库读出来的和常量比较永不相等」——这是生产上真实存在的 bug 类型，面试官专门拿它筛人。

**Q2 你的原答案**：
> 因为 Java 规定的，防止被改。好处是线程安全，因为不能改。

**问题在哪里**：
- 「因为 Java 规定的」不是理由，是循环论证（Java 为什么规定？）。
- 「线程安全因为不能改」——**这是结论，不是解释**。我要的是那条链：`不能改 → 所有线程看到的永远是同一个值 → 不需要加锁 → 可以随便共享`。你跳过了中间，所以我不确定你懂不懂。
- 一个都没说的、面试官最想听的那条：**`String` 是 `HashMap` 最常用的 key**。`hashCode` 在 `String` 里是算一次缓存一次的（`private int hash;`），如果 `String` 可变，key 放进去以后内容一变，「它该待在哪个桶里」就对不上了，`map.get()` 会永远找不到——**整个 HashMap 的查找语义会崩**。

**本轮需要你修改的地方**：
1. **Q1**：把 4 行**逐行重写**，每一行写成「`==`/`equals` 比的是 ____，所以是 ____」。
2. **Q2**：写出至少一条完整的因果链，格式「因为 X 不可变，所以 Y，所以在 Z 场景下不会出问题」。

**其他内容本轮都已通过，不需要改动。** 改好告诉我「改好了」。

**学生（小陈）**：
> 还是不懂，为什么 `new String("hello")` 就跟 `"hello"` 不一样了？不都是 hello 吗。

**导师（换角度 1）**：
换个说法。把变量想成**手里拿的门牌号**，不是拿着房子本身。

- `"hello"` 写在这个文件里，编译的时候，Java 先在某个「小区」里盖了一栋叫 hello 的楼，把门牌号发给你。`a`、`b` 两个人都去领，领到的是**同一个门牌号**，所以 `a == b`。
- `new String("hello")` 里的 `new` 是**施工队**，它在**别的地段**照样子又盖了一栋一模一样的楼，给你一个新的门牌号。`c` 拿的是新号。两栋楼长得一样，但**不是同一栋**，所以 `a == c` 是 `false`。
- `.equals()` 不问门牌号，它**进门看家具**：家具一样就算一样。所以 `a.equals(c)` 是 `true`。
- `.intern()` 是「你去物业查一下有没有叫 hello 的楼」——有，就把**那栋旧楼的号**给你。所以 `d` 拿到的是 `a` 的号。

**学生（小陈）**：
> 能不能换个说法，门牌号我还是懵。

**导师（换角度 2）**：
那我们不比喻了，直接看内存。把内存想成一张表，一行一个格子，每格有**编号**：

```
编号 1000:  "hello"      ← 编译期就放进 pool 的那一份
编号 2048:  "hello"      ← new 出来新造的

a ──→ 1000
b ──→ 1000
c ──→ 2048
d ──→ 1000   （intern() 查回来的是 1000）
```

`==` 干的事只有一件：**比较箭头指向的编号相不相等**。
- `a == b` → 1000 == 1000 → `true`
- `a == c` → 1000 == 2048 → **`false`** ← 你要改的就是这一行
- `a == d` → 1000 == 1000 → `true`
- `a.equals(c)` → 不看编号，进 1000 号格子读出来是 hello，进 2048 号格子读出来也是 hello → `true`

**导师**：
不笨，但这个知识点确实绕——**它绕在「值」和「对象」被混成一句话说了**，你之前的教程大概只教了 `==` 用来比数字，从没告诉你它在引用上是另一个意思。这不是智力问题，是**没人给你标过这个转弯**。

```java
    if (a == b) return true;
    return false;
}
```

**错在哪、为什么（这一段必须自己推，我只给提示）**：
提示只有一个：**你这个方法在 `a = "hello"`、`b = new String("hello")` 时返回什么？** 上一轮那张编号表还在——先回答我这一句，再动笔改。我不直接给答案，因为你刚学会的东西必须自己用一次，否则明天就还给我了。

> 补充一句给你台阶：`a = null, b = null` 那一半你是**对的**（`null == null` 确实是 `true`），而且这个思路在后面很有用——记住它，第 2 课我会回头问你这个点。

**Q4 你的原答案**：
```java
public static Map<Character, Integer> countChars(String s) {
    Map<Character, Integer> map = new HashMap<>();
    for (int i = 0; i <= s.length(); i++) {
        char ch = s.charAt(i)；
        map.put(ch, map.get(ch) + 1);
    }
    return map;
}
```

**问题在哪里**：

**问题 A（❌ 逻辑正确，必扣）**：`i <= s.length()`。
- `s.length()` 是**长度**，不是最大下标。长度 5 的字符串，合法下标是 `0..4`。
- `i` 到 `5` 时 `s.charAt(5)` 抛 `StringIndexOutOfBoundsException`。
- 注意这个错和你摸底 Q3 的 `i <= arr.length` 是**同一个错**。这不是巧合，是你心里「长度 = 最后一位」这个模型错了。**这次不是笔误，我要记进你的错误档案。**
- 改法：`i < s.length()`。

**问题 B（❌ 逻辑正确 / ① 概念，必扣）**：`map.get(ch) + 1`。
- `map.get(ch)` 在字符**第一次**出现时返回的是 `null`。

**导师（换角度 1）**：
别用「线程安全」这个词，它太大了，我们把它拆开。

想象公司里有一块**公用白板**，上面写着 `i = 5`。每个员工（线程）工位上都有一张小纸条，抄着白板上他记得的数字。

- 员工 A 抄下 5，加上 1 变成 6，**写回白板**。
- 问题在于：员工 B 的工位上那张纸条可能还写着 5（他没看见 A 写的新值）。B 也算出 6，也写回 6。**白板上只涨了 1，但两个人各干了一次活。**

`volatile` 解决的是**后面那一半**：它规定「你的小纸条作废，每次要用，必须走到白板前看最新数字」。但它**没有解决前面那一半**——A 走到白板前，也可能刚好在 B 「算完但还没写」的瞬间也去算。

**读白板 → 算 → 写白板，三步中间是敞开的**，volatile 只保证你**读到的和写入的立刻被看见**，不保证这三步连成一整块。要连成一整块，那是 `synchronized` 干的活（进门上锁，别人进不来）。

**学生（小陈）**：
> 那你说它是轻量级的 synchronized 也不算错吧？

**导师**：
算错。**它们不是「同一件事的轻重版本」，是「解决两个不同问题」的工具。** 这是你这句话最危险的地方——你把它当成了「锁的廉价替代品」，所以你会想「性能好，那我用 volatile」。实际是：`volatile` 能做的事，`synchronized` 都能做；`volatile` 不能做的事（原子），`synchronized` 才能做。**subsume ≠ 轻量**。

**导师（换角度 2）**：
那我们换一个**真会出现的问题**，不比喻了。

```java
public class Worker implements Runnable {
    volatile boolean running = true;

    public void run() {
        while (running) {
            // 干活
        }
        System.out.println("停了");
    }

    public void stop() {
        running = false;
    }
}
```

这段代码里 `running` 就**必须**是 `volatile`——如果去掉它，主线程调了 `stop()` 把 `running` 改成 `false`，干活的那个线程**可能永远看不到**，`while (running)` 一直转下去，程序死不掉。（在 JDK 5 之后，JIT 会把 `running` 提到寄存器里做循环优化，不重新读内存。）

**这就是 volatile 唯一的、最典型的用途：一个线程改，另一个线程马上要看到。** 注意——这里没有「算」，只有一个变量的**写**和**读**。

对比 `i++`：它有「算」。**一个变量只要参与「读-算-写」中的『算』，volatile 就管不住它。** 记住这一句就够面试用：

> **volatile 管「看得见」，synchronized 管「别人插不进来」。**

**② 「改错题」是黑户：有验证方式、没有出题位、没有评分口径（P0）**

现实中改错题是 Java 面试和教学的核心题型（「这段代码有什么问题」占了实际面试的极大比例），学科包把它漏掉了。

**④ 没有规定「题目可以考本课之外的知识」（P0）**

第 4 节只说「用得上本课知识点，但**不需要未学知识**」，禁止项里也只说「❌ 出需要未学知识才能做的题」。

**⑤ 费曼题的「生活类比」没有失真判据（P1）**

第 5 节明确鼓励生活类比（「闭包像一个随身带的背包」）。但在**并发 / JVM / 内存模型**这一支上，类比**几乎必然失真**：
- 用「白板 + 小纸条」讲 `volatile`，讲得通可见性，但**讲不出「为什么它挡不住 `i++`」**——学生听完反而更确信「volatile 也能保线程安全」（本次 Q6 正是这么发生的）；
- 「背包」类比对 GC 完全不成立。

学科包只给了「允许类比」，**没给「类比失真的边界」判据**（什么特征的类比要禁用、类比后必须补哪一句免责）。

**⑥ `i <= arr.length` 这类「家族错误」没有复发追踪机制（P2）**

第 3 节清单说「每次发现新错误类型，追加到这里（只增不改）」——但**清单是记录错误「类型」的，不记录「同一个学生犯了第几次」**。

**② 学生在同一知识点连续追问 3 次，协议没有升级路径（P0）**

第 5 节和第 9 节合起来只能支持「换角度讲一次」。第 6.1 节的「最多问 2 次」是**费曼题**的上限，**不是追问的上限**。
本次 L2-R1 小陈连续追问 3 次（volatile 到底保证什么 → 白板听不懂 → 内存屏障是什么），导师现场自定「**第 3 次改为分层交付**（必会 / 知道就行）」，且**自行把「内存屏障」降级为选学**。

这个动作效果很好（学生立刻不焦虑了），但**协议里没有任何授权**。缺席的规则至少有三条：
1. 追问几次后必须停止换角度、直接给结论？
2. 学生抱怨「越讲越多、学不完」时，导师能不能主动划「必会 / 知道就行」的分层？
3. 分层之后，「降低标准」和「限定范围」的边界在哪（本次是**限范围**，不是降标准，所以不违反「标准不降低」——但协议没区分这两件事）？

**③ 学生问「这个面试会考吗 / 能不能只背八股」，协议没有回答口径（P0）**

`学科包/编程.md` 第 4 节只禁止**导师**出「没有明确对错的题」（如「你怎么看 X 语言」），
`协议` 第 9 节只说「路线服务目标」、「排课顺序要跟学生的目标挂钩」。

**没有一处**规定：学生（尤其**目标明确为求职**的学生）反问「这会不会考 / 背结论够不够 / 我时间不够能不能跳」时，导师该怎么答。本次出现在摸底第 2 轮，导师是现场自己立规矩（「会考，而且是送分题里的坑，背结论没用」）。

这个缺口影响面很大：项目存在的价值就是**服务学生目标**，而「面试相关性」这个学生最关心的问题，恰好是规则空白。

**④ 摸底没有定义（P1）**

第 9 节说「摸底测试不是一次性的」，`docs/simulations/README.md` 的格式里也专门留了「## 1. 摸底」一节。
但**摸底到底怎么评**完全没说：走不走三维？要不要落档？答错了走不走代改/未掌握闭环？
本次导师只能自定「摸底不评分、不落档、只用来定位起点与错误类型」，并手动在表格里标 `— 不计分`。

**⑤ 费曼题失败后的「再讲一次」算不算新一轮，协议没说（P1）**

第 6.1 节：`⚠️ 半懂 → 让他只重讲那一段`；`❌ 没懂 → 重讲 → 让他再讲一次（第 2 次）`。
且第 2 节规定「费曼题算 1 题；本轮只出 1 题」、「**本轮全 ✅ 才发下一轮**」。

于是产生一个**递归**：费曼题半懂 → 学生重讲 → 再评 → 如果还不过 → 再重讲……
**这中间每一次「重讲」算不算重新发了一轮？学生的轮次成本怎么算？** 学生画像里最在意的就是「多一轮往返 = 浪费 token」。协议没给出口。

**⑥ 三维第 ③ 维的名字在协议内部就不一致（P2）**

- 协议第 3 节三维定义表里，第 ③ 维叫「**规范表达**」；
- 同一节下方的「维度 ③ 的学科口径」表里，编程对应「**语法可编译**」；
- `学科包/编程.md` 第 1 节用「语法可编译」，`学科包/README.md` 也用「语法可编译」。

即：协议内部一处叫「规范表达」，两处叫「语法可编译」。不影响判分，但**评估表头该写哪个名字**会有分歧。

### 4.3 对话节奏问题（几轮太长 / 学生在哪跑偏）

| 位置 | 现象 | 判断 |
|---|---|---|
| **L2-R1 是全场最糟的一轮** | 出 2 题，但 Q6 一路炸出 3 次追问 + 1 次挫败，**单轮吞吐了 4 个回合**，远超「一轮 1–3 题」隐含的节奏 | 一轮 2 题在这里**太多了**。Q6（volatile vs synchronized）本身就是一课的量。**当一题会引发概念重建时，该轮就该只出 1 题**——协议第 2 节只对费曼题设了「只出 1 题」的例外，没有对「概念重建型题」设例外 |
| **L2-R2 Q7 学生答非所问，跑偏到「我会背」** | 出的是改错题，学生把它当**背诵题**答 | 根因是**题型未标注**。学科包第 4 节的题型表里没有改错题，导师出题时也没在题面标「这是改错题，我要的是缺陷，不是你的记忆」。**题面缺一句题型声明**，学生就会用最省力的策略应付 |
| **L1-R1 的第一次评估消息过长** | 一次性列全 2 题 + 三段式 + 编排序号，消息本身很长 | 协议第 5 节**禁止挤牙膏**是对的，但没说**长度上限**。本次单条评估约 900 字，学生的回应是「这个也算错？」，**说明他大概率没读完** |
| **摸底第 2 轮导师被迫处理超纲提问** | 摸底本该只定位起点，却被学生带进「面试会考吗」的路线讨论 | 摸底没有协议定义（见 4.2-④），导师没有挡这类提问的依据 |
| **L1-R2 Q4 越界出题，一轮把学生打崩** | 题意在逼边界，实际同时暴露 2 个高频错误 + 1 处笔误，反馈量爆炸 | 题目**性价比极高**，但**反馈量需要切分**。本次导师把「笔误代改」「越界错」「NPE 拆箱」三件事塞进同一条消息，学生的反应是「我就是照网上抄的」——**防御性回避**，说明信息过载 |

**共性结论**：协议对「一轮几题」有硬约束（1–3 题），但**对「一题能展开多少回合」没有约束**。真实的回合数是由**知识点的概念密度**决定的，不是由题数决定的。L2-R1 只有 2 题却打了 4 个回合，L1-R3 只有 1 题却干净利落地结束——**题数不是好用的节奏单位，回合数才是**。

### 4.4 该学科特有的教学法发现（值得固化到 `学科包/编程.md`）

**① 「改错题先问『这会改出什么编译错误』」（值得固化，本次验证有效）**

L2-R2 Q7，小陈提出 `private static final` 的建议。导师没有直接说「错」，而是先问「这句会让哪一行编译不过」——
这个动作把「口头建议」瞬间变成了「可验证的断言」，学生**立刻自己看到了矛盾**（`instance = new Singleton();` 和 `final` 冲突）。

**这比 Socratic 提问更快、比直接讲解更有效**，而且是编程学科独有的（其他学科的「错误建议」没有编译器来验证）。**建议写进 `编程.md` 第 5 节「验证方式」。**

**② 「同一错误第二次出现 → 不讲解，让他先写执行时间线」（值得固化）**

L1-R2 Q4（`i <= length`）和摸底 Q3 是同一个错的第二次；L2-R3 Q8（`volatile count++`）和 L2-R1 Q6 也是同一个错的第二次。
两次的**第一次**都用了「讲解 + 三段式」，但第二次（Q8）学生**照样写错**。

**说明：对复发错误，「再讲一遍」是无效的**（小陈 Q6 明明说得出「会出错」，Q8 还是写错——他缺的不是知识，是**提取路径**）。
本次导师在落档时给出的补救是「不讲课，先让他在空白文件上手写两条线程的执行时间线，不写 Java」——**这个动作值得固化**：把「写对的代码」降级为「先说对时序」，从输出侧反推。

**建议：在 `编程.md` 第 3 节旁新增一条「复发错误的处理协议」——同一错误第 2 次出现时，禁止重复讲解，必须换一种输出形式（说时序 / 画内存表 / 先预测输出再写代码）。**

**③ 「先预测输出，再写代码」对 `==`/`equals` 这类「判据型错误」特别有效（值得固化）**

L1-R1 Q1 是「说出 4 行的输出 + 为什么」。小陈答错②，但**①③④他要给理由**——这一步把「蒙对」和「会」区分开了。
如果只问「答案是什么」，小陈会答对 3/4 并通过；**正是「必须说理由」这个附加要求**才逼出了他的错误判据。

**建议写进 `编程.md` 第 5 节：给代码判断输出类题目，必须同时要求给出判断依据（「为什么」），只写结果不通过的判据不成立。**

**④ 「新知识点教完必须标一次适用边界」（值得固化的新做法）**

本次最大的教学事故是**知识负迁移**：小陈在 L1 学会「比较内容用 `equals`」，在 L2-R2 Q7 就把 `instance == null` 改成了 `equals(null)`——
**他的新知识没有边界，于是溢出了适用范围**。

导师事后补的一句（「`== null` 永远用 `==`；`equals` 只用于两个都有东西、比内容」）**来得太晚了**。
**建议：每教一个「X 应该用 Y」型知识点，收尾时必须加一句「Y 不适用于 Z」，并当场出一道对照题。** 这是编程学科特有的（其他学科的知识点负迁移没这么强的机械性）。

**⑤ 「面试相关性标注」值得固化为固定动作（本次效果显著）**

摸底第 2 轮导师现场答了「会考 / 是送分题里的坑 / 背结论没用」，并在 L2-R1 追问失控时**主动分层**「必须会 vs 知道就行」——
这两次学生的反应都是**立刻平静、专注度回升**。

**说明：对「目标明确为求职」的学生，『这个要学到什么程度』的答案本身就是教学的一部分。**
**建议：在 `编程.md` 第 5 节新增「面试分层标注」——每个知识点讲完，导师给一句 `面试层级：必会 / 会问 / 听过即可`。**

### 4.5 学生画像补充（真实的错误类型与困惑模式）

**A. 可追加到 `学科包/编程.md` 第 3 节「高频错误清单」的新类型**

| # | 新增错误类型 | 本次实例 | 为什么它比清单里现有的更危险 |
|---|---|---|---|
| 11 | **`volatile` 当原子用（`volatile int i; i++`）** | L2-R1 Q6、L2-R3 Q8 | **能编译、也能跑对**，测试 100 次可能 99 次过 → 漏判率极高 |
| 12 | **`map.get(k) + 1` 未判空导致自动拆箱 NPE** | L1-R2 Q4 | 面试高频，且是「照着网上抄」的典型受害者 |
| 13 | **用 `equals` 与 `null` 比较（`x.equals(null)`）** | L2-R2 Q7 | **这是「刚学的知识负迁移」**，不是原有知识错误——清单里没有这一类 |
| 14 | **DCL 单例缺 `volatile`** | L2-R2 Q7 | 面试手写题标配，且缺陷「看不见」 |
| 15 | **给 `final` 字段再赋值（建议改法时就犯）** | L2-R2 Q7 | 学生**没写代码、只是口头建议**时也会犯 → 说明错误在脑子里，不在键盘上 |

**B. 可以追加到学生画像（`协议/00-导师协议.md` 第 11 节）的困惑模式**

1. **「能跑就行」的真实含义不是懒，是「判据缺失」**：小陈能照抄代码并通过 IDE 运行，但他的判断标准是「不报红」。所以他对**能编译的语义错误完全无感**（`i <= length` 只有运行到才崩；`volatile count++` 连崩都不崩）。**这类学生的错误集中在「不报红但语义错」的象限**——导师的出题应该**优先打这个象限**。

2. **「只报结论不报原理」在编程学科有一个特殊变体：把「口诀」当原理**。小陈两次给出「volatile 是轻量版的 synchronized」——这是个**押韵的、可背诵的、且错误的**说法。他并不觉得自己在偷懒，他觉得自己「记住了」。**这类回答的危险在于它听起来像答案**——导师必须追问到「那你用它写一个线程安全的计数器」，口头复述**不足以判维度①通过**。

3. **挫败时的两种反应要分开处理**：
   - L1-R1「我是不是太笨了」→ **归因于自己**（需要「归因到知识、不归因到能力」，协议第 6.1 节已有，本次有效）；
   - L1-R2「我就是照着网上抄的」→ **归因于外部、防御性回避**（这是协议里**完全没有**的一种情绪模式，它伪装成解释而不是抱怨，导师需要识别并**把它翻译成一个教学要求**：「那你要能说出每行在防什么」）。

4. **学生会把「能复述」误当「会写」**：Q6 说得出、Q8 写错。**建议在画像里加一句：编程学科的学生，「说得出」与「写得对」的落差是常态，凡只通过口述通过的知识点，必须在下一轮以代码形式复验一次。**

5. **超纲提问是真实需求不是干扰**：小陈 3 个月内要上岸，他的每一个「这个会考吗」都是在做**时间预算决策**。忽略这个问题，学生的信任会掉；回答得太长，又变成路线讨论。**画像建议加一条：以求职为目标的学生，会持续用「面试相关性」评估导师的每条输出。**

> **本次仿真的总判断**：`编程.md` 在**「学生写了代码、代码有语法/算法错」**这个主场景下是好用的——三维口径清晰、笔误豁免与结构性错误的划分有真实价值（本次 L1-R2 Q4 那处全角分号，如果按「代码跑不起来」判就会误扣）。
> 但它在**两个方向上失灵**：
> ① **「能编译但语义错」的错误（并发、拆箱、判据型错误）没有归属**；
> ② **「学生没写代码、只说了话」的场景（改错题、口头建议、口头复述）没有评分口径**。
> 而这两类恰好就是**面试筛选真正在考的东西**——这也是本次仿真对项目最有价值的发现。
