# StepsToGreat learning workflow

> This overview connects existing procedures; it is not another authority for rules or learning state. Detailed criteria remain in the [tutor protocol](../协议/00_导师协议.en.md).
> 中文：[完整学习流程](./learning-workflow.md)

## From starting to mastery

Read personal rules and the handoff → resume existing work, or clarify needs using the incorporated grill-me approach → introduce a concrete situation and one easy question → conduct initial placement → establish the route → teach and practise in rounds → re-read original answers and assess → correct and re-assess → close the small goal → finalize the whole lesson → consolidate and resume by agreement.

Unresolved rounds must pass before advancing. Every new block starts conversationally; the same block does not need another introduction. Required Feynman or integrated closure belongs in the planned completion criteria. On a pause, save existing evidence without forcing the remaining steps.

## Stages, gates, and records

| Stage | Actions and gates | Records |
|---|---|---|
| Handoff and routing | Treat development as engineering. For tutoring read personal rules, 🚦, the teaching index, current round guide, and answers. Summarize the state in at most four lines. Do not restart onboarding for existing progress | Follow the handoff's evidence, not old chat |
| **Needs clarification: grill-me** | Inspect facts first. Establish subject, purpose, background, deadline, and realistic study time. Probe ambiguous goals and tradeoffs, recommend choices, and restate understanding for correction. Group independent gaps; defer dependent questions. Stop when needs are clear | Chat initially; 📋 when saved or formalized; route decisions in the course route |
| Conversational entry | Every new block starts with a concrete situation, task, obstacle, and **one current question**, followed by feedback on the actual answer. No feature menus or future question lists | Provisional observations with prompts, original answers, and hints; never mastery. Save by the entry protocol when requested |
| Initial placement | Select a subject pack. Adapt across foundation, application, and advanced probes: **2–8 total, 1–3 per round**, stopping when placement is clear. Reuse recorded diagnostic entry questions; identify hints and untested scope | Subject's `00-摸底测试.md`; 📋 and 🚦 |
| Route | Work backward from the goal for the first **3–5 lessons**, with prerequisites, module units, exit criteria, and required closure. Use an agreed provisional direction for undecided goals | `00-课程路线.md`; do not duplicate current-round state |
| Formal lesson | 1–3 questions per round, normally 2; fewer for new or costly questions. Usually 2–3 rounds per lesson. Continue an already introduced situation | `01_教学引导.md` is the index; create `第N轮_教学引导.md` for each round's complete explanation, examples, and prompts. Accumulate answers in `01_学生回答.md`. Update 🚦 and 📚 at issuance |
| Submission and assessment | Re-read current original answers and revisions after “done” or “fixed.” Append chat submissions unchanged before re-reading. Assess every current question together across independent conceptual, logical, and subject-specific formal dimensions | Append assessments; preserve history. Every applicable dimension must pass |
| Correction and re-assessment | Directly fix only a single local issue, explaining original → cause → change. Core concepts, reasoning, or multiple independent structural errors require student revision. Combine explanation of a shared cause while scoring dimensions honestly. Re-assess revised questions and identify carried-forward passes in the complete round table | Append revisions and an assessment for each submission. No next round while unresolved |
| Small-goal closure | All skills need evidence and all formal rounds in this block must pass. State “you can now…” and stop. Wait for “continue” even for a new block in the same lesson, unless continuous study is agreed | Synchronize the teaching index and answer top views; update only 🚦 if necessary, not 📊 prematurely |
| Whole-lesson closure | Revisit all rounds. Final assessment covers every question; explanations cover actual corrections and key principles. Mark mastery only after all applicable dimensions pass. Use explanatory placeholders for unpublished lessons | Final assessment and explanations in answers; update 🚦 / 📊 / ⏳ and keep 📚 accurate |
| Consolidation | After 3 newly mastered concepts, use one integrated review question; connect new and old concepts. Feynman diagnosis at major conceptual module closure, not pure operation; at most once per lesson, never consecutive rounds. Its round has only that question, assessing concepts only; honor refusal with ordinary questions | Answers and assessment in the owning document; deferred reviews or explanations in ⏳ |

## Where grill-me fits

The starting needs interview and optional decision discussions retain its questioning approach. See the existing [needs gathering and interrogation](./readme-details.en.md#needs-gathering-and-interrogation) explanation. This update names the connection in the entrypoints and [conversational entry §1](../协议/05_对话导入.en.md#1-when-to-use-it). This is an incorporated method, **not a requirement to install or invoke another skill**.

Needs clarification establishes what to learn and which tradeoffs to make. Placement determines the actual starting point. Practice and Feynman diagnosis establish learning evidence. Needs answers never establish mastery. Standalone decision interrogation is optional when requested; do not demand endless resolution before an already clear learning goal, or seek permission again for authorized work.

## Requirements across the workflow

- **Sources:** read/create `资料/索引.md`, locate and read full sections including exceptions, and cite file, section, and page/line where available. Without student material, use verifiable primary sources. Unreadable sources require reporting the gap and stopping; snippets are not evidence. Preserve original material.
- **Two progress layers:** module K/T derives from route-defined units and whole-lesson final assessments; the current checklist has 2–4 observable skills, or 1 for a tiny goal. Entry is provisional; prompted success does not tick independent skills. A complete checklist does not fill the module bar.
- **Changes only:** keep chat and the teaching-index/answer top views consistent; replace display snapshots only. Reuse graphics while K/T is unchanged. Ordinary re-assessment does not require rereading the full route, history, or state machine. Grade programming statically with paper traces unless execution is requested; engineering changes receive engineering checks.
- **Stuck or paused:** change perspective, then teaching method; after three unsuccessful explanations supply the answer and explain, checking paraphrase. Tutor-provided answers and paraphrase do not establish independent mastery; verify independently later. Record unresolved explanations for another session. File a pause without issuing more questions.
- **Preferences and switching:** save authorized lasting preferences in personal rules with a change record; tutoring does not edit framework files. Keep one current subject and active round. Close the round before switching, store other subjects in 📚 status, prefix lesson numbers with the subject, and use local re-placement before skipping.
- **Skill distribution:** maintain the handwritten `SKILL.md` separately; synchronize protocols from upstream. Standalone projects carry their local framework, while lightweight workspaces use the installed skill. Updates protect rules, profiles, answers, and material; never distribute developer learning data. Format, state, and regression checks do not establish real learner gains.
