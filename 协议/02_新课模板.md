# 02_新课模板（Lesson Template）

> 用途：每次发布新课，照本文件产出两个文件：`01_教学引导.md`（导师写）+ `01_学生回答.md`（镜像同题，学生作答 + 最终复评）。
> 英文版：[`02_新课模板.en.md`](./02_新课模板.en.md)

---

## 1. 两个文件的关系（唯一真相原则）

需求已明确后，每个新知识块先按 [`05_对话导入.md`](./05_对话导入.md) 做短场景/故事与一个小问题，再整理本块所需文档。已有课的后续块追加到原课，不每块创建新课或重做整体摸底。导入原答与提示可追加为「非正式评估」记录，正式轮次仍独立验证；首次正式发课前须完成摸底与路线，前一轮/课未通过不得导入下一块。

```
学科/<学科>/NN-<课名>/
├── 01_教学引导.md     ← 导师写：讲解 + 例题 + 题目（按轮次排布）
└── 01_学生回答.md     ← 学生写：镜像同题 + 空答案位 + 末尾两个占位区
```

- **回答文档 = 唯一学习证据**。是否掌握，以回答文档的「最终复评结果」为准。
- **不生成 HTML 副本**。需要交互练习时再按需生成，且生成物不算真相（Markdown 才是）。
- 回答文档末尾固定两个占位 H2：`## 最终复评结果`、`## 正确答案与解析` —— 评估完成后由导师填写。

## 2. 教学引导排版（必要内容优先）

两份文档标题后都放同一份双层视图，版式与更新依据见 [`06_小目标进度.md`](./06_小目标进度.md)：上层是模块名称及模块掌握进度条，下层是本次小目标与具体技能清单。模块条依据路线中的单元范围及正式掌握证据，与本次清单勾选数无关；技能项写实际能解释、操作或应用的内容，不写「完成任务 / 通过验证」。模块范围未知时显示待确定，不编造总数。模板见 `模板/教学引导模板.md` 与 `模板/学生回答模板.md`。

正文按「要解决的问题 → 方法与例子 → 必要的易错点 → 本轮练习」组织。新旧对比和知识关联有用才融入讲解，不强制八段、五条重点或固定数量的陷阱。不能因为精简而删掉关键原理、边界条件、可操作步骤或可核对来源。

```markdown
# <学科> | NN_教学引导

<!-- s2g-goal-view:start -->
## 模块：<所属模块名称>

<十格模块进度条> **<已掌握单元数>/<模块单元总数> 个知识单元已掌握**

## 本次小目标：<本块可验证的能力>

- [ ] <能说清的具体概念或方法含义>
- [ ] <能完成的具体步骤或操作>
- [ ] <能独立做到的具体应用>

> 当前一步：<眼前要做的事>。依据：<模块掌握证据与本次技能评估的短注>。
<!-- s2g-goal-view:end -->

## 要解决的问题
<一小段承接对话场景，说明实际问题和用途，不重复完整对话。>

## 方法与例子
<本块 1–2 个概念、关键原理和最小可运行/可操作的例子；引用紧跟相关内容。>

## 容易弄错的地方
<必要的 1–2 处，写明为什么错及如何避免；没有就删此节。>

## 本轮练习

### 第一轮

**问题 1**：<当前题面>
<本轮需要时再放问题 2 或 3；后续轮次通过后再追加。>
```

> **为什么按轮次排**：如果第 1 题就暴露概念错误，一次发 5 题会让后面几题**跟着全错**；
> 一轮一轮来，第 2 题就是在正确理解上做的。总题量不变，但每一题都在正确轨道上。

### 费曼轮怎么排（按需插入）

**不是每课都有费曼轮。** 判断依据见 [`00_导师协议.md`](./00_导师协议.md) 第 6.1 节。

| 情况 | 怎么排 |
|---|---|
| 本课有抽象/易混概念，且学生是初次接触 | 在**概念轮之后**插入一个费曼轮（**只出 1 题**） |
| 大模块收尾（如 OOP 学完、函数式学完） | **必做**一个费曼轮，覆盖整个模块 |
| 纯操作型内容（如「怎么导入模块」） | **不排**费曼轮 |
| 学生此前费曼表现好、且本课内容具体 | **不排**，或只在课末用一句「用一句话概括本课」轻量带过 |

**费曼轮的题面模板**：

```markdown
### 费曼轮 · 问题 N

**用你妈能听懂的话解释：<概念名>。**

规则：
- ❌ 不许出现这些词：<本课术语 1>、<本课术语 2>
- ✅ 可以打比方、举生活里的例子
- 3–5 句话说清即可

> 这不是考试。**讲不清很正常** —— 讲不清恰恰说明这里有洞，正好补。
```

> ⚠️ 费曼题**算 1 题**，且**该轮只出这 1 题**（它比普通题耗时得多）。

## 3. 出题纪律

| 项 | 规则 |
|---|---|
| **每轮题量** | **1–3 题**（默认 2 题；知识点全新或较难时出 1 题） |
| **一课总轮数** | 通常 2–3 轮（合计约 5 题）；可按学生目标调整，不固定 |
| **费曼题** | **算 1 题**，且该轮**只出这 1 题**；是否排见第 2 节的「费曼轮怎么排」 |
| **发下一轮的前提** | **本轮全 ✅**。本轮有 ⚠️/❌ → 先走完「讲解 → 代改/自改 → 复评」再发 |
| **变式** | 实操题与综合题必须在例题基础上**变化条件**（换数据、换约束、加边界），**不能与例题同构照抄** |
| **语言** | 用学生的语言出题 |
| **禁止** | 一次发出超过 3 题；把整课题目一次列全让学生自己做完；出「请复述第 3 节内容」这种考记忆的题；**把费曼题当普通题滥用**（见 6.1 的硬性下限与上限） |

## 4. 回答文档模板（**按轮次追加**，不是一次列全）

> ⚠️ **关键**：回答文档**初始只放第一轮的题目**。学生答完、评估通过后，
> 导师再**追加**下一轮的题目（只增不改，学生已写的部分原样保留）。
>
> 这样做的原因：文档里如果一次列全 5 题，学生等于看到了全部题目 —— 与「一轮 1–3 题」的设计相矛盾。

**第一轮（发课时写入）**：

````markdown
# <学科> | NN_学生回答

<!-- s2g-goal-view:start -->
## 模块：<所属模块名称>

<十格模块进度条> **<已掌握单元数>/<模块单元总数> 个知识单元已掌握**

## 本次小目标：<本块可验证的能力>

- [ ] <能说清的具体概念或方法含义>
- [ ] <能完成的具体步骤或操作>
- [ ] <能独立做到的具体应用>

> 当前一步：<眼前要做的事>。依据：<模块掌握证据与本次技能评估的短注>。
<!-- s2g-goal-view:end -->

## 第一轮

### 问题 1
<与教学引导完全一致的题面>

**我的回答**

<此处留空；文字直接写，代码题用带语言标识的空代码围栏。>
````

本轮按需追加问题 2 或 3。题面不缩写成可能丢条件的摘要，不替学生写答案。顶部显示区可按证据更新，学生原答及历史评估只增不改。

**第二轮（第一轮全 ✅ 后，追加）**：

````markdown
<与教学引导完全一致的题面>

<按题型留空作答位置；本轮需要时再追加问题 4。>
````

**第三轮（第二轮全 ✅ 后，追加）**：

````markdown
---

## 第三轮

### 问题 5
<与教学引导完全一致的题面>

**我的回答**

<按题型留空作答位置。>
````

**末尾（初始就放好，评估完成后由导师填）**：


## 5. 发布新课时对学生的输出模板

块开始时展示模块条与本次技能清单，再给场景和当前问题。学生提交后先给一句具体成果反馈，再展示已确认的新技能；有帮助就说明帮助，不凭夸奖打钩。普通修订只点出相关技能，不每条回复重贴全部视图。小目标完成明确说「你现在能……」，即使模块条没变化也完整收尾。已发目标或题目不重发，文件链接用一行即可；不重贴五条重点、规则承诺、复习提醒或任务板块，不让下一题淹没刚获得的成果。

```markdown
<针对原答的一句具体反馈：这次你独立做对的动作及它带来的结果；如有提示则如实说明。>

<技能改变或停点时展示与两份文档一致的模块进度与本次技能清单。>

<本次已完成就明确收尾；仍未完成则只给当前需要的一个小步骤，不追加另一块。>

<教学引导的可点击文件链接> · <学生回答的可点击文件链接>
```

## 6. 落档（发布新课那一刻）

| 要做的 | 位置 |
|---|---|
| 新建 `01_教学引导.md`（题目按轮次排布，但**只发第一轮**） | `学科/<学科>/NN-<课名>/` |
| 新建 `01_学生回答.md`（**只放第一轮题目** + 末尾两个占位区） | 同上 |
| 追加后续轮次题目 | 在回答文档里**追加**（只增不改） |
| 更新当前课次与进度 | `我的学习/00-学习档案.md` → 🚦 交接状态 |
| 追加课次映射 | 同上 → 📚 课次索引 |
