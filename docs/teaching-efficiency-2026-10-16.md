# 教学批改省时规则与隔离模拟（2026-10-16）

学生反馈：Java 练习一次批改约 7 分 31 秒，后续复评又约 3 分 18 秒，实际编译运行增加等待。此次改动的目标是减少不必要的文件读取、重复讲解、制图和实跑，同时保持逐题三维评估、原答保留与不提前推进。

## 改动口径

- 已发布轮次只重新读取本轮题面、原答和修订；一次评完本轮全部题。依据缺失或有争议时才查对应协议、资料或一手来源。整课最终复评再汇总历史。
- 编程题按题面静态检查类型、作用域、方法签名和关键行为，必要时纸面推演；默认不编译、不运行，也不把推演称作实测。学生明确要求实验时才实跑。
- 同一根因影响多维时，各维按观察结果如实评分，只合并解释与修订。单处局部笔误由导师代改并讲清；核心概念错或多处独立结构错误由学生在原轮修订，不靠导师写出答案就判掌握。
- 每次提交只追加一次评估，学生新修订另行追加复评；原答不覆盖。只在当前一步或技能变化时更新两份顶部视图；档案交接 🚦 失真才更新该区。模块数量不变就不重算、不新制进度图；课程路线不记录每轮状态。
- 小目标完成后给出具体成果并停下。下一新知识块或下一课等学生说「继续」，除非此前已约定连续学习。

## 测试方法

用两个隔离的 Java 学习文件夹，给真实导师 Agent 相同的「完成了」或「改好了」短消息。题面、课程交接、教学引导、学生资料索引与原答均在文件中；导师必须自己读、评、写、回复。前一组有两题：把 `Runnable` 误当可调用 `start()` 的对象，以及 Stream 代码里基本类型泛型实参与 Lambda 形参重名。后一组是学生修订线程题后复评，另一题已有正确答案与通过记录。旧版与新版均使用 DSH 的 `buddy` / `deepseek-v4.1-flash` 主池，沿用原推理配置；完整结果留在本机隔离目录和 DSH session/result 文件，未触碰真实 `E:\playground` 的学习记录。

## 验收边界

在迭代中，较早候选曾把确定的编译错误写成「待复评」，另一候选复评后自动发布新一轮，均已拒绝；历史记录自相矛盾的复评夹具也已废弃并重建。最终两组均核对了逐题三维、一次列全待改点、原答与修订保留、无编译调用、不把小目标通过当整课掌握、不自动发下一新块。最终复评模拟仍更新了 📊 行内的轮次备注，尽管状态没有升级为掌握；规则已明确中间轮次只应更新失真的 🚦，后续真实使用需继续观察这个多余写入。

隔离夹具保留了当前教学所需的题面、交接、资料和原答，但省略了旧课全文及完整 📋/📚 索引，因此不能用完整档案校验器的结果代表真实学习目录。模拟只能验证导师在这些输入下的操作；学生是否更愿意学、是否真正掌握，仍需后续实际使用观察。

Java 语义核对依据：[Runnable API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Runnable.html)、[Thread API](https://docs.oracle.com/en/java/javase/21/docs/api/java.base/java/lang/Thread.html)、[Java Language Specification：Type Arguments](https://docs.oracle.com/javase/specs/jls/se21/html/jls-4.html#jls-4.5.1)。
