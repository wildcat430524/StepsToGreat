# 03_落档事件表（Filing Event Table）

> 用途：**什么时候该写哪个文件**。除了这张表列出的写入，不要往档案里随手加状态。
> 核心纪律：**状态只在三处维护** —— 🚦 交接状态 / 📊 掌握表 / ⏳ 待办表。其他地方只引用，不复述。
> 英文版：[`03_落档事件表.en.md`](./03_落档事件表.en.md)

---

## 1. 事件 → 写入位置

| 事件 | 要写的位置 |
|---|---|
| **首次使用 / 需求收集** | `我的学习/00-学习档案.md` → 📋 学生信息 |
| **摸底测试完成** | 新建 `学科/<学科>/00-摸底测试.md`；`00-学习档案.md` → 📋 + 🚦 |
| **确定课程路线** | 新建 `学科/<学科>/00-课程路线.md`；`00-学习档案.md` → 🚦 |
| **发布新课** | 新建 `NN-<课名>/01_教学引导.md` + `01_学生回答.md`；`00-学习档案.md` → 🚦 + 📚 课次索引 |
| **学生提交 / 评估未通过** | `01_学生回答.md` 评估区；必要时 `00-学习档案.md` → ⏳ 待办 |
| **复评通过** | `01_学生回答.md` →「最终复评结果」（日期 + 逐题三维表 + 结论）+「正确答案与解析」（三段式）；`00-学习档案.md` → 📊 掌握表 + 🚦 交接状态 + ⏳ 待办 |
| **课程顺序变化** | 只改 `学科/<学科>/00-课程路线.md`，其他地方引用它 |
| **间隔复习 / 费曼讲解完成** | `00-学习档案.md` → ⏳ 待办（状态）+ 🕰 更新日志 |
| **学生换学科** | 新建 `学科/<新学科>/` 整套；`00-学习档案.md` → 📋 + 🚦 |
| **学生要求重测 / 跳课** | 更新 `00-摸底测试.md`（只增不改，追加新结论）；`00-学习档案.md` → 🚦 |

---

## 2. 三处状态的分工（不许互相重复）

| 位置 | 只回答什么 | 不写什么 |
|---|---|---|
| **🚦 当前交接状态** | **现在这一课**是什么、进度到哪、接手第一步 | 不写长期状态、不写历史 |
| **📊 掌握表** | 每个知识点**算不算真掌握**（含评估日期与证据入口） | 不写「正在学」的过程 |
| **⏳ 待办表** | **挂起**的复评 / 复习 / 费曼 | 不重复「当前正在上的课」 |

> 反例（真实发生过的错）：同一进度在 5 个区各写一遍 → 接手时不敢确定哪份是准的。

---

## 3. 编辑纪律

1. **改任何文件前必须先读该文件**（多数工具未读先改会报错）。
2. 改完读关键段落核对。
3. 要写日期用本地日期命令（Windows：`Get-Date -Format 'yyyy-MM-dd'`）。
4. **学生历史回答只增不改**：新增评估结论区，不覆盖学生原答案与历史评估。
5. **回答文档的最终复评优先于教学文档里的历史勾选**。冲突时以回答文档为准。
6. 路径用相对链接，保证在 Obsidian / VS Code / Trae 里都能点开。

---

## 4. 文档状态优先级（冲突时按这个判）

```
1. 学生回答文档的「最终复评结果」   ← 最高
2. 学习档案的 📊 掌握表
3. 教学文档里的历史勾选
4. 聊天记录里的口头结论             ← 最低，不作为依据
```

---

## 5. 复评通过时的标准写法（照抄格式）

在 `01_学生回答.md` 末尾：

```markdown
## 最终复评结果

**复评日期**：YYYY-MM-DD

| 题号 | 概念理解 | 逻辑正确 | 规范表达 | 结论 |
|------|----------|----------|----------|------|
| 1 | ✅ | — 不适用 | — 不适用 | 通过 |
| 2 | ✅ | ✅ | — 不适用 | 通过 |
| 3 | ✅ | ✅ | ✅ | 通过 |
| 4 | ✅ | ✅ | ✅ | 通过 |
| 5 | ✅ | ✅ | ✅ | 通过 |

**最终结论**：<课名> 已掌握。首次评估发现 N 处问题（<一句话概括>），
经导师代改 / 学生自改并重新读取确认，现全部通过。

---

## 正确答案与解析

### 问题 3 修正点
**你的原答案**：<原代码/原文>
**问题在哪里**：<为什么错 + 会导致什么后果>
**正确写法**：<改后内容>

### 问题 5 修正点
（同上三段式）

### 核心要点回顾
- <要点 1>
- <要点 2>
- <要点 3>
```

> 维度名按 `学科包/<学科>.md` 里的定义替换（编程 = 语法可编译；英语 = 表达规范；等等）。

## 6. 学习档案的标准写法

**🚦 交接状态**（只写当前这一课）：

```markdown
| 项目 | 当前状态 |
|------|----------|
| **当前学科** | <学科名> |
| **当前课次** | #NN <课名> |
| **最近完成** | #NN-1 <上一课名> |
| **教学文档** | `<路径>` |
| **回答文档** | `<路径>` |
| **当前进度** | <教学已发布，回答文档为空，等待学生作答> |
| **接手后的第一步** | <具体动作> |
| **推进条件** | <三维全通过后进入下一课> |
```

**📊 掌握表**：

```markdown
| 知识点 | 状态 | 评估日期 | 备注 |
|--------|------|----------|------|
| <知识点> | ✅ 已掌握 | YYYY-MM-DD | <一句证据> |
| <知识点> | ⚠️ 部分掌握 | YYYY-MM-DD | <缺什么> |
| <知识点> | ⏳ 待作答 | YYYY-MM-DD | <文档已建，答案为空> |
```

**⏳ 待办表**：

```markdown
| 事项 | 触发条件 | 安排 | 证据入口 | 状态 |
|------|----------|------|----------|------|
| <事项> | <为什么挂起> | <什么时候做> | `<路径>` | ⚠️ 挂起（不阻塞主线） |
```
