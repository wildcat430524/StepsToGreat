# 真实导师运行与模拟学生测试（2026-09-30）

文件夹版和技能版都完成了已有第一课的三轮学习闭环，并从新会话中恢复了当前轮次。但首次反馈有错误论证，技能版状态校验器还存在可以独立复现的漏检。不能据此宣称整体通过率或真实学习效果。

## 测试方法

- 两个隔离工作区，主题相同：Python 列表别名、嵌套列表浅拷贝、替换外层槽位与空列表。
- 导师通过 DSH 真实执行，provider 为 `buddy`，model 为 `deepseek-v4.1-flash`，未显式指定 reasoning effort。每个版本两个会话、五次导师反馈，共四个会话、十次反馈。
- 学生答案和质疑由测试维护者单独写入；导师不能扮演学生，不能读取测试控制器或旧导师回复。第二轮另开新会话，只以学生消息「完成了」触发评估，测试文件交接。
- 第一轮两题，其中一题正确，一题把浅拷贝误认为逐层独立复制；维护者质疑导师的错误论证，再提交正确订正。第二轮由导师出两道操作题，维护者提交正确概念与输出，并故意漏一个右括号。第三轮单独回答费曼题，要求当天停止、不发布下一课。
- 初始状态是维护者预置的已有课程，**没有测试首次需求收集、摸底和自动规划**。第二、三轮题目由各导师实际生成，不是完全相同的固定题面。
- 教学材料由维护者编写，依据 [Python Tutorial：Lists](https://docs.python.org/3.13/tutorial/introduction.html#lists) 与 [Names and Objects](https://docs.python.org/3/tutorial/classes.html#a-word-about-names-and-objects) 核对；固定例子另用 Python 3.11.9 实跑。没有把模型生成的任意代码交给维护者脚本执行。

## 优先处理的问题

### 1. 技能版会把活跃档案判为空模板

技能版 `scripts/validate-state.mjs` 的 `parseProfile` 使用 `BLANK_MARKERS.some(m => text.includes(m))`。掌握表保留「（尚未开始）」时，即使已经有学科、当前课次和有效的交接状态，也会跳过后续检查。

独立反例：给这份活跃档案写入不存在的回答路径，文件夹版报 I3 并以 1 退出；技能版返回 BLANK、无问题、以 0 退出。最终学习完成后占位词消失，两版才都返回 PASSED，所以只测课末会漏掉这个问题。

建议先修正空模板识别，再增加「活跃档案保留未掌握占位 + 回答文件不存在」的回归用例。技能版校验器属于同步脚本保留的独占文件，普通上游同步不会自动修正它。此次测试保留了缺陷与反例，没有修改被测校验器。

### 2. 导师知道正确结论，但初次纠错理由不准确

学生假定内层也独立复制，据此预测原列表不变；这在该错误前提下是自洽的。两个导师都把它描述成「互相矛盾」，评估表还同时标两个 ❌，与不重复计分的文字说明冲突。受到学生质疑后，两者才撤回论证并明确只有一处概念错误。

建议把「前提错但推导自洽」加入行为回归，并单独审查初次反馈的解释质量。最终答对、能够认错，不能替代首次反馈准确。

### 3. 技能版题目入口不同步

技能版把第二轮、第三轮题目追加到回答文档，教学引导仍停在第一轮。冷启动仍成功，但学生打开教学引导时看不到当前练习。这是可用性风险，建议明确题目唯一入口或同步教学引导；本报告没有把它算成概念评估失败。

四份最终工具轨迹合计 194 次工具调用，十次导师反馈均有成功读取回答文件的记录，且发生在第一次直接文件编辑之前。此统计只覆盖直接文件工具；不据此声称穷尽了 shell 内部读写。新会话的轨迹未发现读取旧导师回复文件的调用。

真实工作区的 `我的学习/我的规则.md`、`我的学习/00-学习档案.md` 与 `AGENTS.md` 的哈希均未变化。测试先在仓库内运行，结束后归档到仓库外，避免复制的框架和故意损坏的夹具影响项目链接检查。原始会话返回及工具轨迹保留运行时路径，没有改写历史证据。

技能版 `before-01` 快照取得偏晚，不能冒充运行前快照；初始答案采用生成时记录的种子哈希与 `seed-answer.md` 核对，初始档案来自文件夹版的运行前快照。学生后续提交按标签插入文档，不保证段落按提交时间排列，时间顺序应看阶段快照和会话记录。

模拟工作区只复制必要框架，未复制英文文件、教程等全部依赖，因此导师在其中运行全量 Markdown 检查时出现的缺链不能当作原项目缺陷。最终课程状态已由维护者另行校验。

这是一条受控学习路径、一个学科和一个导师模型的行为测试。它不证明真实学生的学习增益，也没有覆盖首次使用、多学科切换、不可读资料、连续错误升级、长期复习或更多模型。

## 复现准备与审计

准备脚本在主项目 `evals/learning-simulation/`；技能包里的本文是报告镜像，完整复现需检出主项目及同级技能项目。工具默认将夹具放在仓库外，已有目录会拒绝覆盖。

```powershell
node evals/learning-simulation/setup.mjs E:/s2g-learning-simulations/new-run
node evals/learning-simulation/snapshot.mjs E:/s2g-learning-simulations/new-run/folder E:/s2g-learning-simulations/new-run/folder-before-01.json
node evals/learning-simulation/snapshot.mjs E:/s2g-learning-simulations/new-run/skill E:/s2g-learning-simulations/new-run/skill-before-01.json
python evals/learning-simulation/truth.py
node evals/learning-simulation/probe-validator.mjs E:/s2g-learning-simulations/new-run
node evals/learning-simulation/audit.mjs E:/s2g-learning-simulations/new-run baseline
```

这几条命令只准备夹具、执行固定例子和校验；**不会自动调用导师或生成模型成绩**。真实重跑时应按上述五次反馈顺序调用导师，维护者单独提交学生答案，每次前后保存快照。换新会话时不提供旧聊天或旧回复文件。工具轨迹提取脚本需要支持内置 Zstandard 的 Node（本次为 Node 24.15.0）；普通准备与审计脚本不依赖该功能。

本次另外在新目录实际执行了准备、两份初始快照、反例注入及基线审计，重新得到相同的漏检结果。主项目 Markdown 检查通过（109 个文件），行为评估工具的 34 个测试通过；技能版自检通过（97 个文件），两个仓库的 `git diff --check` 通过。这些是工程检查结果，与上面的真实导师表现分别报告。
