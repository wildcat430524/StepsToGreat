# 我的规则（My Rules）

> **这是你的规则文件，优先级最高。**
> 导师每次接手会**先读这里**，再读框架默认规则（`协议/00_导师协议.md`）。
> **这里写的任何一条，都会覆盖框架默认。**
>
> 你可以：改任何一条、删掉不要的、加自己的、写自己的教学偏好。
> 不知道怎么写？直接跟导师说「我要改成 X」，它会帮你写进这个文件。
> English version: [`我的规则.en.md`](./我的规则.en.md)

---

## 怎么用

**这个文件初始是空的（全是注释）—— 空的就意味着「完全用框架默认规则」，一切正常。**

想改哪条，就**把那一行前面的 `<!--` 和 `-->` 去掉**（取消注释），改成你要的值。

三种方式，任选：

| 方式 | 怎么做 |
|---|---|
| **直接改** | 编辑本文件，取消注释并修改 |
| **口头说** | 对导师说「以后出题一次只出 1 题」→ 它帮你写进本文件 |
| **不改** | 保持全注释 = 完全用框架默认规则 |

**取消注释的例子**：

```markdown
<!-- 改之前：这行是注释，不生效 -->
<!-- - 每轮出题：2 题 -->

<!-- 改之后：生效了，覆盖框架默认 -->
- 每轮出题：1 题
```

## 优先级说明（给导师看）

**规则优先级从高到低**：

```
1. 本文件（我的规则.md）          ← 最高，覆盖下面所有
2. 学生当场说的话                  ← 覆盖第 3 条以下
3. 我的学习/00-学习档案.md 🚦      ← 当前进度（状态，不是规则）
4. 协议/00_导师协议.md             ← 框架默认规则
5. 学科包/<学科>.md                ← 该学科的评估口径
6. AGENTS.md 的其余部分            ← 框架入口
```

**冲突时**：按上面的顺序，上面的赢。
**本文件没写的**：用框架默认。
**本文件写了的**：以本文件为准，即使和框架默认相反。

> **唯一例外**：如果你在本文件里写了**自相矛盾**的两条，导师应该**问你要哪一条**，而不是自己猜。

## 给导师的操作说明

| 情况 | 怎么做 |
|---|---|
| 学生说「以后改成 X」 | 把 X 写进本文件（**不要改 `协议/`** —— 那是只读框架） |
| 学生说「我不喜欢 Y」 | 同上，写成一条明确的规则 |
| 本文件是空的 | 一切按框架默认，**不要主动往里写东西** |
| 发现两条规则矛盾 | **问学生要哪一条**，不要自己选 |
| 想建议一条规则 | 可以提议，但**要学生同意**才写进去 |
