# 框架升级与档案迁移（UPGRADE）

> **谁会用到这篇**：把你的 StepsToGreat 文件夹更新到新版本的人（通常是 `git pull`），或要迁移旧档案的人。
> **学生不需要读本文** —— 升级由你自己或帮你维护的人做，学习本身不受影响。
>
> 当前协议版本：**1**（版本号写在 `我的学习/00-学习档案.md` 的「协议版本」行）

---

## 1. 为什么需要版本握手

框架是不断改进的：新的不变式（I11、I12…）、新的学科包、新的落档规则。
但**学习档案是学生攒了几个月的资产**，不能因为框架升级就作废。

所以协议里放了一行版本号，`validate-state.mjs` 接手时会做三件事：

| 档案版本 | 工具版本 | 判定 | 退出码 |
|---|---|---|---|
| 相同 | 1 | ✅ 正常校验 | 依结果 |
| **低于**工具 | 1 < 2 | ⚠️ 提示「需要迁移」，**仍照常校验**（旧档案不会被判死） | 依结果 |
| **高于**工具 | 2 > 1 | ❌ **报错 I12** —— 拒绝用旧口径校验新档案 | `1` |
| 未声明 | — | ℹ️ 提示，视为当前版本 | 依结果 |

> **为什么「高于」必须报错**：工具不认识新协议的规则，如果它还是输出「✅ 通过」，
> 那就是**假的安全感** —— 比明确报错危险得多。宁可让你先更新工具。

## 2. 升级前：先备份（30 秒）

**这一步不能省。** 迁移只做「只增不改」的改动，但任何自动化都可能遇到意外。

```powershell
# Windows：把数据目录复制成带日期的备份
Copy-Item -Recurse "我的学习" "我的学习.bak-$(Get-Date -Format yyyyMMdd)"
Copy-Item -Recurse "资料" "资料.bak-$(Get-Date -Format yyyyMMdd)"
```

```bash
# macOS / Linux
cp -r 我的学习 "我的学习.bak-$(date +%Y%m%d)"
cp -r 资料 "资料.bak-$(date +%Y%m%d)"
```

> 💡 更省事的做法：把整个 `StepsToGreat` 文件夹复制一份再升级。

## 3. 升级步骤

```bash
cd StepsToGreat
git pull                       # 1. 拉取框架更新（协议 / 学科包 / 模板 / _tools）

node _tools/setup-agents.mjs   # 2. 重新生成跳板文件（工具名单可能有变）
node _tools/validate-state.mjs # 3. 按新口径校验你的档案
```

第 3 步的输出决定接下来做什么：

| 输出 | 含义 | 怎么办 |
|---|---|---|
| `✅ 状态自洽` | 档案已兼容新版本 | 把「协议版本」行更新为新版本号，完事 |
| `⚠️ 档案协议版本 1 低于当前 2` | 档案需要迁移 | 按下面第 4 节逐条做 |
| `❌ [I12] 档案协议版本高于本工具` | 你的工具太旧 | `git pull` 更新 `_tools/` 再来 |
| `❌ [I6]/[I7]/[I8]…` | 档案里有本来就存在的问题 | 见第 4 节 |

## 4. 迁移纪律：只增不改

| 允许 | 禁止 |
|---|---|
| 补上缺失的**新结构**（如新增的「协议版本」行） | 改写学生已有的答案、错因、复评结论 |
| 把新规则要求的**证据**补齐（如给已掌握的课补全复评表） | 为了过校验而**编造**评估日期或结论 |
| 在更新日志里**记录**做了什么 | 删除学生的历史记录 |

> **核心判据**：迁移只处理「结构」，不触碰「事实」。
> 如果某项证据**确实缺失**（早期版本没要求逐题三维表），正确做法是**标注为待补**并告诉学生，
> 而不是替他编一个日期。

## 5. 版本历史与迁移要点

### v1（2026-09）— 首版带版本号的协议

**为什么这次要有版本号**：之前的档案没有任何版本标记，框架升级后**没有任何机制回答**：
「这份攒了三个月的档案按哪一版协议写的？现在这版校验器能放心地说『通过』吗？」

于是 v1 引入两样东西：档案 📋 里的 `**协议版本** | 1` 一行，以及不变式 **I12** 的版本握手。

#### 这一版收紧的判定（旧档案可能因此报错）

| 不变式 | 从前的宽松口径 | 现在的口径 | 旧档案可能报错的原因 |
|---|---|---|---|
| **I2** | 只要文本里出现「尚未开始」就当空模板 | 必须 🚦 / 📊 / 📚 **三处都未填**才算空模板 | 反过来了：以前是**漏检**（静默跳过全部检查），现在是真的开始检查 |
| **I6** | 复评区有「最终结论」字样就算填了 | 必须有真实日期 + 非空话结论 + **逐题三维表** | 早期课的复评区只有一句话，缺逐题表 |
| **I7** | 找不到表格行时默认「没有失败」 | 空表 / 空格子 / 非 ✅ 一律算不通过 | 复评表里留了空格子 |
| **I8** | 日期只验格式 | 日期必须**日历上真实存在** | 写了 `2026-02-31` 这类手滑 |
| **I10** | 只有同时写了教学文档和回答文档才算重复 | 写一个路径、或只写课次/课名也算重复（复习语义豁免） | 待办表里混进了当前课 |
| **I12** | 无 | 版本握手 | 档案没写「协议版本」行（只给提示，不阻塞） |

#### 旧档案迁移：三档处理

| 情况 | 怎么办 |
|---|---|
| 档案没写「协议版本」 | 在 📋 学生信息加一行 `\| **协议版本** \| 1 \|`（提示级，不影响通过） |
| I6/I7 报错（复评区不完整） | **先判断是不是真的缺证据**：若该课确实通过了，让学生重跑一次复评补表；若证据真的缺失 → **如实**把 📊 状态改回对应状态，**不要编日期和结论** |
| I8 报错（日期非法） | 找学生确认真实日期，改对 |
| I10 报错（待办重复当前课） | 删掉那一行（状态只留在 🚦） |
| 不想现在迁移 | 也**可以**：版本低于工具只给 `warning`，不阻塞。想清楚再动 |

## 6. 关于 `git pull` 冲突（非技术用户必读）

**大部分文件不会被覆盖**：`我的学习/` 和 `资料/` 都在 `.gitignore` 里，框架更新碰不到它们。

**有两个例外**（它们是被跟踪的起始文件）：

| 文件 | 你改过它 | `git pull` 时 |
|---|---|---|
| `我的学习/00-学习档案.md` | 几乎一定改过（要记进度） | **可能冲突一次** |
| `我的学习/我的规则.md` | 改过规则的话 | **可能冲突一次** |

**遇到冲突怎么办**（最省事的办法）：

1. 不要慌，**你的内容不会丢** —— git 会把两份都留在文件里，用 `<<<<<<<` 标出。
2. 最简单的做法：**保留你的那一份**，框架那几行改动下次再说。
3. 或者：备份后重新 `git clone` 一份干净版本，再把 `我的学习/` 和 `资料/` 拷过去。

> ⚠️ README 里「`git pull` 不会覆盖你的学习记录」这句话应当理解为
> **「你的数据目录不会被框架更新覆盖」**；这两个起始文件属于已知例外（见
> [`adr/0004-framework-data-separation.md`](./adr/0004-framework-data-separation.md) 的「已知取舍」）。

2. 同步 [`../协议/04_状态机.md`](../协议/04_状态机.md) 顶部「当前协议版本」（中英两版）

5. 给每条新的收紧口径**加一个回归用例**（`tests/fixtures/NN-.../`）
6. 跑 `npm run verify:ci` —— 中英不一致、版本号不一致、不变式条数不一致都会被自动拦下
