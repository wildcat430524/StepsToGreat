# 0003 · 三维评估，维度 ③ 随学科变化

- **状态**：已接受
- **日期**：2026-09-21
- **决策者**：项目发起人

---

## 背景

源项目（Java 基础自学系统，跑了 22 课）用的评估口径是固定的三维：

```
概念理解 / 逻辑正确 / 语法可编译
```

这个口径在 Java 上验证有效，但**「语法可编译」是编程专属**：

- 学英语的人没有「可编译」这回事
- 学历史的人判什么？
- 学健身的人判什么？

本项目要通用（编程 + 文理科 + 考试），固定三维做不到。

---

## 决策

**保留「三个独立维度、全 ✅ 才推进」的机制；维度 ③ 的名称与判据由学科包定义。**

| 学科 | 维度 ③ 名称 | 判什么 |
|---|---|---|
| 编程 | 语法可编译 | 代码结构性正确、能跑 |
| 语言 | 表达规范 | 语法、时态、搭配、拼写结构 |
| 文科 | 表述规范 | 论证结构、术语、引用规范 |
| 理科 | 推导规范 | 符号、步骤、量纲、逻辑链 |
| 考试 | 答题规范 | 题型格式、得分点覆盖、时间分配 |

维度 ①② 保持通用：**① 概念理解 / ② 逻辑正确**。

学科包放 `学科包/<学科>.md`；无对口包时由导师照 `_自定义学科包模板.md` 现场生成。

---

## 理由

| 理由 | 说明 |
|---|---|
| **机制不变，口径可变** | 「全 ✅ 才推进」是核心资产；变的只是第三个维度怎么判 |
| **强制保留第三维度** | 不许因为「不好量化」就跳过 —— 换名字也要有（如「姿势规范」「表达清晰度」） |
| **可扩展** | 加学科只需加一个 md 文件，不改协议 |
| **可解释** | 学生能看懂「为什么我这题被扣分」 |

---

## 为什么必须三维独立（不能合并打分）

| 只保留的维度 | 会漏掉什么 |
|---|---|
| 只有概念 | 学生能说不会做 |
| 只有逻辑 | 学生做对了但说不清为什么，遇到变形就废 |
| 只有规范 | 学生写得漂亮但理解错，换场景就错 |
| 合并成「综合分」 | 80 分不知道是「懂了但写错」还是「没懂但蒙对」→ 无法决定下一步 |

**独立评分的价值**：区分「懂了但手滑」与「没懂」—— 前者代改即可，后者必须重教。这是「小问题代改 / 大问题引导」这条分叉的**判据基础**。

---

## 备选方案与为何否决

| 方案 | 否决理由 |
|---|---|
| 固定三维不变 | 非编程学科无法适用 |
| 让 AI 每次现场决定维度 | 同一学科不同会话口径不一致 → 学生困惑、进度不可比 |
| 每个学科完全自定义（连 ①② 也换） | 失去跨学科的可比性；且 ①② 在绝大多数学科都成立 |
| 用单一「掌握度百分比」 | 无法区分「懂但手滑」与「没懂」，破坏代改分叉 |

---

## 影响

- `协议/00_导师协议.md` 第 3 节明确写「维度 ③ 的名称与判据取自学科包」
- `学科包/README.md` 提供**决策树**帮导师选包
- `_自定义学科包模板.md` 要求填「什么是结构性错误 / 什么是手滑」—— 这是生成新学科包的**关键两问**
- 学习档案的 📋 学生信息里必须记录**用了哪个学科包**，避免换会话时口径漂移
