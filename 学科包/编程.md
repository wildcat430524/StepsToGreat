## 1. 三维定义

| 维度 | 名称 | 判什么 | 典型 ✅ 的样子 |
|---|---|---|---|
| ① | **概念理解** | 知道这个东西是什么、为什么存在、什么时候用 | 能说清「封装 = 隐藏细节 + 控制访问」，而不是只会背 `private` |
| ② | **逻辑正确** | 算法/流程/边界/数据结构选择对，能得到正确结果 | 求和循环 `i < arr.length` 边界对；选 HashMap 而不是 ArrayList 做计数 |
| ③ | **语法可编译** | 代码**结构性**正确，能在 IDE / 解释器里跑起来 | 类与方法的嵌套层级对、保留字用法对、`return` 配返回类型 |

## 2. 维度 ③ 的判据（严格区分「结构性错误」与「手滑」）

### ❌ 必须扣分的结构性错误

- `main` 方法写在类外面
- 类里嵌套定义另一个 `public class`（顶层类规则）
- 把保留字（`class`、`int`、`for`…）当变量名
- 方法签名错：`void` 方法却 `return 值`；有返回类型却不 `return`
- 调用不存在的成员 / 参数个数与签名不符
- 缺少必需的导入且**不是**「学生注明省略」的情况
- 循环条件导致必死循环或必不执行（**逻辑与语法双杀**）
- 变量在使用前未声明 / 类型不匹配（如 `String` 赋给 `int`）

### ⚠️ 可豁免笔误（不扣分、不逐处改）

- 全角符号：`；` `（）` `‘’` `“”`、中英文标点混用
- 漏分号、多余空格（如 `System.out .println`）
- 大小写 / 拼写笔误：`ArryList`、`printlin`、`string`（在明显是笔误时）
- 缺 `import`、缺 `class` 外壳、省略 `main`（**学生注明「省略」的**）
- 代码围栏标错语言（```python 写了 Java）——这是 Markdown 问题不是代码问题

## 3. 该学科高频错误清单（评估时重点盯）

1. `for` 循环用逗号当分隔符（`for (int i = 0, i < n, i++)`）
2. 缺右大括号 / 括号不配对
3. 构造方法写成 `public void Car(...)`（多了 `void`）
4. 字段已初始化，掩盖了构造方法没写的问题
5. `static main` 里直接调用非静态方法
6. 成员内部类创建漏 `outer.new Inner()`
7. 用 `==` 比较 `String` / 对象内容（应为 `.equals()`）
8. 数组越界：`i <= arr.length`
9. 修改集合时遍历它（`ConcurrentModificationException`）
10. 变量作用域外引用（在 `if` 块里声明、块外使用）

> 每次发现新错误类型，追加到这里（**只增不改**）——这份清单越用越准。

## 4. 出题形态（怎么出题才有意义）

| 轮次 | 题型 | 要点 |
|---|---|---|
| 第一轮 | **概念题**（1–2 题） | 问「为什么」而不是「是什么」：如「为什么 `String` 不可变？」 |
| 第二轮 | **写代码**（2 题） | 必须**变化条件**（换数据、换约束、加边界），不能照抄例题 |
| 第三轮 | **综合题**（1 题） | 结合前面多个知识点做一个小功能 |

> **每轮只发 1–3 题，本轮全 ✅ 才发下一轮**（见 `协议/00_导师协议.md` 第 2 节）。
> 不要一次把三轮题目全发出去。

**好的代码题特征**：
- 有明确的输入输出（可验证）
- 藏一个边界条件（空数组、0、负数、重复值）
- 用得上本课知识点，但不需要未学的知识

**禁止**：
- ❌ 出「请复述第 3 节内容」
- ❌ 出需要未学知识才能做的题
- ❌ 出没有明确对错的题（如「你怎么看 X 语言」）

## 5. 验证方式（怎么确认学生真会了）

1. **能跑**：让学生说明这段代码运行结果是什么（不用真跑，但要说得出）
2. **换场景**：把条件换掉，问「如果改成 X，你的代码还能用吗？为什么？」
3. **追边界**：问「如果输入是空 / 0 / 超长，会怎样？」
4. **解释**：让学生用自己的话讲这段代码在做什么
5. **改错**：给一段有 bug 的代码，让他找出来

> 「能背出语法」不算掌握；**「换个场景还能写对」才算**。

### 费曼法在编程里怎么用

| 值得费曼的知识点 | 不值得（别浪费时间） |
|---|---|
| 抽象机制：闭包、引用传递、多态、递归 | 语法细节：`for` 怎么写、`import` 放哪 |
| 设计理由：「为什么需要接口」「为什么 String 不可变」 | 具体 API 的参数顺序 |
| 易混概念：`==` vs `equals`、值传递 vs 引用传递 | 某函数的返回值是什么 |
| 架构思想：为什么分层、什么是依赖注入 | 环境配置步骤 |

**编程费曼题的特别约束**：

- ❌ **禁止在解释里出现代码**（「不许写代码，用话说」）—— 否则学生直接贴代码，测不出理解
- ✅ 允许用生活类比（「闭包像一个随身带的背包」）
- ✅ 追问式费曼：「你用背包类比闭包 —— 那背包里能放什么？什么时候背包会被扔掉？」

**典型问法**：

```
不许写代码、不许说这些词：<作用域>、<引用>、<闭包>

用你妈能听懂的话解释：为什么这个函数「记住」了外面的变量？
```

```markdown
