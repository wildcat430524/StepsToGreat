## 4. 本学科发现的优化点

### 4.1 学科包缺陷（`学科包/编程.md` 没覆盖到的情况）

**⭐ 核心缺陷：维度③「语法可编译」对动态语言的判据是空的。**

> **本节的缺陷 → 第 5 节建议编号对照**：A/B/C → #1 #2；D → #3；E → #4；出题形态 → #5；费曼禁用词 → #16；表述纪律 → #17；教具 → #18。

`编程.md` 第 1/2 节整体是为**强类型可编译语言（Java）**写的，逐条核对如下（**不夸大，只算真专属的**）：

**第 2 节「❌ 必须扣分的结构性错误」共 8 条 → 3 条纯 Java 专属 + 2 条只在 Java 语境下成立的表述：**

| 条目 | 对 JS 是否成立 |
|---|---|
| `main` 方法写在类外面 | ❌ 不适用（JS 无 main/类外壳要求） |
| 类里嵌套定义另一个 `public class` | ❌ 不适用 |
| 把保留字当变量名 | ✅ 通用（JS 也是 SyntaxError） |
| 方法签名错：`void` 却 `return 值` | ❌ 不适用（JS 函数无签名返回类型） |
| 调用不存在的成员 / 参数个数不符 | ✅ 通用（但 JS 里参数个数不符**不报错**，只是 `undefined` —— 判据要改写） |
| 缺少必需的导入 | ⚠️ 表述是 Java 的（JS 用 `import`/打包器，且未定义变量在非严格下**静默变全局**） |
| 循环条件导致必死循环 | ✅ 通用 |
| 变量未声明 / 类型不匹配（`String` 赋 `int`） | ⚠️ 前半通用、后半 ❌（JS 无类型检查，`"a" + 1` 合法） |

**第 3 节「高频错误清单」共 10 条 → 5 条纯 Java 专属：** ③ 构造方法多写 `void`、④ 字段初始化掩盖构造方法、⑤ `static main` 调非静态方法、⑥ 成员内部类 `outer.new Inner()`、⑨ `ConcurrentModificationException`。
另 ② 缺右大括号（通用）、⑦ `==` 比较 `String`（JS 对应物是 `==` vs `===`，判据要换）、⑧ `i <= arr.length`（JS 里不抛异常，只读到 `undefined`，**比 Java 更隐蔽**）、⑩ 变量作用域外引用（JS 里 `var` 有提升、`let` 有 TDZ，是三个不同的坑）。

**结论：两节合计 18 条判据里，8 条对 JS 完全不适用，5 条表述需改写 —— 真正能直接拿来判 JS 的不到 5 条。**

**第 1 节维度③ 名为「语法可编译」，定义是「能在 IDE / 解释器里跑起来」** —— 对 JS，「解释器里跑起来」这句话本身就在骗人：`this` 绑错的代码**照样跑起来**。

**在 JS 上会发生什么（本仿真实测）**：

| 本仿真学生犯的错 | 语法 | 编译/解析 | 运行 | 现有判据能否判 |
|---|---|---|---|---|
| `setInterval(function(){ this.seconds++ })` | ✅ 合法 | ✅ 通过 | ⚠️ 不报错，但打印 `NaN`、`timer.seconds` 永为 0 | **不能**：不在「必须扣分」清单，也不在「可豁免笔误」清单 |
| `forEach(function(n){ this.total += n })` | ✅ 合法 | ✅ 通过 | ⚠️ 不报错，返回 0 并偷偷污染 `window.total` | **不能**（同上） |
| `end` 打印在异步回调之前预测成 2 | ✅ 合法 | ✅ 通过 | ✅ 能跑，❌ 顺序错 | **不能** |

→ 结果是导师只能把 ③ 标 `✅`（"语法完全合法"）而把错误塞进 ②。**塞进去似乎说得通，但它造成了两个具体危害**：

1. **三维退化成二维。** JS 里绝大多数真正的错误都落在 ②，③ 变成恒真的空维度。而 `学科包/README.md` 第 5 节明令「不许因为学科不好量化就跳过维度③」——现状等于**跳过**。
2. **判定漂移 + 术语打架。** 同一个 `this` 绑定错误：判 ② = "逻辑不通"（走 Socratic，正确），判 ③ = "代码结构性正确、能跑起来"（✅，也正确）。导师在同一行里既说"能跑"又判"不通过"，学生（本仿真第 3 轮的质疑）会直接问「能跑凭什么算错」——**这不是学生钻牛角尖，是判据本身自相矛盾。**

**明确方案（建议照抄进 `编程.md`）**：

**A. 第 1 节拆成「语言族分支表」**（新增第二张表，现有 Java 表保留为静态编译型）：

| 语言族 | 代表 | 维度③ 名称 | 判什么 |
|---|---|---|---|
| 静态编译型 | Java / C / C++ / Go / Rust | **语法可编译** | 能否通过编译器：结构、签名、类型、保留字 |
| **动态解释型** | **JS / TS(擦除后运行) / Python / Ruby / PHP** | **运行时正确（Run-time Correctness）** | **在不改变学生意图的前提下，代码在其真实运行环境下的可观察行为**：值、类型、`this`、执行顺序、`null/undefined`、异常 |

**B. 维度③ 对动态语言的总口径（一句话，写给导师和学生）**：

> **「语法通过只说明能跑，不说明对。本学科包一律判：跑出来的结果对不对。」**

**C. 「能跑 ≠ 正确」用现有判据解释的三条（补进第 2 节，作为「动态语言的反判据」）**：

1. **不报错 ≠ 对**：`undefined++` → `NaN`、`window.x += 1`、`this` 静默变成 `window`，全是合法代码。**编译期挡不住的错，运行时也不会替你挡。**
2. **输出对了 ≠ 对**：碰巧（特定输入/特定顺序）对不算对。判据换成「**换个输入还对不对**」。
3. **跑一次对 ≠ 对**：顺序类/异步类/共享状态类 bug，一次运行不是证据。

**D. 动态语言的「可豁免笔误」必须单列，并明确反向清单**（否则导师会把致命语义错误当笔误放过）：

**先说一个现有条文直接放行语法错误的问题**：`编程.md` 第 2 节现有「全角符号 `（）` 一律豁免」。本仿真学生写的 `setInterval(function（） {…})` 里，`（）` **会让 JS 直接抛 `SyntaxError`（连解析都过不了）**。导师当时按"中文输入法笔误"给了豁免——这个豁免对学生友好，但**判据本身是漏的**：全角符号在 Java 里可能只是笔误，在 JS 里可能直接是语法错误。→ 建议：**全角符号的豁免要限定为「不改变 token 边界」的场合**（如注释、字符串、全角逗号/分号），出现在 `()` `{}` `[]` `<>` 位置时必须按结构性问题处理。

- ⚠️ **可豁免**（本仿真实测）：**漏分号（ASI 能救，且不改变语义）**、`consle`/`consoel` 拼写、引号风格混用、注释里的全角字符、字符串里的中文标点。
- ❌ **绝不可豁免**：① 全角括号/全角引号出现在**语法结构位置**（`function（）`、`“abc”` 当字符串）→ 真 `SyntaxError`；② 长得像笔误但**语义变了**的：`=` 写成 `==`、`==` 写成 `===`、`var` 写成 `let`、`-` 写成 `--`、`function` 漏 `()` 变成引用、普通函数写成箭头函数。→ 建议在 `编程.md` 第 2 节加一行：**「能跑但语义变了的，不是笔误，是错误；连解析都过不了的，也不是笔误。」**
- ⚠️ 附注：本仿真同题的 `consle.log` 被豁免，但它运行时是真 `ReferenceError`。**两处豁免都踩在边界上**，说明动态语言的笔误判据必须比静态语言更严，而不是更松。

**E. 还漏了什么（本仿真之外也要补的 JS 判据）**：
- `window` 全局污染（本仿真真实验到了：`window.total`、`window.seconds` 被写坏）——`编程.md` 完全没提「隐式全局」这一类错误。
- 数组/对象的**引用共享**（`const a = [1]; const b = a; b.push(2)`）。
- 浮点：`0.1 + 0.2 !== 0.3`。
- `NaN` 的特殊性：`NaN !== NaN`、`isNaN` vs `Number.isNaN`。
- 异步错误不进 `try/catch`（未 `await` 的 `Promise`）。
- 以上没一条在现有清单里。

### 4.3 对话节奏问题

> **本节 → 第 5 节建议编号**：1 → #12；2 → #13；3 → #14（后半）；4 → #14（前半）+ #15；5 → #19。

1. **抽象概念学生会连续追问 2 次以上，协议只说"换角度"没说换什么轴。**
   本仿真第 1 轮学生连问 2 次（「为什么啊我还是不懂」「能不能画个图」）。导师临时排出了有效顺序：**① 换符号表征（调用形状表）→ ② 换生活类比 → ③ 换图形（两列对照图）**。
   → 建议把"换角度"固化成这 3 种表征的**轮换清单**，导师一次只换一种，不要一次全上。

2. **学生跑题 2 次，每次都发生在"刚答完一题、还没被评估"的间隙。**
   - 第 2 轮：答完题 3/题 4 后插入轮播图 `bind` + `autoplay`（两个话题）。
   - 第 3 轮：答完题 5 后质问"凭什么算错"（这个跑题**是好跑题**，直接命中本领域核心冲突）。
   → 建议协议加「**停车位**」机制：一句话确认 + 明确归还时间（"记进 ⏳ 待办，本课收尾后第一件事讲"）+ 不展开。本仿真验证有效（学生被拉回后没有情绪反弹）。

3. **单轮评估消息约 900 字，接近上限。** 第 2 轮评估含题 3（笔误 3 处）+ 题 4（概念错）+ 箭头函数讲解 + 真机对账，实测需要分成 3 段才读完。
   → 建议：一轮 2 题时，每题的"三段式"限 3 行；长原理另起 `🔍 多说一句` 折叠块，学生可以后看。

4. **情绪低谷出现在"一轮 2 题 + 两题都错 + 新知识点首次实操"三件事叠加时。** 本仿真第 2 轮首评后学生说"我是不是学不会，this 好烦"。
   → 观察到的有效做法：**先明确列出答对的部分（本仿真列了 2 条）再讲错**，学生立刻回到状态。建议把这条写进协议（现在第 10 节只说"语气耐心鼓励"，没给操作顺序）。
   → 另一条可操作建议：**新知识点的首次实操轮降到 1 题**（协议允许 1–3 题，但没给"什么时候降到 1 题"的触发条件）。

5. **费曼题单独一轮是对的**，但学生第一反应是「不许写代码我讲不了啊」。→ 建议协议第 6.1 节加一句可复用的开场话术：「不许写代码不是为难你，是因为一写代码就测不出你懂没懂了。」

### 4.4 该学科特有的教学法发现（值得固化到 `编程.md`）

> **本节 → 第 5 节建议编号**：1 → #5；2、3、6 → #18；4 → #16；5 → #2；7 → #17。

1. **⭐ 先预测、再运行、后对账（Predict-Run-Compare）。这是本仿真最有效的单一手段。**
   摸底 M3、正课第 3 轮都靠它把"我以为我会"顶到墙上。学生从第 2 轮开始主动跑对账（"我跑了！控制台真的是 now 0 / now 0 / end 0，我盯着看了三十秒"）。
   → 建议进 `编程.md` 第 4 节（出题形态）与第 5 节（验证方式），并写成**硬要求**：**先写预测，再允许运行；不许先跑再补预测**（否则学生变成"从结果反推"，等于没有推理）。
   → 注意：这与 `编程.md` 第 5 节现有第 1 条「不用真跑，但要说得出」**冲突**——对动态语言，"不用真跑"是危险的（JS 的反直觉恰恰在"说出来"和"真跑"之间）。建议第 5 节第 1 条加动态语言例外。

2. **⭐ 调用表达式形状表（判断 this 的第一表征）。** 五行表格（`obj.m()` / `m()` / `new M()` / `m.call(x)` / `()=>`）比任何定义都有效，学生看完表当场就把第 1 轮两道题改对。
   → 建议直接进 `编程.md` 第 4 节作为 JS 的标准教具。

3. **图形表征：「点号左边是谁」两列对照图。** `this` 的锚定物是**调用点左边的形状**，不是函数定义处。画成"代码写法 → JS 找 this 的动作"两列，学生立刻理解。
   → 建议进 `编程.md` 第 5 节（怎么确认学生真会了）。

4. **费曼题的「禁用词表」应该按知识点预置。** `编程.md` 第 5 节已有"禁止写代码"，但只说了一个笼统模板。JS 的核心概念**无法绕开关键词**（`this`、闭包、异步本身就是术语）。本仿真导师临时禁了「作用域/绑定/上下文/调用栈/词法」——**正是因为禁掉了"绑定""上下文"，学生才被迫用"签名单"类比，才暴露了他把两条相反规则合成"就近原则"的洞**。
   → 建议 `编程.md` 第 5 节补一张「知识点 ↔ 预置禁用词表」：`this` → 作用域/绑定/上下文/词法；闭包 → 作用域/引用/垃圾回收；异步 → 任务队列/回调/非阻塞。

5. **「能跑 ≠ 正确」三连（不报错 / 输出对 / 跑一次对）是 JS 的固定话术，可逐次复用。** 本仿真第 3 轮用它直接化解了学生的质疑，而且学生当场接受了。→ 建议做成学科包里的固定模板。

6. **对账三列表（预测 | 实际 | 差异原因）正好用来治"不看堆栈直接改"的习惯。** 学生本项目里的原话是"报 undefined 我就改成 vm.xxx 就好了"。让他填满这张表三次以后，第 3 轮他开始自己揪矛盾（"我前面②答对了，①错了，对吧？"）。
   → 建议作为 JS 学科的标准练习模板。

### 4.5 学生画像补充（真实的错误类型与困惑模式 → 可补 `编程.md` 第 3 节）

> **本节 → 第 5 节建议编号**：A 的 8 条错误 → #4；B 的困惑模式 → #17（表述纪律 + 三个错误心智模型）；B-4「停车位」→ #13。

**A. 真实错误类型（本仿真实录，直接可追加进高频错误清单）**

| # | 错误 | 本仿真哪里发生 | 为什么高危 |
|---|---|---|---|
| JS-1 | `this` 在回调里丢失（`setInterval` / `forEach` / `addEventListener`） | 摸底 M3、正课 3、4 | 不报错，值静默变 `NaN`/`undefined` |
| JS-2 | 把"函数属于某个对象"当成 `this` 的依据（位置论，而非调用论） | 摸底 M1、正课 1 | 会持续污染后续所有 `this` 判断 |
| JS-3 | 把箭头函数的规则和普通函数的规则**合成"就近原则"** | 费曼题首评 | 两条规则相反，合一就等于没懂 |
| JS-4 | **用"能跑"当"对"的判据** | 正课 2 首评、正课 3 质疑 | 浏览器不报错 → 学生认为通过 |
| JS-5 | **不看堆栈/不看实际值，直接改到不报错** | 摸底学生自述 | 掩盖真实原因，制造"改对了"的错觉 |
| JS-6 | 异步顺序按**书写顺序**猜 | 正课 3（`end 2`） | 一次运行可能"看起来对" |
| JS-7 | 隐式全局污染（`window.total` / `window.seconds`） | 摸底 M3、正课 4 真机 | 学生完全不知道 `window` 被写坏了 |
| JS-8 | 只报结论不报原理（背得出 `3 3 3`，讲不出为什么） | 摸底 M5 | 项目已知高频问题，JS 里尤为普遍 |

**B. 困惑模式（比错误类型更值得记的操作信息）**

1. **一遇到抽象词就崩**：「作用域」「绑定」「上下文」「执行环境」这类词一出现，学生立刻进入"我是不是学不会"状态，答题质量断崖。本仿真实测的**解法是角色化表述**：一旦把 `this` 说成"谁点的单/谁签的名/谁在用这个函数"，他立刻能推对。
   → 建议写进 `编程.md` 第 3 节作为**表述纪律**：JS 的 `this`/闭包/异步三个知识点，一律**先用角色化语言讲，术语最后补**。
2. **拿"本地能跑"当证据**：他的默认判据是"浏览器没红字 = 对"。这是**前端自学 3 个月的典型水位**，不是个人缺陷。→ 建议学科包直接把它写进"必须优先拆掉的三个错误心智模型"。
3. **动机触发点在"面试"这个词上**：本仿真导师把 `this` 绑到"前端面试第一坑"时，学生注意度明显提高（后续追问变少）。→ 建议「为什么要学」话术里保留这个锚。
4. **需要给"停车位"**：他有真实的项目困惑（轮播图、移动端 `autoplay`），跑题不是捣乱，是**真实需求溢出**。三次跑题里有两次是真实的技术问题。→ 建议 ⏳ 待办表专门留一栏收这种"学生主动提出的话题"，并明确归还时间。
