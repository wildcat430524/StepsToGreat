## 1. 一张表看懂：8 个学科各自打分

| # | 学科 | 现有规则可用度 | 一句话理由 |
|---|---|---|---|
| 01 | 编程·后端 Java | **判据打架** | `编程.md` 第 2 节两清单自相矛盾（`printlin` 同时命中「豁免」与「必扣」）；「能编译但语义错」在三维里无归属 |
| 02 | 编程·前端 JS | **判据失效** | 维度③「语法可编译」对动态语言**恒真**，三维退化成二维；18 条判据里 8 条完全不适用 |
| 03 | 编程·算法 | **判据缺失** | 复杂度无归属；「多个正确解法」无口径；高频错误清单 10 条全是 Java 语言错，算法一条没有 |
| 04 | 编程·SQL | **判据错位** | 「语法对但结果错」的静默错误（`LEFT JOIN` 丢数据）无处安放；③叫「语法可编译」但 SQL 不编译 |
| 05 | 文科·历史 | **判据打架** | 「论据不足」被②③同时认领；「因果倒置」被列在③但它其实是②的问题 |
| 06 | 文科·法学哲学 | **判据打架** | 同上；且「概念混用」被列为③结构性错误，但它是维度①的理解问题 —— **分类错位** |
| 07 | 理科·数学 | **判据打架** | 「结论对但过程不完整」落两不管地带；「跳步」无阈值；「分类讨论遗漏」②③归属自相矛盾 |
| 08 | 理科·物理 | **判据打架** | 单位漏写/量纲错/换算错被压进同一行❌项；矢量方向无三档判据；没画受力图无规则 |

**整体判断**：**8 个学科全部需要修补**，其中 **6 个的核心症状是同一个 —— 「这个错该算②还是③」判不出来**。

> 注意：这不是「学科包写得差」。学科包已经是同类项目里少见的细致设计；
> 问题出在**三维评估的「归属判据」层**——协议定义了三个维度「是什么」，但没定义「某个具体错误该进哪个」。

## 2. 跨学科共性缺陷（★ 最重要，优先修）

> **判据**：被 **2 个及以上学科族**（编程 / 文科 / 理科）独立发现的才算共性 —
> 只在单一学科族内出现的放第 3 节。

### C1 维度归属不清：同一批错误被两个维度同时认领（**三个学科族全部命中**）

**现象**（三个学科族各自独立遇到）：

| 学科族 | 具体冲突 | 出处 |
|---|---|---|
| 编程 | 「能编译但语义错」（`volatile int i; i++`）能编译、能跑、还常跑对 → ③管不到，②没提并发 | 01#3、02 |
| 编程 | 复杂度分析该进②还是③？O(n²) 暴力解**能跑能 AC**，进③等于宣布「能跑 = 达标」 | 03 4.1① |
| 文科 | 「论证结构残缺 / 论据不足」被②（论证）与③（表述规范）同时认领 | 05 4.1①、06 5#4 |
| 文科 | 「概念混用」被列为③结构性错误，但它其实是**维度①**的理解问题 | 06 4.1① |
| 理科 | 「跳步严不严重」该判②（逻辑）还是③（规范）？`理科.md` 只说「跳步严重 → ③⚠️」，没给阈值 | 07 4.1①、08 4.1② |
| 理科 | 「分类讨论遗漏」在 `理科.md` 第 2 节被列为③，但它是**逻辑不完备**，该归② | 07 4.1③ |
| 理科 | 「条件缺失」（用了公式没写适用条件）是①概念问题还是③规范问题？ | 07 4.1④ |

**为什么是缺陷**：导师**当场判不出来**，只能自创口径。
后果不是「判错一个题」，而是**判定不可复现** —— 换一个导师评同一份卷子会得出不同结论，
而本项目的核心机制（全 ✅ 才推进）建立在判定的确定性上。

**涉及文件**：`协议/00_导师协议.md` §3、`学科包/编程.md` §1–2、`学科包/文科.md` §1–2、`学科包/理科.md` §1–2

**建议改法**（三选一，见 §5 的取舍）：
1. 给每个学科包加一张「**具体错误 → 维度归属**」对照表（最直接，但会让学科包膨胀）
2. 给三维加一条**通用裁决原则**（如「错在『说的东西不对』→ ①；『推理链断了』→ ②；『写法不合规范』→ ③」）
3. 两者结合：原则写进协议，各学科的边界案例写进学科包

**优先级**：**P0**

### C2 一轮 1–3 题对高成本题型不适配（**三个学科族全部命中**）

**现象**：

| 学科族 | 实测数据 | 出处 |
|---|---|---|
| 编程·算法 | 一道算法题含「思路 / 代码 / 复杂度 / 边界」四个子问题，**R1 两题吃掉 8 个往返**，正课共 13 个往返 | 03 4.3 |
| 文科 | 论述题 200–400 字，一题批改量等于 5 道选择题；案例题同理 | 05 4.3、06 4.3 |
| 理科 | 推导题一题就要写多行公式 + 分类讨论，一轮两题导致**导师回复失控** | 07 4.3、08 4.3 |

**为什么是缺陷**：协议的「1–3 题」是按**编程轻题型**定的量。
对重题型（算法 / 论述 / 推导），一轮 3 题会让单次评估消息过长、学生消化不完。

**涉及文件**：`协议/00_导师协议.md` §2「出题节奏」表

**建议改法**：把「一轮 1–3 题」改成「**一轮 1–3 题，且按题型成本折算**」：
- 轻题型（概念问答 / 选择题 / 短代码）：可到 3 题
- 重题型（算法完整题 / 论述题 / 复杂推导）：**1–2 题**，且允许「一轮 = 1 个问题（含多个子问）」
- 由学科包声明自己的题型属于哪档

**优先级**：**P0**

### C3 学生反复追问时「换角度」没有升级路径（**三个学科族命中**）

**现象**：协议 §4 只说「学生仍不理解时，再给原理说明或局部示例」，
但**没说换几次、换到什么时候该直接给答案**。

| 出处 | 实际情况 |
|---|---|
| 01、02 编程 | 学生连续追问 3 次，导师只能一直换角度 |
| 07 理科 | 「理科追问特别贵」，没有停止条件 |
| 弱模型测试 | FLASH 与 GLM 都在自述里点名这条（见弱模型报告 §3.4） |

**已修**（本轮）：`协议/00_导师协议.md` §4 新增「学生反复追问时的升级路径」三档表：
第 1 次换角度 → 第 2 次换教法类别 → **第 3 次直接给答案 + 要求复述**。

**剩余待办**：`03_落档事件表.md` 也补了对应事件行（已修）。但**「换角度」的工具箱**（换例子 / 换类比 / 画图 / 换数值）还没写进协议 —— 各学科仿真都提到导师需要一份可选的「换角度手段清单」。

**优先级**：**P0**（主体已修，工具箱待补）

### C4 导师单次回复过长，无长度纪律（**三个学科族命中**）

**现象**：文科论述题 + 理科推导题导致导师评估消息极长。
`05` 与 `07` 都实测到「回复比题目还长」，`01` 与 `04` 提到评估 N 题时的消息爆炸。

**为什么是缺陷**：长回复直接违背项目的核心主张 ——
学生消息通常 3–5 字、**在意往返成本**；导师却可能一次输出几千字。

**涉及文件**：`协议/00_导师协议.md` §3（评估）、§10（沟通风格）

**建议改法**：加一条**长度纪律**（如「单次评估消息 ≤ 若干字，超出则分『本轮结论』与『详细解析（可折叠到回答文档）』两部分」），
并要求：**评估结论进对话，详细讲解进回答文档**，对话里只给摘要 + 指向。

**优先级**：**P0**

### C5 可豁免笔误清单与结构性错误清单互相打脸（编程 + 理科）

**现象**：

- **编程**（01#1）：`编程.md` 第 2 节「可豁免笔误」列了 `printlin`，
  同一节「结构性错误」又列了「调用不存在的成员」→ **`System.out.printlin()` 同时命中两条**。
- **编程**（02）：现有「全角符号一律豁免」会**放行真 SyntaxError**（`function（）`）。
- **理科**（07、08）：`理科.md` 的可豁免清单说「单位写全称/简写不一致可豁免」，
  但必扣清单说「量纲不匹配必须扣分」 → **边界在哪没说**。
  「单位漏写 / 写错 / 换算错」三种情形被压进同一行 ❌ 项。

**建议改法**：给每条判据**加边界限定词**，并把「同一处代码/步骤同时命中两清单」列为
**必须显式裁决**的情形（缺省按「结构性错误」处理，因为保守方向是「不让它过关」）。

**优先级**：**P0**

### C6 学生找借口 / 归因于题面时，无处理动作（编程 + 理科）

**现象**：
- 算法仿真中阿豪**两次**说「题目没说清楚」，而题面**确实可挑剔**（缺数据规模上界）。
- 物理仿真中学生的「会算不就行了」被协议仅以「耐心鼓励，标准不降低」一句带过。

**已修**（部分）：弱模型测试未覆盖；
`_抽取-编程.md` A6 与 `_抽取-理科.md` B14 都给了具体三步建议。

**建议改法**：新增三步 ——
① 核实题面是否真有歧义（**有则认账并当场补题面，同时说明判定不变**）
② 无歧义则明确指正「先怀疑自己的解法，再怀疑题面」
③ 把「审题习惯」记进 ⏳ 待办（并允许 ⏳ 记录非知识类条目）。

**优先级**：**P1**

### C7 摸底测试的评法与落档缺口（编程 + 理科）

**现象**：两个学科族都提到 —— `01_摸底剧本.md` 说「摸底不是考试，不用打分」，
但没说**摸底结果要不要落档、怎么落、按什么维度归类**。

**已修**（部分）：本轮修了「5–8 题」的措辞误导（见弱模型报告 §3.2）。

**剩余**：摸底结果的**落档粒度**仍未定义（`_抽取-理科.md` A7）。

**优先级**：**P1**

## 5. 我的判断：哪些建议应当被采纳，哪些应拒绝

> ⚠️ **这一节是最重要的。** 133 条建议若全采纳，规则文档会膨胀一倍以上，
> 而项目已明确的设计主张是「**加规则 ≠ 提价值**」。

### 5.1 立即采纳（P0：不修则判定不可复现）

| # | 改动 | 为什么必须做 | 落到哪 |
|---|---|---|---|
| **1** | **新增「具体错误 → 维度归属」裁决原则 + 各学科边界案例** | 6 个学科的核心症状；不修则「全 ✅ 才推进」失去确定性基础 | `协议/00_导师协议.md` §3 加**裁决原则**；三个学科包各加**边界案例表**（只列有争议的，不重抄全部判据） |

### 5.3 建议拒绝（做了反而变差）

| 建议 | 拒绝理由 |
|---|---|
| **给「动态语言」新增一整套独立判据体系**（JS/Python 单独一套③） | 会让 `编程.md` 变成两套并行规则。**改为**：③保留主名「语法可编译」，但加一句「**动态语言按『运行时正确』判**」+ 3 条「不报错≠对 / 输出对≠对 / 跑一次对≠对」反判据 —— 用**一行**解决，不加结构 |
| **「②扩为正确性+复杂度+边界三子项」并给三张判据表** | 方向对，但「给三张表」是过度设计。**改为**：在②的说明里加一句「含复杂度与边界」 |
| **新增「考试包叠加」到全部学科** | 应试场景已由 `学科包/考试.md` 覆盖；把它的答题格式判据渗进理科包（08 B12 的冲突）**是修冲突，不是加体系** |
| **为「多个正确解法」新建「②-1 多解判定」小节** | 一个真实场景撑不起一个新小节。**并入**②的一句说明即可 |
| **给每个学科包写「评分点模板」**（论述题结构点表 / 数学三问法 / 材料题引用规范） | 单个学科特有且描述性内容多，放进各自学科包可以，但**不要再增一个通用层** |
| **「导师单次回复 ≤ 600 字」这类硬性字数** | 违反「标准不降低」并且会误伤必要的详细讲解。**改为**方向性纪律（结论进对话、详解进文档），**不设硬字数** |
| **把 8 份仿真报告的经验全部固化成规则** | 这正是项目反对的「加规则 ≠ 提价值」。仿真报告的价值是**证据**，规则只取其中会**判据打架**的部分 |

### 5.4 待议（需要更多证据）

| 建议 | 为什么先不动 |
|---|---|
| 「立场自由 ≠ 事实自由」是否需要一条独立铁律 | 方向正确（学生可能编造史实支撑立场），但**当前 8 份仿真里没有真实犯例** —— 等真出现再加 |
| SQL 是否要有「数据集 + 期望结果」的独立出题格式 | 涉及模板改动，影响面大；先用现有题型跑几次真实教学再定 |

| 「跨包容冲突」（理科 vs 考试）是否需要统一仲裁规则 | 目前只发现 1 处，加规则的成本高于收益 |

## 6. 结论

### 6.1 现有协议 + 学科包对 8 个学科的整体可用度

> **流程层可用，判据层不够用。**

- **流程层（接手顺序 / 轮次机制 / 落档三处 / 代改三段式 / 掌握闭环）**：8 个学科**全部跑通**，
  弱模型测试也拿到 11–12/12 —— 这套骨架是**扎实的**。
- **判据层（某个具体错误该算哪一维）**：**8 个学科全部需要修补**，
  且 6 个学科的核心症状是**同一个问题**（②③归属不可判）。

一句话：**协议知道「什么时候该做什么」，但不知道「这个错误算不算错」。**

### 6.2 最该先修的 3 件

| 顺序 | 改动 | 理由 |
|---|---|---|
| **1** | **维度归属裁决原则 + 三学科包边界案例表** | 唯一的**系统性**缺陷，一修覆盖 6 个学科 |
| **2** | **一轮题量按题型成本折算** | 三个学科族实测超载；修法极简（一张表加一列） |
| **3** | **`validate-state.mjs` 增加「重复小节」不变式** | 弱模型**真实犯过**且现有校验器**抓不到** —— 这是唯一「已发生但无防护」的失误 |

### 6.3 一条元结论

> 这 8 份仿真的最大价值**不是那 133 条建议**，而是它暴露了一个结构性事实：
>
> **三维评估的「机制」是完整的，但「判据」是按维度描述的，不是按错误描述的。**
> 导师真正需要的是反过来的：**拿到一个错，能查到它属于哪一维。**
>
> 修这一处，比修 133 条都值。
