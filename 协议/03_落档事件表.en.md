# 03_Filing Event Table

> Purpose: **when to write which file**. Beyond the writes listed in this table, don't casually add status to the profile.
> Core discipline: **state lives in exactly three places** — 🚦 Handoff Status / 📊 Mastery table / ⏳ To-do table. Everything else references them, never restates them.
> Whether those three are **self-consistent, evidenced, and un-advanced**, is checked by [`../_tools/validate-state.mjs`](../_tools/validate-state.mjs)
> against the 10 invariants in [`04_状态机.en.md`](./04_状态机.en.md).
> Chinese version: [`03_落档事件表.md`](./03_落档事件表.md)

---

## 1. Event → where to write

| Event | Where to write |
|---|---|
| **First session / requirements gathering** | `我的学习/00-学习档案.md` → 📋 Student info |
| **Placement test done** | Create `学科/<学科>/00-摸底测试.md`; `00-学习档案.md` → 📋 + 🚦 |
| **Course route settled** | Create `学科/<学科>/00-课程路线.md`; `00-学习档案.md` → 🚦 |
| **Publish a new lesson** | Create `NN-<课名>/01_教学引导.md` + `01_学生回答.md`; `00-学习档案.md` → 🚦 + 📚 Lesson index |
| **Student submits / assessment fails** | `01_学生回答.md` assessment area; `00-学习档案.md` → ⏳ To-do if needed |
| **Re-assessment passes** | `01_学生回答.md` → "Final Re-assessment" (date + per-question 3-dimension table + verdict) + "Correct Answers & Analysis" (three-part); `00-学习档案.md` → 📊 Mastery table + 🚦 Handoff Status + ⏳ To-do |
| **Course order changes** | Only `学科/<学科>/00-课程路线.md`; everywhere else references it |
| **Spaced review / Feynman done** | `00-学习档案.md` → ⏳ To-do (status) + 🕰 changelog |
| **Student switches subject** | Create the whole `学科/<new subject>/` set; `00-学习档案.md` → 📋 + 🚦 |
| **Student asks for a re-test / skip** | Update `00-摸底测试.md` (append-only, add the new verdict); `00-学习档案.md` → 🚦 |

## 2. Division of labour between the three state places (must not overlap)

| Place | Answers only | Does not write |
|---|---|---|
| **🚦 Current Handoff Status** | What **this lesson** is, how far along, the first step after taking over | No long-term state, no history |
| **📊 Mastery table** | Whether each topic **counts as truly mastered** (with assessment date and evidence entry point) | No "currently learning" narration |
| **⏳ To-do table** | **Pending** re-assessments / reviews / Feynman | Does not restate "the lesson currently running" |

> Anti-pattern (a mistake that actually happened): writing the same progress into 5 sections → whoever takes over can't tell which one is authoritative.

---

## 3. Editing discipline

1. **Read any file before editing it** (most tools error out otherwise).
2. Re-read the key section after editing.
3. Use a local date command for dates (Windows: `Get-Date -Format 'yyyy-MM-dd'`).
4. **Student history is append-only**: add a new assessment section; never overwrite the student's original answers or past assessments.
5. **The answer document's final re-assessment outranks historical checkmarks in the teaching guide.** On conflict, the answer document wins.
6. Use relative links for paths so they open in Obsidian / VS Code / Trae.

---

## 4. Document status priority (use this to settle conflicts)

```
1. The student answer document's "Final Re-assessment"   ← highest
2. The profile's 📊 Mastery table
3. Historical checkmarks in the teaching guide
4. Verbal conclusions in chat history             ← lowest, never used as evidence
```

## 6. Standard wording for the profile

**🚦 Handoff Status** (only the current lesson):

```markdown
| Item | Current state |
|------|----------|
| **Current subject** | <subject name> |
| **Current lesson** | #NN <lesson> |
| **Last completed** | #NN-1 <previous lesson> |
| **Teaching guide** | `<path>` |
| **Answer document** | `<path>` |
| **Current progress** | <guide published, answer document empty, waiting for the student> |
| **First step after taking over** | <concrete action> |
| **Advance condition** | <move to the next lesson only after all three dimensions pass> |
```

**⚠️ The two "between lessons" states (the protocol was silent on this; found by the end-to-end run)**

Because filing happens only after a whole lesson passes, a **legitimate intermediate state** exists:
the previous lesson has passed and is written into 📊, but the next lesson has not been published yet.
Here 🚦 must not keep the old lesson's paths (stale) and must not invent a path that doesn't exist.
The correct wording is to **name the next lesson in "Current lesson" and leave the paths as a placeholder**:

| Case | Current lesson | Teaching guide / Answer document | Note |
|---|---|---|---|
| **A. Previous lesson passed, next not published** | `#NN+1 <next lesson>` | `—（#NN+1 尚未发布）` | Take the lesson name from `00-课程路线.md`; never invent one |
| **B. New lesson just published, awaiting the student** | `#NN+1 <next lesson>` | `<real path>` | The 📚 index should have been appended by now |

> In case A the 📚 lesson index does **not** yet have the `#NN+1` row — that is normal, not an error.
> The validator only emits **notes** for A (`[I3] still a placeholder` / `[I9] not in the 📚 index`), never a failure.
> **Forbidden**: in case A, leaving the paths empty or writing a bare `—` (with no explanation) —
> that makes it impossible for whoever takes over to tell "not published yet" from "someone forgot the path".

**📊 Mastery table**:

```markdown
| Topic | Status | Assessed | Notes |
|--------|------|----------|------|
| <topic> | ✅ Mastered | YYYY-MM-DD | <one-line evidence> |
| <topic> | ⚠️ Partially mastered | YYYY-MM-DD | <what's missing> |
| <topic> | ⏳ Awaiting answer | YYYY-MM-DD | <document created, answers empty> |
```

**⏳ To-do table**:

```markdown
| Item | Trigger | Scheduled | Evidence entry | Status |
|------|----------|------|----------|------|
| <item> | <why it's pending> | <when to do it> | `<path>` | ⚠️ Pending (non-blocking) |
```
