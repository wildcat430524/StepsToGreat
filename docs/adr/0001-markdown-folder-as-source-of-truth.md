# 0001 · Markdown 文件夹为唯一真相，不做应用

- **状态**：已接受
- **日期**：2026-09-21
- **决策者**：项目发起人

---

## 背景

要让 AI 当一对一导师，有三条路：

1. 做一个 Web / 桌面应用（服务端 + 数据库 + 前端）
2. 做一套 Prompt 模板，用户每次手动粘贴
3. 做一堆 Markdown 文件，用户用 AI 工具打开这个文件夹

约束：
- 用户是**非技术人**（考研考公学生、学英语的人），不能要求他们部署服务
- 项目要**开源**，让别人拿去用
- 学习记录必须**归用户所有**，不能锁在别人的服务器里
- 不能有运维成本（个人项目，没有服务器预算）

---

## 决策

**采用方案 3：一个 Markdown 文件夹。**

- 规则：`AGENTS.md` + `协议/`
- 状态：`我的学习/00-学习档案.md` 的 🚦/📊/⏳ 三处
- 证据：每课的 `01_学生回答.md`
- 判题：由 AI 承担，不写后端

---

## 理由

| 理由 | 说明 |
|---|---|
| **零运维** | 没有服务器就没有运维、没有账单、没有宕机 |
| **数据主权** | 用户的记录是普通 Markdown，能用记事本打开，十年后还在 |
| **工具无关** | 任何能读文件的 AI 都能当导师；换工具不丢记录 |
| **可审计** | 协议是纯文本，用户可以自己读、自己改、自己 fork |
| **分发成本为零** | `git clone` 或下载 zip 即可 |

---

## 代价（明确接受）

| 代价 | 缓解 |
|---|---|
| 没有炫酷交互 | 用 Markdown 表格 + mermaid 图；需要交互练习时按需生成 HTML（不落盘） |
| 依赖 AI 的工具调用能力 | 纯聊天网页版只能手动粘贴（已在教程中说明） |
| 无法自动判题 | 判题交给 AI；弱模型可能误判（已在已知限制中列出） |
| 用户可能误删文件 | 已建议纳入 git；`我的学习/` 默认 gitignore 但用户可自行纳入 |

---

## 备选方案与为何否决

| 方案 | 否决理由 |
|---|---|
| Web 应用 | 需要服务器、账号、数据库；与「数据主权」冲突；个人项目无力长期运维 |
| 纯 Prompt 集合 | 状态不落盘 → 每次新会话都从零开始，学不了长期课程 |
| 桌面 App | 要打包、要签名、要处理三平台；开发成本远超收益 |
| 用现成 LMS（Moodle 等） | 重、要部署、与「AI 当导师」不匹配 |

---

## 影响

- 全部内容必须是**纯文本**（Markdown）
- 需要一套「多 AI 工具适配层」（见 ADR-0002）
- 需要 `.gitignore` 严格区分框架与数据（见 ADR-0004）
- 质检只能做**格式级**检查（`_tools/check.mjs`），无法验证教学质量
